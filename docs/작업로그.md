### 3. 주요 구현 판단

**바이브데이즈 — 상태값 하나로 전환되는 구조**
모집은 기수제라 마감·연기·기수 교체가 잦다. 문구를 하드코딩하지 않고
`CohortStatus`(`upcoming`/`open`/`closed`/`ended`) + 요소별 노출 토글
(`show.price/capacity/schedule/cta`)로 만들었다.
**날짜 자동 계산에 의존하지 않는다** — 조기 마감이나 연장 같은 운영 판단이 달력보다
우선하기 때문이다. `closed`일 때 신청 버튼은 없애지 않고 비활성 + 사유를 남긴다.
버튼이 사라지면 "마감됐다"는 사실 자체가 전달되지 않는다.

**포트폴리오 카드 구조 변경 — 도트 페이지네이션 때문**
카드 전체가 클릭 타깃(Sheet trigger)인데 그 안에 도트 버튼을 넣으면 버튼 안의 버튼이 되어
HTML상 무효이고 도트를 눌러도 상세창이 열린다. 그래서 **투명 오버레이를 카드 바닥에 깔고**
시각 요소는 `pointer-events-none`으로 얹었다. 클릭이 오버레이로 통과하고 도트만
`pointer-events-auto`로 직접 받는다.

**포트폴리오 3분류는 파생값**
`work_items`에 분류 컬럼이 없어 `category` 문자열에서 키워드로 파생한다
(`src/lib/work-category.ts`). Admin에서 분류를 직접 고르게 되면 이 파일은 그 필드를
읽는 것으로 바뀐다 — 그때까지의 임시 다리다.

**사례 상세 CTA → 문의 폼 사전 선택**
라벨을 코드에 박지 않고 **실제 문의 옵션 목록에서 키워드로 찾아 맞춘다.** 유형/세부 유형은
DB에서 오고 Admin에서 바뀔 수 있어, 하드코딩하면 라벨이 바뀌는 순간 조용히 어긋난다.
덕분에 옛 라벨(`프로젝트 문의`)에서도 그대로 동작한다.
교육 사례만 예외로 `/education` 문의 폼으로 보낸다.

**필터는 사례 6개 이상일 때만 노출** (`FILTER_MIN_ITEMS`)
사례가 서너 개면 한 화면에 다 보여 필터가 걸러줄 게 없고, 오히려 사례가 적다는 인상만 준다.

### 4. ⚠️ 운영 사고 — 배포 사이트 이미지 전부 깨짐

**가장 중요한 기록.**

포트폴리오 콘텐츠를 고치면서 Supabase `work_items`를 직접 수정했는데,
그게 그대로 **라이브 사이트(www.kpopsoft.com)에 즉시 반영**됐다.

```text
Supabase 프로젝트 하나 ──┬── 로컬 (redesign/ver2)
                        └── 배포 (main)
```

콘텐츠는 DB에 있어 즉시 반영되지만 **이미지 파일은 코드(`public/work/`)에 있어
배포되어야만 서버에 올라간다.** `main`에는 그 이미지가 한 장도 없었고, DB만 새 경로를
가리키면서 포트폴리오 카드 이미지가 전부 404가 됐다.

**대응**
1. 이미지 파일만 담은 커밋을 `main`에 푸시 → 404 해소 (`8649935`)
   - 코드·레이아웃은 건드리지 않고 정적 자산만 추가. 별도 워크트리에서 작업해
     브랜치 작업이 섞이지 않게 했다.
2. 이후 사용자 요청으로 DB를 원래 더미 4건으로 복구 → 다시 실제 사례로 재적용

**재발 방지** — `scripts/apply-work-content.cjs`
```bash
node scripts/apply-work-content.cjs            # 계획만 출력 (기본, 안전)
node scripts/apply-work-content.cjs --check    # 배포 서버에 이미지 존재 확인
node scripts/apply-work-content.cjs --apply    # 반영 (이미지 없으면 자동 중단)
node scripts/apply-work-content.cjs --rollback # 직전 백업으로 복구
```
`--apply`는 실행 전 배포 서버의 이미지를 확인하고, 하나라도 없으면 중단한다.
이번 사고의 원인(순서 뒤바뀜)을 스크립트가 강제한다.

**앞으로의 원칙**
- **DB 수정 = 배포.** 콘텐츠성 DB 변경 전에는 라이브에 바로 나간다는 점을 먼저 확인한다.
- 배포 순서: `브랜치 배포 → 이미지 확인 → DB 반영`

### 5. DB 변경

| 대상 | 내용 |
|---|---|
| `work_items.image_urls` | `text[]` 컬럼 추가 (갤러리). 마이그레이션: `supabase/migrations/20260731000000_work_items_image_urls.sql` |

기존 `image_url`(단일)은 대표 이미지 겸 폴백으로 유지한다.

### 6. 콘텐츠 원칙 — 지어내지 않은 것

- **성과 수치**: 실제 사례로 바꾸면서 더미 수치(`1차 문의 자동 해결 65%` 등)를 전부 비웠다.
  확인되지 않은 성과를 회사 홈페이지에 띄우지 않는다.
- **후기**: "진도를 잘 못 따라갑니다" 후기를 뺀 자리를 비워 뒀다. 나머지 5건이 실제
  수강생이 쓴 글이라, 지어낸 후기를 사이에 끼우면 구분이 불가능해진다.
  → **실제 후기 1건 필요.** 현재 평균이 5.0(전부 5점)이라 4점대 후기가 섞이는 편이
  신뢰도에 낫다.

## 2026-08-02 — 교육 페이지 수정 요청서 반영

기준: `KPOPSOFT_education_page_revision_request.md`. 브랜치 `redesign/ver2`.

### 착수 전 확정한 것 (사용자 결정)

| 쟁점 | 결정 |
|---|---|
| 목적 3축 vs 프로그램 3분류 | **명칭 통일하지 않는다.** 목적은 탐색 장치, 3분류는 상품 체계 |
| 헤더 | 전역 4메뉴 유지 + 교육 전용 서브바 신설 (역할 분리) |
| 상세 페이지 2개 | 이번 범위 제외 |

### 목적 선택 ↔ 프로그램을 어떻게 이었나

요청서는 "앵커 이동만 하지 말고 연결된 항목이 활성화되도록" 요구한다. 두 섹션이
형제라 props로는 안 이어지고, URL 쿼리로 두면 목적을 고를 때마다 뒤로가기 기록이
쌓여 브라우저 뒤로가기가 "이전 화면"이 아니라 "이전 필터"가 된다. 그래서 페이지
안에서만 사는 컨텍스트(`explore-context.tsx`)로 뒀다.

`AI 입문`과 `실무 활용`이 같은 정규 클래스로 가는 문제는 **정렬**로 풀었다.
`RegularClass.tracks`를 새로 두고 선택한 트랙의 과정을 앞으로 보낸다 —
거르지는 않는다. 4과정뿐이라 한 화면에 다 들어오고, 감추면 "고른 것 말고는
없다"는 인상만 남는다. `level`(자유 문자열)과 별개 필드인 이유는 level에
"비개발자 환영" 같은 난이도가 아닌 값이 들어오기 때문이다 — 코드가 분기에
쓸 축을 표기와 섞으면 문구를 다듬을 때 동작이 따라 깨진다.

### 프로그램 Sticky Scroll — 활성 판정을 observer로 하지 않은 이유

IntersectionObserver의 임계값 방식은 블록 높이가 서로 다를 때 무너진다. 정규
클래스 블록은 4과정이 들어가 다른 블록의 몇 배라, 짧은 블록이 임계값을 넘기지
못한 채 지나간다. 그래서 **뷰포트 중앙에서 가장 가까운 블록**을 활성으로 본다.

### 지어내지 않은 것

- **별점 제거.** 후기 본문은 수강생이 커뮤니티에 남긴 실제 글이지만, 다섯 건에
  붙어 있던 5점은 작성자가 매긴 값이 아니라 우리가 채운 값이었다. 근거 없는
  만점 평균은 신뢰를 주기는커녕 후기 전체를 의심하게 만든다(요청서 §11).
  `rating` 필드는 남겼다 — 실제 평점을 수집하면 다시 읽으면 된다.
- **강사 담당 프로그램.** 요청서 §10 카드 정보지만 누가 어느 과정을 맡는지
  확인된 자료가 없다. `instructorPrograms`를 빈 맵으로 두고, 비면 그 줄을
  그리지 않게 했다.
- **교육 사례 6개 카테고리.** 실제 자료는 지난 프로그램 3건뿐이다. 두 줄 마키는
  카드가 쌓였을 때 의미가 있고, 3건으로 돌리면 같은 카드가 반복해 지나가며
  사례가 적다는 사실만 강조된다. 섹션 자리와 카테고리 축만 잡아 뒀다.
- **CTA 라벨.** 요청서의 `기업교육 자세히 보기` / `정규 과정 보기`는 상세
  페이지를 전제한 문구다. 페이지가 없는 상태에서 그대로 쓰면 클릭하기 전까지
  알 수 없는 거짓말이 되므로, 지금 실제로 할 수 있는 행동(문의)으로 보냈다.
