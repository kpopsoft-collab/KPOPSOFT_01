# 구현 계획

## 표준 형태 — 이 모양으로 통일한다

`work`를 예로 든 병합 후 `[id]/page.tsx` 전문. 나머지 8쌍은 이름만 바뀐다.

```tsx
import { notFound } from "next/navigation";

import { getContentData } from "@/lib/admin/content-data";
import { ContentFormShell } from "@/components/admin/content/content-form-shell";
import { WorkForm } from "@/components/admin/content/work/work-form";
import { createWork, updateWork } from "../actions";

/** 추가·수정 겸용 라우트 (`id === "new"`가 추가). 제약은 docs/06-admin/06 §3. */
export default async function WorkFormPage({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  const isNew = id === "new";

  // isNew면 조회를 아예 하지 않는다 — 없는 행을 매번 찾지 않으려고.
  // `?? undefined`는 리포지터리의 null을 폼의 `initial?: T`에 맞추는 것이다.
  const item = (isNew ? undefined : await getContentData().work.get(id)) ?? undefined;
  if (!isNew && !item) notFound();

  return (
    <ContentFormShell
      backHref="/admin/content/work"
      backLabel="Work"
      title={isNew ? "프로젝트 추가" : "프로젝트 수정"}
    >
      <WorkForm initial={item} onSave={isNew ? createWork : updateWork.bind(null, id)} />
    </ContentFormShell>
  );
}
```

**주의할 지점 셋**

1. `?? undefined` — 리포지터리는 미스를 `null`로 주는데 폼 `initial`은 `T | undefined`다.
   `!item` 검사가 `isNew`와 묶여 있어 타입이 안 좁혀지므로 여기서 맞춘다.
2. `import`에 `create…`를 **추가**한다. 지우는 `new/page.tsx`가 쓰던 액션이다.
3. 함수 이름을 `Edit…Page` → `…FormPage`로 바꾼다. 하는 일이 달라졌다.

## 1단계 — 비교육 4쌍

`work` `experts` `stats` `pillar-examples`

각 쌍마다: `[id]/page.tsx`를 위 형태로 고치고 → `new/` 디렉터리를 **삭제**하고 →
`npx tsc --noEmit`.

**왜 여기부터** — 4쌍 모두 22줄짜리 같은 모양이라 판단이 안 든다. 여기서 형태가
굳으면 2단계는 복사다. `pillar-examples`만 폼이 `content/pillars/` 아래에 있으니
import 경로를 확인한다.

> `stats`가 둘이다 — `content/stats`(홈 수치)와 `content/education/stats`(교육 성과).
> 1단계는 앞의 것, 2단계가 뒤의 것. 파일 경로로 구분한다.

## 3단계 — `past-programs` + 문서

### 3-1. `past-programs` 병합

갤러리 블록과 **그 조회까지** `!isNew`로 감싼다. 조회를 밖에 두면 추가 화면에서
`listByProgram("new")`가 나간다(R3 위반).

```tsx
const data = getContentData();
const item = (isNew ? undefined : await data.education.pastPrograms.get(id)) ?? undefined;
if (!isNew && !item) notFound();

// 갤러리는 부모 행이 있어야 붙일 수 있어 추가 화면에는 없다.
const images = isNew ? [] : await data.education.pastProgramImages.listByProgram(id);
…
{!isNew && (
  <GalleryManager
    programId={id}
    images={images}
    onAdd={addPastProgramImage}
    onRemove={async (imageId: string) => {
      "use server";
      await removePastProgramImage(imageId, id);
    }}
  />
)}
```

`onRemove`의 인라인 서버 액션은 `id`를 클로저로 잡는다. `!isNew` 안에 있으므로
`id`는 항상 실제 행 id다.

### 3-2. 정규 클래스 주석 정리

`education/regular-classes/[id]/page.tsx`의 20줄 주석을 **포인터 1~2줄로 줄인다**
(D4). "합치기 전에는 정적이었다"는 문장은 지운다 — 02 §4에서 무효가 됐고, 이제
예외도 아니다. `getForEdit()`을 쓰는 이유(업로드 원본을 함께 읽는다)는 **남긴다.**
그건 이 컬렉션만의 사정이다.
