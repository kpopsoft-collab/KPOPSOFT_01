# 검증 체크리스트

> **상태 — 전부 닫혔다.** §1·§2·§6·§7은 2026-08-06에, **§3의 저장 항목과 §4의
> 갤러리 항목은 2026-08-09에** 목 모드로 닫았다. §5의 *"이름만 고쳐 저장해도 자료가
> 남는다"*만 목 모드로 성립하지 않아 실제 DB 쪽에서 따로 닫혀 있다.
> 무엇을 어떻게 확인했는지는 [06-구현결과.md](06-구현결과.md) §3-3.
>
> 아래 상자는 **착수 전에 쓴 계획 그대로** 둔다 — 무엇을 보기로 했었는지가 기록이다.

## 1. 구조 — 먼저 본다

- [ ] `find "src/app/admin/(shell)/content" -type d -name new` → **`inquiry-options/new` 하나만** 남는다
- [ ] `[id]/page.tsx`가 12개 (10개 병합 + `pillars` + `inquiry-options`), `regular-classes` 포함 13개
- [ ] `git status`에 목록 페이지(`*/page.tsx` 13개) **변경 없음** — URL을 안 바꿨다(D2)
- [ ] `actions.ts` 13개 **변경 없음**
- [ ] 폼 컴포넌트·`content-form-shell.tsx`의 **props와 마크업** 변경 없음 (주석만 바뀐다, R5)

## 2. 빌드 — `new/` 삭제 누락은 여기서만 잡힌다

- [ ] `npx tsc --noEmit` 통과
- [ ] `npm run lint` 통과
- [ ] `npm run build` 성공
- [ ] 빌드 로그의 라우트 목록에 `…/[id]`만 있고 `…/new`가 **없다**
      (`new/`가 남아 있으면 여기 나오고, 그 라우트가 `[id]`를 가린다)

## 3. 화면 — 10쌍 전부가 아니라 **최소 4개를 열어 본다**

`work`(1단계 대표) · `education/faqs`(2단계 대표) · `education/past-programs`(3단계) ·
`education/regular-classes`(기존 병합분 회귀).

각각에 대해:

- [ ] `/admin/content/<컬렉션>/new` → 200, 제목이 **"… 추가"**, 폼이 **빈 값**
- [ ] 추가 화면에서 저장 → 목록에 새 행이 보인다
- [ ] 목록의 연필 버튼 → `/admin/content/<컬렉션>/<id>` 200, 제목이 **"… 수정"**, 폼에 **기존 값**
- [ ] 수정 저장 → 값이 실제로 바뀐다
- [ ] `/admin/content/<컬렉션>/존재하지-않는-id` → **404** (`notFound()`가 산다)
- [ ] 추가 화면에 **삭제 버튼이 없다** (R4)

> "폼이 열린다"를 "저장된다"의 증거로 쓰지 않는다.
> `docs/08-decisions/00-START-HERE.md`의 교훈 — 링크를 만들었으면 그 링크를 연다.

## 4. `past-programs` — 갤러리 분기

- [ ] `/…/past-programs/new`에 **갤러리 블록이 없다**
- [ ] 추가 저장 후 그 행을 열면 갤러리 블록이 **보인다**
- [ ] 갤러리에 이미지 추가 → 보인다 / 삭제 → 사라진다 (`onRemove` 클로저가 산다)
- [ ] 코드로 확인: `isNew`일 때 `listByProgram`이 **호출되지 않는다** (R3)

## 5. 회귀 — 정규 클래스

이미 병합돼 있던 컬렉션이라 이 작업으로 깨질 이유는 없지만, 주석을 건드린다.

- [ ] `getForEdit()`를 계속 쓴다 — `get()`으로 바뀌지 않았다
- [ ] **이름만 고쳐 저장해도 업로드 자료가 남는다** (결정기록 01의 07 §3 5-1 회귀)
- [ ] 상세 자료 링크가 새 탭에서 열린다
