# 요구사항

## 1. 원문 요청

> - form 수정
> - 원데이클래스 인지 아니면 여러번 진행하는 클래스인지 체크 표기 필요
> - 원데이클래스인 경우는 강의일 일자 1일만 선택
> - 여러번 진행하는 클래스인 경우에는 form to 날짜 선택
> - html 파일을 업로드 할수 있는 기능 필요

## 2. 일정 유형 (schedule)

### 2.1 유형 선택

폼에 **일정 유형** 선택을 넣는다. 값은 둘 중 하나이고 항상 하나가 선택돼 있다.

| 값 | 라벨 | 의미 |
|----|------|------|
| `oneday` | 원데이 클래스 | 하루에 끝난다 |
| `multi` | 다회차 클래스 | 여러 날에 걸쳐 진행한다 |

**컨트롤은 라디오 두 개**로 만든다. 요청서 문구는 "체크 표기"지만 체크박스
하나(켜짐=원데이)로 만들면 안 된다 — 꺼진 상태가 "다회차"인지 "아직 안 정함"인지
화면만 봐서는 구분되지 않고, 나중에 "온라인 상시" 같은 세 번째 유형이 생기면
체크박스가 못 늘어난다.

`fields.tsx`에 라디오 프리미티브가 없다. `SelectField`(있음)로 시작해도 되지만
값이 둘뿐이라 셀렉트는 클릭이 한 번 더 든다. **`RadioField`를 `fields.tsx`에 새로
추가**하는 쪽을 권장한다(다른 폼에서도 쓸 자리가 있다).

### 2.2 날짜 입력

- `oneday` — **강의일** 날짜 1개만 받는다. 종료일 입력은 화면에서 **감춘다**
  (비활성만 시키면 값이 남아 있는지 알 수 없다).
- `multi` — **시작일 / 종료일** 두 개를 받는다.
- 유형을 바꿔도 이미 입력한 시작일은 유지한다. `multi → oneday`로 바꾸면
  종료일은 저장 시점에 버린다(폼 상태에는 남겨 두고, 다시 `multi`로 돌리면 복구).
- `DateField`가 이미 있다(`src/components/admin/content/fields.tsx:44`). ISO
  `YYYY-MM-DD` 문자열을 주고받는다. 그대로 쓴다.

### 2.3 검증

| 규칙 | 어디서 | 실패 시 |
|------|--------|---------|
| `multi`에서 종료일 < 시작일 | 폼(저장 버튼 비활성) + DB check | 폼: "종료일은 시작일보다 빠를 수 없어요" |
| 날짜 미입력 | 허용한다 | — |

날짜를 **필수로 만들지 않는다.** 기존 4개 과정은 "상시 모집, 기수별 일정 별도
공지" 형태로 운영 중이라 날짜가 없는 행이 정상이다. 필수로 걸면 기존 행을
수정하려 할 때마다 저장이 막힌다.

### 2.4 공개 화면 표기

날짜가 있을 때만 표기한다. 없으면 지금과 동일하게 `duration`(4주 등)만 나온다.

| 유형 | 값 | 표기 |
|------|-----|------|
| oneday | 2026-09-12 | `2026년 9월 12일 (하루 과정)` |
| multi | 2026-09-01 ~ 2026-10-05 | `2026년 9월 1일 – 10월 5일` |
| multi | 시작일만 | `2026년 9월 1일 시작` |
| 둘 다 없음 | — | 표기 없음 |

포맷 함수는 한 곳(`src/lib/education-content.ts` 또는 별도 `format.ts`)에 둔다.
목록·상세·어드민 미리보기가 같은 문자열을 쓰게 하기 위해서다.

## 3. HTML 상세 업로드

### 3.1 목적

정규 과정 상세 페이지 본문을 코드 배포 없이 교체할 수 있게 한다. 디자이너/
기획자가 만든 HTML 조각을 올리면 `/education/programs/[slug]` 본문에 들어간다
(→ [02-education-programs-public-pages](../02-education-programs-public-pages/00-START-HERE.md)에서 소비).

### 3.2 동작

1. 파일 선택 (`.html`, `.htm` 만)
2. 클라이언트에서 크기 검사 — **1MB 초과 거부**
3. 파일명과 본문을 폼 상태에 담고, 저장 시 서버 액션으로 넘긴다
4. 폼에 **현재 올라간 파일명 + 업로드 시각 + 제거 버튼**을 보여준다
5. **미리보기**: 정제된 결과를 폼 안에서 접었다 펼 수 있게(`<details>`) 보여준다.
   올린 것이 어떻게 나오는지 저장 전에 확인할 수 없으면, 확인 방법이 공개 페이지에
   직접 들어가 보는 것뿐이다.

`ImageUpload`(`src/components/admin/content/image-upload.tsx`)와 같은 자리·같은
생김새를 쓰되 **별도 컴포넌트**(`HtmlUpload`)로 만든다. 이미지 업로드는 Storage에
올리고 URL을 돌려주는 물건이라 흐름이 다르다.

### 3.3 무엇을 받아들이나

- `<body>` 안에 들어갈 **조각**을 기대한다. 통짜 문서(`<!doctype html>` 포함)가
  들어오면 서버에서 `<body>` 안쪽만 추출한다.
- `<style>`은 허용하되 **스코프를 씌운다**(§4 참고). 안 씌우면 올린 HTML의
  `h2 { color: red }` 한 줄이 사이트 전체 헤더를 물들인다.
- `<script>`, `on*` 속성, `<iframe>`, `<form>`, 외부 `<link rel=stylesheet>`는 **제거**한다.

## 4. 보안 — 이 기능의 핵심 위험

업로드된 HTML을 그대로 렌더하면 **저장형 XSS**가 된다. 어드민만 올릴 수 있어
위험이 낮다고 볼 수도 있지만, 지금 이 사이트에는 **로그인 세션(Supabase auth)이
같은 도메인에 있다.** 어드민 계정 하나가 털리거나 제3자가 만든 HTML을 검토 없이
올리는 순간, 방문자 브라우저에서 임의 스크립트가 도는 경로가 열린다.

**따라서 렌더 전 정제는 선택이 아니라 요구사항이다.**

- 정제는 **서버에서** 한다. 클라이언트 정제는 우회된다(액션을 직접 호출하면 그만).
- 라이브러리: `isomorphic-dompurify` 또는 `sanitize-html`. 도입 시
  `context7` MCP로 최신 API를 확인한다(CLAUDE.md 규약).
- 허용 태그 화이트리스트를 명시한다. 텍스트·목록·표·이미지·링크·`<style>` 정도.
- 렌더는 `dangerouslySetInnerHTML`을 쓸 수밖에 없다. **정제된 값만** 넣고,
  그 자리에 왜 안전한지 주석을 남긴다.
- 원본은 별도 컬럼에 그대로 보관한다 — 정제 규칙이 바뀌었을 때 다시 정제할
  근거가 없으면 파일을 다시 받아야 한다.

## 5. 받아들임 기준

- [ ] 폼에서 원데이/다회차를 고를 수 있고, 고른 것에 따라 날짜 입력이 1개/2개로 바뀐다
- [ ] `multi`에서 종료일이 시작일보다 빠르면 저장할 수 없다
- [ ] 날짜를 비워도 저장된다
- [ ] `.html` 파일을 올리면 파일명이 폼에 표시되고, 저장 후 다시 열었을 때도 남아 있다
- [ ] `.html`이 아닌 파일, 1MB 초과 파일은 명확한 한글 메시지와 함께 거부된다
- [ ] 올린 HTML 안의 `<script>`가 저장된 결과에서 사라진다 (테스트로 확인)
- [ ] `new`와 `[id]` 양쪽에서 동일하게 동작한다
- [ ] 기존 4개 과정을 열어 아무것도 안 고치고 저장해도 값이 유실되지 않는다
