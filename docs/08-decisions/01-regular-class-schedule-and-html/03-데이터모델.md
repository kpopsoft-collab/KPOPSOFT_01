# 데이터 모델

## 1. 추가 컬럼

`public.education_regular_classes`에 붙인다. 기존 컬럼은 건드리지 않는다.

| 컬럼 | 타입 | 기본값 | 뜻 |
|------|------|--------|-----|
| `schedule_type` | `text` (도메인 `education_schedule_type`) | `'multi'` | `oneday` \| `multi` |
| `start_date` | `date` | null | oneday면 **강의일**, multi면 **시작일** |
| `end_date` | `date` | null | multi 전용. oneday면 항상 null |
| `detail_html` | `text` | `''` | **정제된** 본문 조각 (렌더용) |
| `detail_html_raw` | `text` | `''` | 업로드 원본 (재정제·감사용, 렌더 금지) |
| `detail_html_name` | `text` | `''` | 원본 파일명 (어드민 표시용) |
| `detail_html_uploaded_at` | `timestamptz` | null | 업로드 시각 |

### 왜 `duration`을 놔두나

`duration`("4주")은 사람이 읽는 **표기**다. 날짜가 없는 상시 과정에서도 카드에
찍혀야 하고, 날짜가 생겨도 "총 4주 과정"이라는 정보는 시작/종료일에서 자동으로
안 나온다(주 1회 4주 = 4주지만 달력상 26일이다). 둘은 다른 정보라 함께 둔다.
`level`과 `tracks`를 따로 둔 것과 같은 이유다(`content-types.ts:178` 주석 참고).

## 2. 마이그레이션 DDL 초안

파일명: `supabase/migrations/2026MMDDHHMMSS_regular_class_schedule_and_html.sql`
(타임스탬프는 기존 최신 `20260802140000`보다 뒤여야 한다.)

```sql
-- 정규 클래스: 일정 유형(원데이/다회차) + HTML 상세 본문
-- 근거: docs/08-decisions/01-regular-class-schedule-and-html/
--
-- 기존 데이터는 수정하지 않는다. 기존 4개 과정은 schedule_type='multi',
-- 날짜 null 로 남는다(상시 과정 = 날짜 없음이 정상 상태).

-- ── 도메인 ────────────────────────────────────────────────────────────
do $$ begin
  create domain public.education_schedule_type as text
    check (value in ('oneday', 'multi'));
exception when duplicate_object then null; end $$;

-- ── 컬럼 ──────────────────────────────────────────────────────────────
alter table public.education_regular_classes
  add column if not exists schedule_type public.education_schedule_type
    not null default 'multi',
  add column if not exists start_date date,
  add column if not exists end_date   date,
  add column if not exists detail_html      text not null default '',
  add column if not exists detail_html_raw  text not null default '',
  add column if not exists detail_html_name text not null default '',
  add column if not exists detail_html_uploaded_at timestamptz;

-- ── 무결성 ────────────────────────────────────────────────────────────
-- 날짜는 "없어도 되지만, 있으면 앞뒤가 맞아야 한다".
-- 필수로 걸지 않는 이유: 기존 상시 과정 행이 저장 불가가 된다.
do $$ begin
  alter table public.education_regular_classes
    add constraint education_regular_classes_schedule_ck check (
      case schedule_type
        -- 원데이는 종료일이라는 개념이 없다. 남아 있으면 어느 쪽이 진짜인지
        -- 화면이 판단할 수 없으므로 아예 못 들어오게 막는다.
        when 'oneday' then end_date is null
        else start_date is null or end_date is null or end_date >= start_date
      end
    );
exception when duplicate_object then null; end $$;

-- 공개 화면이 "다가오는 일정"을 뽑을 때 쓴다.
create index if not exists education_regular_classes_start_date_idx
  on public.education_regular_classes (start_date)
  where start_date is not null;

comment on column public.education_regular_classes.detail_html is
  '정제(sanitize) 완료된 상세 본문 조각. 화면에 렌더되는 값은 이것뿐이다.';
comment on column public.education_regular_classes.detail_html_raw is
  '업로드 원본. 정제 규칙이 바뀌었을 때 재정제하는 근거. 절대 그대로 렌더하지 않는다.';

-- ── 되돌리기 (down) ───────────────────────────────────────────────────
--   alter table public.education_regular_classes
--     drop constraint if exists education_regular_classes_schedule_ck,
--     drop column if exists schedule_type,
--     drop column if exists start_date,
--     drop column if exists end_date,
--     drop column if exists detail_html,
--     drop column if exists detail_html_raw,
--     drop column if exists detail_html_name,
--     drop column if exists detail_html_uploaded_at;
--   drop domain if exists public.education_schedule_type;
--   drop index if exists public.education_regular_classes_start_date_idx;
```

적용: `mcp__supabase__apply_migration` 또는 `supabase db push`.
> ⚠️ **"추가 작업 없음"은 틀렸다.** RLS가 **행 단위**라 게시된 행의 모든 컬럼이
> anon에게 열린다. 정제 전 원본을 같은 테이블에 두면 공개 API로 그대로 내려간다.
> 확정본은 원본을 관리자 전용 동반 테이블로 분리했다 →
> [10-마이그레이션-DDL.md](10-마이그레이션-DDL.md)

## 3. HTML을 어디에 둘 것인가 (결정 D1)

### 안 A — DB 컬럼 (**권장**)

업로드 위젯이 브라우저에서 파일 텍스트를 읽어(`file.text()`) 폼 상태에 담고,
서버 액션이 정제해서 `detail_html`에 저장한다. Storage를 아예 안 쓴다.

| | |
|---|---|
| 장점 | 버킷·MIME·RLS 추가 설정 없음. 정제를 **저장 시점에 강제**할 수 있다. 공개 페이지가 행 하나만 읽으면 끝(추가 fetch 없음). 롤백·이력이 DB와 함께 간다 |
| 단점 | 1MB 넘는 문서에는 부적합. Postgres `text`는 한도가 훨씬 크지만 매 조회에 실려 온다 |
| 완화 | 1MB 제한을 업로드 단에서 건다. 목록 조회 시 `select`에서 `detail_html`을 빼면 페이로드가 늘지 않는다 |

### 안 B — Storage 파일

`education-docs` 버킷을 새로 만들고(`text/html` 허용) 파일을 올린 뒤 URL만 저장.

| | |
|---|---|
| 장점 | 큰 문서에 유리 |
| 단점 | **공개 버킷에 HTML을 두면 그 자체가 실행 가능한 페이지가 된다** — `*.supabase.co/storage/.../x.html`로 직접 접근되고, 정제를 거치지 않는다. 막으려면 비공개 버킷 + 서명 URL + 서버 fetch가 필요한데, 그러면 페이지마다 왕복이 하나 는다 |
| 필요 시 | 버킷은 **반드시 `public = false`**. `education` 버킷에 `text/html`을 추가하는 선택지는 없다(그 버킷은 공개다) |

**결론: A로 간다.** 상세 페이지 본문 조각은 문서라기보다 콘텐츠 필드에 가깝고,
1MB는 본문 HTML로 충분히 크다. B가 필요할 만큼 큰 파일이 실제로 들어오면 그때
`detail_html_url` 컬럼을 하나 더 붙여 A와 공존시킨다(둘 중 있는 쪽을 쓴다).

## 4. 타입 변경

### `src/lib/admin/content-types.ts`

```ts
/** 정규 클래스 일정 유형. 원데이는 종료일 개념이 없다. */
export type EducationScheduleType = "oneday" | "multi";

export const EDUCATION_SCHEDULE_TYPES: readonly EducationScheduleType[] = [
  "oneday",
  "multi",
] as const;

export const educationScheduleTypeLabel: Record<EducationScheduleType, string> = {
  oneday: "원데이 클래스",
  multi: "다회차 클래스",
};

export type EducationRegularClass = ContentBase & {
  // ... 기존 필드 그대로 ...
  scheduleType: EducationScheduleType;
  /** ISO "YYYY-MM-DD". oneday면 강의일, multi면 시작일. 없으면 빈 문자열. */
  startDate: string;
  /** ISO "YYYY-MM-DD". multi 전용. */
  endDate: string;
  /** 정제 완료 본문. 렌더되는 값. */
  detailHtml: string;
  /** 업로드 원본. 렌더 금지. */
  detailHtmlRaw: string;
  detailHtmlName: string;
};
```

날짜를 `string | null`이 아니라 **빈 문자열**로 두는 이유: `DateField`가 빈
문자열을 "미입력"으로 다루고, 폼 상태 전체가 이미 문자열 기반이다. null을
섞으면 폼에서 `?? ""`가 필드마다 붙는다. DB로 나갈 때 `"" → null`로 바꾼다.

`detailHtmlUploadedAt`은 어드민 표시용이라 굳이 타입에 넣지 않아도 된다.
표시하려면 `detailHtmlUploadedAt: string`으로 추가하고 매핑에도 넣는다.

### `src/lib/admin/supabase-content.ts` — `FIELDS`

```ts
education_regular_classes: [
  ...COMMON,
  // ... 기존 ...
  ["scheduleType", "schedule_type"],
  ["startDate", "start_date"],
  ["endDate", "end_date"],
  ["detailHtml", "detail_html"],
  ["detailHtmlRaw", "detail_html_raw"],
  ["detailHtmlName", "detail_html_name"],
],
```

> `""`(빈 문자열)를 `date` 컬럼에 그대로 보내면 Postgres가 거부한다.
> `SupabaseRepo`의 변환 지점에서 빈 날짜를 `null`로 바꾸는 처리가 필요하다.
> 범용 매핑을 건드리기 싫다면 **서버 액션(`actions.ts`)에서 정규화**한다 —
> 그 편이 영향 범위가 좁다. [04-구현계획.md](04-구현계획.md) 3단계 참고.

### `src/lib/education-content.ts` — 공개 타입

정적 폴백 4개 행에는 `scheduleType: "multi"`만 넣고 날짜는 비운다.
