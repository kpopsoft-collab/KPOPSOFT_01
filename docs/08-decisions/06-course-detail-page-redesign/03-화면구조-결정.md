## 1. 결정 D1~D8

### D1. 업로드 HTML 인라인 렌더링을 **폐지**한다

근거 [01](01-현황분석-무엇이-깨졌나.md) §3 — 정제기가 지우는 세 가지(`<script>`,
`@keyframes`/`@font-face`, `position`)가 전부 문서 한 장을 문서답게 만드는
요소다. 되살리면 정제가 무의미하고, 안 되살리면 화면이 빈다. **인라인 경로에
고칠 지점이 없다.**

### D2. `.html` 한 장도 **Storage에 올린다**

번들과 **같은 파이프라인·같은 버킷·같은 모양**(`education/<uuid>/index.html`).
zip을 푸는 단계만 건너뛴다. 새 필드도 새 버킷도 없다.

얻는 것: **원본이 정제 없이 그대로** 남는다.
잃는 것: 업로드 HTML의 검색 색인. 결정기록 05가 번들에 대해 이미 받아들인
비용이고([그 폴더 01-요구사항](../05-course-bundle-storage/01-요구사항.md) §3-1),
그래서 상세 페이지 **본체가 색인 대상으로 온전해야 한다** — D4가 그것을 보장한다.

### D2-정정 (2026-08-05 구현 중). Storage 공개 URL을 **새 탭 주소로 쓸 수 없다**

> **착수 때 이 결정은 "Storage 공개 URL을 그대로 새 탭에 연다"였다. 틀렸다.**

**Supabase Storage는 HTML을 의도적으로 `text/plain`으로 내려준다.** 저장된
메타데이터가 `text/html`이어도 응답 헤더는 `text/plain`이라, 새 탭에 열면
페이지가 아니라 **소스 코드가 그대로** 보인다. 남용·피싱 신고 대응을 위한
플랫폼 정책이고 버킷 설정으로 못 바꾼다
([supabase/supabase#7424](https://github.com/supabase/supabase/issues/7424),
[discussions#2557](https://github.com/orgs/supabase/discussions/2557)).

> **이건 이번에 생긴 문제가 아니다.** 2026-08-04에 올린 zip 번들
> (`vibe-coding`)도 **같은 이유로 계속 깨져 있었다.** 결정기록 05가 해소했다고
> 적은 리스크("Storage가 공개 `.html`을 그려 주는가")는 실제로는
> **파일이 올라갔다**는 것까지만 확인한 것이었다. 열어 본 사람이 없었다.

**그래서 새 탭 주소는 우리 라우트다** — `/course-assets/<uuid>/<path>`
(`src/app/course-assets/[...path]/route.ts`). Storage에서 그대로 가져와
Content-Type만 다시 붙여 내보낸다. **파일은 여전히 Storage에 있다**(D2 유지).

### D3-정정. 우리 도메인으로 서빙한다 — **`CSP: sandbox`가 조건이다**

> **착수 때 이 결정은 "우리 도메인 프록시 금지"였다(결정기록 05 D4 승계). 뒤집었다.**

결정기록 05 D4의 전제는 **Storage가 격리된 origin으로 동작한다**였다. D2-정정에서
그 전제가 무너졌으므로 결정을 다시 내린다. **대안이 없다** — Storage 공개 URL은
소스 코드를 보여주고, 별도 서브도메인·다른 호스트는 결정기록 05 D1이 이미 버렸다.

D4가 지키려던 것(업로드된 JS가 `kpopsoft.com`의 세션·스토리지에 닿지 못하게)은
응답 헤더 **`Content-Security-Policy: sandbox`** 로 지킨다. `allow-same-origin`을
주지 않으면 문서가 **불투명 origin(`null`)** 이 되어 same-origin 검사에 항상
실패한다.

착수 때 이 안을 버린 이유는 *"한 줄짜리 헤더에 origin 격리를 통째로 의존하게
된다"* 였다. 그 우려는 유효하다 — 그래서 **헤더 하나에만 걸지 않는다**:

| 층 | 무엇 |
|----|------|
| 1 | `CSP: sandbox` (allow-same-origin **없음**) → 불투명 origin |
| 2 | `<uuid>/` 모양(`BUNDLE_PATH_RE`) 강제 → 버킷의 다른 키로 못 넘어간다 |
| 3 | **DB에 등록된 번들 경로만** 허용 → 우리 도메인이 임의 파일의 공개 프록시가 되지 않는다 |
| 4 | 확장자 허용목록(`EXT_MIME` 15종) → 업로드 때 허용한 것 밖은 안 내보낸다 |
| 5 | `X-Content-Type-Options: nosniff` · `X-Robots-Tag: noindex` |

실측(2026-08-05, 로컬): `window.origin === "null"`, `localStorage`·
`document.cookie` 접근이 **둘 다 예외로 막힘**, 슬라이드 25장 정상 렌더.

> 이 라우트는 결정기록 05 D4가 말한 "예쁜 URL"이 아니다. **렌더 가능한 URL**이다.
> 서브도메인으로 옮기더라도 `text/plain` 문제는 그 앞단에서 똑같이 풀어야 한다.

### D4. 커리큘럼은 **항상** 보인다

업로드물은 커리큘럼을 대체하지 않는다. 본문 3분기(`detailHtml` / `bundleUrl` /
`curriculum`)를 없애고, 커리큘럼은 고정 블록, 업로드물은 **그 아래 별도 블록**이다.
조사 §3-1 — 커리큘럼이 결정을 만든다.

### D5. 데스크톱은 **비대칭 2단**

`lg` 이상에서 본문(8칸)과 우측 sticky 요약 카드(4칸). 요약 카드에 기간·난이도·
일정·트랙 + 문의 CTA를 묶는다. 조사 §3-4, 그리드 문서의 *asymmetric 2-column*.

`lg` 미만에서는 1단이고, 요약 카드는 히어로 바로 아래에 **한 번** 놓는다.
모바일 하단에는 **고정 CTA 바**를 둔다(조사 §3-6).

### D6. 되돌아가는 길을 만든다

- 히어로 위 breadcrumb — `교육 › 정규 클래스 › <과정명>`
- 페이지 하단 **다른 과정 3장** — 목록 카드 컴포넌트 재사용

### D7. 기존 `detail_html` 행은 **백필**한다

동반 테이블(`education_regular_class_html_sources`)의 **원본**을 Storage에
올리고 `detail_bundle_path`를 채운 뒤 `detail_html`을 비운다.
원본은 동반 테이블에 그대로 남으므로 **되돌릴 수 있다.**

### D8. `detail_html` 컬럼과 `CourseHtml`은 이번에 **지우지 않는다**

백필이 운영에서 확인될 때까지 되돌릴 여지를 남긴다. 화면은 더 이상 읽지 않는다.
정리는 다음 작업으로 넘긴다([05-검증체크리스트](05-검증체크리스트.md) 마지막 줄).

## 2. 확정 구조

```
Header

① Breadcrumb            교육 › 정규 클래스 › AI 도구 마스터        (전폭 1280)
② Hero                  accent 패널 — 순번 / 과정명 / 부제 / 설명   (전폭 1280)
                        ※ 메타 dl은 ③으로 옮긴다 (중복 제거)

──── lg 이상 2단 시작 ────────────────────────────────────────────
│ 본문 (8칸)                        │ ③ 요약 카드 (4칸, sticky)   │
│                                   │    기간 · 난이도 · 일정      │
│ ④ 대표 이미지                      │    트랙 태그               │
│ ⑤ 이 과정을 마치면 (설명 재배치)      │    [교육 문의하기]          │
│ ⑥ 무엇을 배우나요 — 커리큘럼          │    [상세 자료 보기 ↗]       │
│ ⑦ 상세 자료 블록 (있을 때만)         │                            │
──────────────────────────────────────────────────────────────

⑧ 다른 과정 — 카드 3장                                  (전폭 1280)
⑨ 문의 CTA 패널                                        (전폭 1280)

Footer
⑩ 모바일 전용 하단 고정 CTA 바 (lg 미만)
```

### 블록별 규칙

| # | 블록 | 언제 보이나 | 비고 |
|---|------|-----------|------|
| ① | Breadcrumb | 항상 | 마지막 항목은 링크 아님 (`aria-current="page"`) |
| ② | Hero | 항상 | accent flat color. 도형 2개. **메타 dl 제거** |
| ③ | 요약 카드 | 항상 | `lg`↑ sticky `top-24`, 미만은 정적 1회 |
| ④ | 대표 이미지 | `image` 있을 때 | 본문 컬럼 폭에 맞춘다 (768 고정 폭 폐기) |
| ⑤ | 이 과정을 마치면 | `description` 있을 때 | 히어로의 긴 설명을 여기로 |
| ⑥ | 커리큘럼 | `curriculum.length > 0` | **업로드와 무관하게 항상** |
| ⑦ | 상세 자료 | `bundleUrl` 있을 때 | 새 탭. `rel="noopener noreferrer"` |
| ⑧ | 다른 과정 | 다른 공개 과정 ≥1 | 최대 3장 |
| ⑨ | 문의 CTA | 항상 | 기존 `ProgramInquiryCta` 유지 |
| ⑩ | 모바일 CTA 바 | `lg` 미만 | 높이 44px↑, `pb-[env(safe-area-inset-bottom)]` |

### 일정 표기 — 빈 값을 감추지 않는다

`formatClassSchedule()`이 `null`이면 지금은 항목이 사라진다. 요약 카드에서는
**"상시 모집 · 문의 시 안내"** 로 적는다. 빈칸은 "정보가 없다"가 아니라
"확인하지 못했다"로 읽힌다.
