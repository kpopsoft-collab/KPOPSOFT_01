`/education/programs/[slug]` 상세 페이지를 다시 짠다. 두 가지가 문제다.

1. **업로드 HTML을 페이지 안에 인라인으로 그린다.** 실제 업로드물(1920×1080
   슬라이드 덱)이 **29,435px짜리 거의 빈 페이지**로 나온다. 근거는
   [01-현황분석](01-현황분석-무엇이-깨졌나.md).
2. **페이지 구성이 상세 페이지 구실을 못 한다.** 히어로 → 이미지 → 본문 →
   CTA 넷뿐이고, 업로드가 있으면 **커리큘럼이 통째로 사라진다.** 되돌아갈
   링크도, 다른 과정으로 가는 길도 없다.

## 결정 요약 (자세한 근거는 [03](03-화면구조-결정.md))

| # | 질문 | 결정 |
|---|------|------|
| D1 | 업로드 HTML을 어디에 그리나 | **인라인 폐지.** 번들과 같이 **새 탭**으로만 연다 |
| D2 | 파일을 어디에 두나 | **Storage.** `.html` 한 장도 `<uuid>/index.html`로 올린다 — 번들 파이프라인 재사용 |
| D2-정정 | Storage 공개 URL을 새 탭에 그대로 쓰나 | **못 쓴다.** Storage가 HTML을 `text/plain`으로 내려 소스 코드가 보인다 |
| D3-정정 | 그럼 어디로 여나 | **우리 라우트** `/course-assets/<uuid>/…` + **`CSP: sandbox`**(불투명 origin). 결정기록 05 D4를 뒤집었다 |
| D4 | 커리큘럼은 언제 보이나 | **항상.** 업로드는 커리큘럼을 대체하지 않고 **옆에 붙는다** |
| D5 | 레이아웃 | 데스크톱 **비대칭 2단** — 본문 + 우측 sticky 요약 카드 |
| D6 | 되돌아가는 길 | 히어로 위 **breadcrumb** + 하단 **다른 과정 3장** |
| D7 | 기존 `detail_html` 행 | **백필**로 Storage에 옮기고 컬럼을 비운다. 원본은 동반 테이블에 그대로 남아 되돌릴 수 있다 |
| D8 | `detail_html` 컬럼·`CourseHtml` | 이번엔 **지우지 않는다.** 백필 확인 뒤 별도로 정리 |

## 왜 D2인가 — 인라인으로는 원리적으로 못 고친다

업로드물은 "본문 조각"이 아니라 **완성된 문서 한 장**이다. 인라인으로 그리면
셋이 동시에 깨진다.

| 깨지는 것 | 이유 | 인라인에서 고칠 수 있나 |
|---|---|---|
| JS로 드러나는 콘텐츠 | 정제가 `<script>`를 지운다 | ❌ 스크립트를 살리면 정제 자체가 무의미 |
| `@keyframes`·`@font-face` | 정제가 `media`·`supports` 외 at-rule을 버린다 | ❌ 같은 이유 |
| 상대경로 `assets/…` | `.html` 한 장에는 그 파일이 없다 | ❌ 텍스트 컬럼 하나로는 대상이 존재하지 않는다 |

셋 다 **정제와 단일 파일이라는 전제 자체**에서 나온다. 반대로 파일을 Storage에
그대로 두고 새 탭에서 열면 **원본 그대로** 보인다.

> ⚠️ 착수 때는 그 새 탭 주소가 Storage 공개 URL일 것이라고 봤다. **틀렸다** —
> Storage는 HTML을 `text/plain`으로 내려서 소스 코드가 보인다. 그래서 주소는
> 우리 라우트(`/course-assets/…`)가 되고, origin 격리는 `CSP: sandbox`가
> 대신한다. 전말은 [03-화면구조-결정](03-화면구조-결정.md) D2-정정·D3-정정.
> **2026-08-04에 올린 zip 번들도 같은 이유로 이미 깨져 있었다.**
