## 1. 무엇이 막고 있었나

Report-Only는 2026-08-05에 걸렸다. 강제로 못 바꾼 이유는 하나였다.

`'strict-dynamic'`이 켜지면 `'self'`는 **무시되고** nonce 있는 스크립트만 돈다.
그런데 nonce는 `proxy.ts`가 요청마다 만들어 CSP 헤더에 넣는 값이라,
**빌드 때 미리 만들어 둔 HTML에는 없다.**

2026-08-05 실측 — `/admin/login`은 script 13개 중 nonce **0개**.
그대로 전환했으면 **관리자가 아무도 로그인할 수 없게 된다.**

## 2. 두 방향 중 1번을 골랐다

| | 방향 | 판단 |
|---|---|---|
| 1 | 정적 페이지를 동적 렌더링으로 바꾼다 | **채택** |
| 2 | `'strict-dynamic'`을 빼고 `'self'`로 번들을 허용한다 | **문제를 못 푼다** |

2번이 안 되는 이유 — `'self'`로 바꿔도 **인라인 RSC 페이로드**
(`<script>self.__next_f.push(…)</script>`)는 여전히 nonce나 hash가 필요하다.
정적 페이지는 똑같이 깨진 채로 남고, 대신 `'strict-dynamic'`이 주는
"nonce 있는 스크립트가 불러온 것만 실행" 성질까지 잃는다. **둘 다 나빠진다.**

## 3. 범위를 먼저 쟀다 — 3개뿐이었다

전 페이지를 동적으로 바꾼다고 하면 커 보이지만, 실제로 정적이던 HTML 라우트는
셋뿐이었다. 나머지 40여 개는 Supabase를 읽어서 이미 동적이다.

| 라우트 | 무엇 |
|---|---|
| `/admin/login` | 순수 클라이언트 컴포넌트라 서버 데이터가 없었다 |
| `/education/cases` | **빈 플레이스홀더** 페이지 |
| `/_not-found` | Next 기본 404 |

`icon.png` · `icon.svg` · `manifest.webmanifest` · `opengraph-image.png`도 정적이지만
**HTML이 아니고 이미 matcher 제외분**이라 상관없다. 전환 뒤에도 정적으로 남았다.

## 4. 페이지별이 아니라 루트 레이아웃에 걸었다

```ts
// src/app/layout.tsx
export const dynamic = "force-dynamic";
```

페이지 3개에 각각 다는 쪽이 "필요한 곳만 건드린다"는 점에서 얌전해 보인다.
그런데 그렇게 하면 **나중에 추가되는 정적 페이지가 조용히 막힌다.**

- 빌드 로그의 `○` 표시를 눈으로 보지 않으면 알아챌 방법이 없다
- 증상은 "그 페이지만 인터랙션이 안 된다"라 CSP까지 거슬러 올라가기 어렵다
- 강제 CSP는 실패가 조용하다 — 콘솔에만 남고 화면은 그냥 안 움직인다

루트 한 줄이면 새 페이지도 자동으로 지켜진다. **잃는 것은 사실상 없다** —
위 3개 중 실사용 페이지는 로그인 화면 하나이고, 그마저 캐시 이득이 의미 없다.

> `not-found.tsx`에는 라우트 세그먼트 설정을 쓸 수 없다(Next는 `layout`·`page`·
> `route`에서만 읽는다). `connection()`을 부르는 커스텀 `not-found.tsx`를 새로
> 만들 수도 있었지만, 루트 레이아웃 방식이면 그 파일 없이 `/_not-found`까지
> 같이 동적이 된다 — 실제로 그렇게 됐다(§5).

## 5. 실측 — 무엇을 어떻게 확인했나

**HTML에 nonce가 있는 것과 브라우저가 스크립트를 실제로 실행하는 것은 다르다.**
둘 다 쟀다.

### 5-0. 먼저, 배포본이 문서와 맞는가 (Report-Only 시점)

전환을 논하기 전에 **배포된 것이 문서에 적힌 정책과 같은지**부터 확인했다.
`www.kpopsoft.com` 응답 헤더 실측.

| 잰 것 | 결과 |
|---|---|
| 홈 · `/education` · `/education/programs` · 상세 · `/admin/login` | 전부 정책이 붙는다 |
| `/course-assets/<uuid>/index.html` | `CSP: sandbox …` **하나만** — 전역 정책이 안 겹친다 |
| prod 정책에 `'unsafe-eval'` · `ws:` | **없음** — dev 추가분이 새지 않았다 |
| `POST` / `GET` / 비JSON `POST` → `/api/csp-report` | `204` / `405` / `204` |

### 5-1. 빌드 산출물

`force-dynamic` 전후로 `next build`의 라우트 표를 비교했다.
정적(`○`) HTML 라우트 3개 → **0개.** 메타데이터 파일 4개만 `○`로 남았다.

### 5-2. nonce 커버리지 (프로덕션 빌드, `next start`)

라우트마다 `<script>` 태그 수와 그중 nonce가 박힌 수를 셌다.

| 라우트 | 전 | 후 |
|---|---|---|
| `/admin/login` | **0 / 13** | **11 / 11** |
| `/education/cases` | 0 | **19 / 19** |
| `/_not-found` | 0 | **10 / 10** |
| 홈·`/education`·`/work`·상세 4개·목록 | 이미 100% | 100% 유지 |

11개 라우트 전부 `script 수 == nonce 수`.

### 5-3. 브라우저 (CDP, headless Chrome) — **강제 모드로**

nonce가 박혀 있어도 실행이 막힐 수 있으므로 실제 브라우저로 확인했다.

| 본 것 | 결과 |
|---|---|
| CSP 위반 · JS 예외 · `console.error` | **8개 라우트 전부 0건** |
| 하이드레이션 (React가 컨테이너에 붙었나) | 전부 성공 |
| **상호작용** (헤더 메뉴 버튼 클릭 → `aria-expanded` 변화) | 전부 반응 |
| 서버가 받은 위반 보고 (`/api/csp-report`) | **0건** |

> 하이드레이션만 보면 "붙긴 했는데 동작은 안 한다"를 못 잡아서 클릭까지 넣었다.
> 처음에는 클릭 직후 같은 동기 블록에서 속성을 읽어 전부 "무반응"으로 나왔다 —
> React 상태 반영은 다음 렌더라 클릭과 확인을 나눠야 한다.

### 5-4. 업로드 강의 자료 — 이번 전환의 유일한 진짜 위험 지점

전역 정책이 `/course-assets`로 새면 nonce 없는 자료 속 스크립트가 전부 막혀
**자료가 통째로 안 뜬다.** 강제 모드에서 다시 쟀다.

| 잰 것 | 결과 |
|---|---|
| 응답 헤더 | `CSP: sandbox …` **하나만** (전역 정책 안 붙음) |
| `self.origin` | `null` — 불투명 origin, 격리 살아 있음 |
| `localStorage` 접근 | 차단됨 |
| 이미지 | **6/6 로드** |
| CSP 위반 | 0건 |

## 6. 되돌리는 법

`proxy.ts`의 `CSP_HEADER_NAME`에 `-Report-Only`를 도로 붙이면 된다. 한 줄이다.

`src/app/layout.tsx`의 `force-dynamic`은 **그때도 남겨 둔다** — 그게 없으면
다시 강제로 걸 때 같은 문제가 되살아난다.

## 7. 남은 것

`style-src 'unsafe-inline'`. [02-정책초안.md](02-정책초안.md) §4와
[00-START-HERE](00-START-HERE.md)의 정정 블록에 이유가 있다 —
`style={{…}}` 11곳과 `next/image`의 `fill`이 박는 `style` 속성 때문이고,
**nonce는 `<style>` 요소에만 붙고 `style` 속성에는 적용되지 않는다.**
프레임워크가 주입하는 쪽은 우리 코드로 없앨 수 없다.

CSP의 XSS 방어력은 대부분 `script-src`에서 나오고 그쪽은 nonce로 완전히 닫혔다.
