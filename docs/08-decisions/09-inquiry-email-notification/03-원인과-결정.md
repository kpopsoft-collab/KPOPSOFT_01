# 03 — 원인과 결정

이 작업의 기준 문서다. [04-구현계획](04-구현계획.md)은 여기서만 근거를 가져온다.

## 1. 원인은 3단이다

| | 벽 | 실측 | 안 고치면 |
|---|---|---|---|
| 1 | `RESEND_API_KEY` 미설정 | [02](02-현황분석.md) §3 | 발송 시도조차 안 함 |
| 2 | **Resend 자체가 승인 설계와 다름** | [01](01-요구사항.md) 승인된 설계 | 키를 채워도 KPO-23 미충족 |
| 3 | 실패가 콘솔에만 남음 | [02](02-현황분석.md) §2 | 또 조용히 안 오고, 또 모름 |

**2번이 이번 조사의 핵심이다.** 처음엔 "키만 채우면 된다"로 보였는데,
KPO-23을 읽고 나니 **채워야 할 키가 다른 서비스의 것**이었다.

## 2. 결정

### D1 — 문의 저장 경로는 손대지 않는다

운영 DB에 3건이 정상 저장돼 있고 형식도 현재 폼과 일치한다.
저장은 문제가 아니다.

**버린 대안** — "혹시 모르니 저장 경로도 같이 점검한다."
실측으로 정상을 확인한 코드를 건드리는 건 없는 문제를 만드는 것이다.

### D2 — Cloudflare Email Service로 간다. Resend가 아니다

`src/lib/email.ts`의 Resend 구현을 Cloudflare로 **교체**한다.

**근거 세 가지.**

1. **KPO-23 승인 설계 §7이 Cloudflare로 확정했다.** 2026-07-24 댓글로
   공지됐고 구현 계획까지 커밋돼 있다.
2. **DNS가 이미 Cloudflare다**([02](02-현황분석.md) §5). NS·MX·SPF 전부.
   Cloudflare로 가면 DNS 추가 작업이 **없다.**
3. **Resend로 가면 SPF를 고쳐야 한다.** 현재 SPF는
   `include:_spf.mx.cloudflare.net ~all` 하나뿐이라 Resend 발송은 SPF에서
   떨어진다. 승인 설계를 어기면서 DNS 작업이 **늘어난다.**

**버린 대안 1** — main에 이미 있는 Resend를 그대로 살린다(코드·의존성 있음).
→ 당장은 싸 보이지만 승인 설계와 어긋나고, SPF를 새로 손봐야 하고,
KPO-23의 **수신** 요구(D6)는 어차피 Cloudflare Email Routing이 해결한다.
서비스를 둘로 쪼갤 이유가 없다.

**버린 대안 2** — Gmail SMTP / Nodemailer.
→ 승인 설계에 없고 앱 비밀번호 관리가 더 나쁘다.

**버린 대안 3** — codex 브랜치를 main에 병합해 한 번에 해결.
→ D4에서 다룬다. 스택이 통째로 다르다.

> ✅ **확정됨 (2026-08-11).** KPO-28 다이어그램이 `Resend`로 적혀 있어
> 모순이었으나, 사용자가 **"resend 아니고 Cloudflare 기준이 맞음"**으로
> 확답했다. KPO-28 다이어그램이 낡은 것이다.
> → `docs/06-admin/03-…:61`과 함께 KPO-28도 정정 대상이다(§4).

### D3 — 수신자는 검증된 `kpopsoft@gmail.com` 하나로 고정한다

`INQUIRY_NOTIFICATION_TO=kpopsoft@gmail.com`.

**이건 비용 결정이다**([02](02-현황분석.md) §8). Cloudflare 공식 문서:
검증된 destination address로 보내는 메일은 **전 플랜 무료**,
임의 수신자는 **Workers 유료 플랜** 필요.
수신자를 늘리는 순간 과금 구조가 바뀐다.

`docs/06-admin/04-결정사항과-착수순서.md:39`가 "발송 연동 시 결정"으로 미뤄 둔
항목이 이것이다. 지금 정한다 — **`admin_users` 전체 폴백은 쓰지 않는다.**

**왜 `admin_users` 폴백을 버리나** — 두 가지 이유가 겹친다.
- `admin_users`는 **로그인 권한** 목록이지 알림 수신 목록이 아니다.
  관리자 초대 UI가 붙으면 수신자가 말없이 따라 늘어난다.
- 늘어난 주소는 Cloudflare에서 **검증되지 않은 주소**다 → 무료 조건을
  벗어나거나 발송이 거부된다. 조용히 비용이 새거나 조용히 실패한다.

수신자를 늘리려면 **Cloudflare에서 먼저 검증**하고 env에 명시한다.

### D4 — 이메일 모듈 2개만 이식한다

`origin/codex/kpopsoft-maxonomy-concept-wind`에서 가져올 것.

- `src/lib/inquiries/email-message.ts` — **그대로.** main의 `Inquiry` 타입과
  필드가 정확히 맞는다([02](02-현황분석.md) §6)
- `src/lib/integrations/cloudflare-email.ts` — `DeliveryAttempt` 타입 추가 후
- 대응 테스트 2개도 참고해 옮긴다

**가져오지 않을 것** — Neon, Auth.js, Vercel Blob, Linear 이슈 자동 생성,
Billing Hub. main은 Supabase 스택이다([02](02-현황분석.md) §7).

**버린 대안** — 브랜치를 main에 병합한다.
→ DB·인증·스토리지를 전부 갈아엎는 일이다. "메일이 안 온다"를 고치는
작업이 스택 교체로 번진다. **그 판단은 따로 해야 한다** — 별건으로 남긴다.

### D5 — 알림이 못 나간 사실을 눈에 보이게 한다

1. 미설정·실패 로그를 `[email] 문의 알림 미발송 — <이유>` + **문의 id** 형식으로
   통일한다. id가 있으면 어드민에서 그 건을 찾아 수동 대응할 수 있다.
2. `console.info` → **`console.warn`**. 운영에서 키가 없으면 `console.error`.
   "로그 전용"은 의도된 모드처럼 읽힌다. 실제로는 알림이 죽은 상태다.
3. Cloudflare 응답의 `queued` / `permanent_bounces`도 **실패로 로그**한다
   (설계 §7의 상태 판정). `delivered`가 비었는데 성공으로 넘기면
   지금과 똑같이 조용해진다.

**버린 대안 1** — 발송 실패 시 사용자에게 에러를 보여준다.
→ `docs/06-admin/03…:47`이 "발송 실패해도 저장은 성공 처리"로 못박았다.
문의자 입장에선 접수가 실제로 됐다. 우리 알림 사정으로 실패를 알리면
**재제출을 유도**해 중복 문의만 쌓인다.

**버린 대안 2** — 실패 알림을 큐에 넣고 재시도한다.
→ 지금 문제는 "설정이 없어 100% 안 나감"이라 재시도가 못 고친다.
승인 설계는 **관리자 화면의 수동 재시도**를 쓴다. 그쪽이 맞고,
이번 범위 밖이다(별건).

### D6 — 수신도 이 작업에 포함한다

`inquiry@kpopsoft.com` → `kpopsoft@gmail.com` 전달을 Email Routing으로 켠다.

**왜 포함하나** — KPO-23 본문이 "이메일 발송 / 이메일 **수신**" 두 줄이다.
발송만 하고 닫으면 그 작업은 안 끝난다.
그리고 **MX·SPF가 이미 깔려 있어**([02](02-현황분석.md) §5) 남은 건
라우팅 규칙과 destination 검증뿐이다. 지금 같이 하는 게 싸다.

또 하나 — 발송 주소가 `inquiry@kpopsoft.com`인데 그리로 온 답장이
아무 데도 안 가면 곤란하다. 발송과 수신은 같이 서야 말이 된다.

### D7 — 응답 매퍼를 고쳐서 이식한다 (실측 근거로 확정)

`mapCloudflareEmailResponse()`는 세 배열이 전부 빈 응답을 `provider_error`로
떨어뜨린다. 그런데 **실제 API가 정상 발송에서 그 응답을 준다** —
테스트 메일이 도착한 것을 확인했다([02](02-현황분석.md) §9-1).

**고칠 판정 규칙**

| 응답 | 판정 | 로그 |
|---|---|---|
| `permanent_bounces` 있음 | 실패 | `permanent_bounce` |
| HTTP 200 + `success:true` + `message_id` 있음 | **접수 성공** | 없음 |
| 그 외(비200·`success:false`·`message_id` 없음) | 실패 | `provider_error` |

`delivered`·`queued`는 **있으면 참고**하되 **비었다고 실패로 보지 않는다.**
지금 경로에서는 정상일 때도 비어 있다.

**왜 이렇게 정하나** — 이 API로 확인할 수 있는 것은 **접수까지**다.
접수를 성공으로 잡아야 거짓 실패가 안 생기고, `permanent_bounces`만 실패로
잡으면 진짜 거부는 놓치지 않는다. 확인 못 하는 것(최종 전달)을
확인한 척하지 않는다.

**버린 대안** — 매퍼를 그대로 두고 `provider_error`를 무시하도록 로그만 낮춘다.
→ 그러면 **진짜** `provider_error`도 같이 묻힌다. 이번 건이 정확히
"신호를 낮춰 놨더니 안 보이더라"였다. 같은 실수를 반복하지 않는다.

> 교훈 — codex 브랜치의 `tests/cloudflare-email.test.mts`는 이 매퍼를
> 통과시킨다. 가짜 응답으로만 돌았기 때문이다. **테스트가 초록인 것과
> 실제로 맞는 것은 다르다.** 이식할 때 실제 응답 픽스처를 추가한다.

## 3. 어떤 env를 쓰나 — 이름이 바뀐다

승인 설계 §7이 지정한 이름을 그대로 쓴다. codex 브랜치 코드가 이 이름을 읽는다.

| 버릴 것 | 쓸 것 |
|---|---|
| `RESEND_API_KEY` | `CLOUDFLARE_API_TOKEN` (`Email Sending: Edit` 최소 권한) |
| `RESEND_FROM` | `CLOUDFLARE_ACCOUNT_ID` |
| `INQUIRY_NOTIFY_TO` | `INQUIRY_NOTIFICATION_FROM` = `inquiry@kpopsoft.com` |
| | `INQUIRY_NOTIFICATION_TO` = `kpopsoft@gmail.com` |

`NEXT_PUBLIC_SITE_URL`도 없다 — 어드민 상세 링크에 쓴다.
없으면 `https://kpopsoft.com`으로 폴백하므로 필수는 아니다.

## 4. 문서도 같이 고친다

지금 문서는 **틀리지 않았지만 Resend를 가리킨다.**

| 파일 | 지금 | 어떻게 |
|---|---|---|
| `docs/06-admin/03-…:61` | "메일 서비스 필요(예: Resend), env `RESEND_API_KEY`" | **Cloudflare로 정정.** KPO-23 근거 명시 |
| `docs/06-admin/00-START-HERE.md:38` | "코드는 Resend로 구현됨" | 같이 정정 |
| `docs/07-dev/02-개발상태.md:99-100` | "실제 발송은 KEY 유무에 달림" | 조치 결과로 갱신 |
| `docs/06-admin/04-…:39` | 수신자 "발송 연동 시 결정" | **D3으로 확정** 반영 |
| `.env.example:53-54` | "전부 선택 사항이다" | 운영에서는 **필수**임을 명시 |

"선택 사항"은 **로컬 개발 기준**에서만 맞다. 운영에서 비면 기능이 죽는다.
그 구분이 지금 문장에 없다.

### 남은 것

4. **토큰에 `Email Sending: Edit`가 있는가** — 확인 못 했다.
   읽기용 엔드포인트가 없어 **실제로 한 통 보내야** 안다.
   없으면 대시보드에서 권한을 추가하거나 토큰을 다시 발급한다.

   없어 API로 확인 못 했다. **대시보드에서 눈으로 봐야 한다.**
   MX·SPF는 이미 서 있으므로([02](02-현황분석.md) §5) 규칙만 없을 수 있다.
6. **`resend` 의존성 제거** — `package.json`에 `resend@^6.17.2`가 있다.
   빼도 되는가? (다른 용도 계획이 있으면 남긴다)

### 토큰 취급

토큰은 `.env.local`에만 넣었다 — `.gitignore`의 `.env*`에 걸리고
git에 추적되지 않는 것을 확인했다. **문서·코드·로그·OpenProject에는 적지 않는다**
(설계 §7).

> ⚠️ 이 토큰은 채팅으로 평문 전달됐다. 배선이 끝나면 **재발급을 권한다.**
> 재발급 시 권한은 `Email Sending: Edit`만 준다.
