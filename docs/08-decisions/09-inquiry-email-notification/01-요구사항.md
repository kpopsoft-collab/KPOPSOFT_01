OpenProject [WP 258 "메일 발송불가함"](https://op.kpopsoft.com/work_packages/258)
— 2026-08-10 14:48 등록, 작성 권기영, 담당 안영근.
첨부 스크린샷은 폼의 **성공 화면**이다. 즉 신고 시점부터 이미
"화면은 성공인데 메일이 없다"가 증상이었다.

같은 날 14:46:17에 들어온 문의가 운영 DB에 남아 있다
([02](02-현황분석.md) §1) — 신고 2분 전. 같은 건이다.

## 기준 작업 — KPO-23

[KPO-23 "이메일 발송시스템 개발"](https://op.kpopsoft.com/work_packages/182)
(WP 182, 담당 오세승, 상태 **할일**, 시작 2026-07-12)이 이 영역의 기준 작업이다.
본문이 정한 범위는 두 줄이다.

- 이메일 **발송**
- 이메일 **수신**

즉 **수신도 범위에 들어 있다.** 관리자 알림만 보내면 끝이 아니다.

> 참고 — KPO-21 "문의 내용 메일로 수신 설정"은 Linear에서 **Canceled**다.
> 그 건을 되살리는 게 아니라 KPO-23이 대체한 것으로 본다.

## 승인된 설계

KPO-23 댓글(황정우, 2026-07-24)이 설계 확정을 공지했고, 본문은
`docs/superpowers/specs/2026-07-13-vercel-admin-platform-design.md`에 있다
(`origin/codex/kpopsoft-maxonomy-concept-wind` 브랜치).

그 문서 **§7 "Cloudflare 이메일"**이 이 작업의 직접 기준이다.

| | 확정 내용 |
|---|---|
| 방식 | 공식 `cloudflare` Node SDK의 `client.emailSending.send()` |
| 발신 | `inquiry@kpopsoft.com` |
| 수신 | **검증된** `kpopsoft@gmail.com` |
| 제목 | 문의 유형과 신청자 이름 포함 |
| 본문 | **HTML + 텍스트 대체본 둘 다** |
| 회신 | 유효한 이메일 연락처일 때만 `reply_to` |
| 상태 판정 | `message_id` · `delivered` · `queued` · `permanent_bounces` |
| 수신 경로 | Email Routing으로 `inquiry@kpopsoft.com` → `kpopsoft@gmail.com` |
| 비밀값 | 토큰·계정 ID를 코드·픽스처·로그에 남기지 않는다 |

§7이 명시적으로 **제외**한 것.

- **방문자 자동 접수확인 메일** — 임의 수신자 발송이라 무료 범위를 벗어난다
- 이번 범위는 검증된 `kpopsoft@gmail.com` 관리자 알림에 한정

## 무엇이 되어야 끝인가

1. 홈 Contact 폼에서 문의를 넣으면 **`kpopsoft@gmail.com`에 알림이 도착한다.**
2. `/education` 하단 교육 문의 폼도 같다. 두 폼은 같은 Server Action을 쓴다.
3. 메일에 유형·세부 유형·보낸 사람·연락처·접수 시각·본문이 다 있다.
4. **메일에서 바로 답장하면 문의자에게 간다.**
5. **`inquiry@kpopsoft.com`으로 온 메일이 Gmail로 전달된다.**
6. 메일이 **안 나갔을 때 그 사실을 알 수 있다.** 조용히 넘어가지 않는다.

## 기존 기준 문서가 이미 정해 둔 것

| 항목 | 어디서 | 내용 |
|---|---|---|
| 발송 시점 | `docs/06-admin/03-화면설계와-공개사이트-영향.md:47` | 저장 성공 직후 |
| 발송 실패 처리 | 같은 곳 | **저장은 성공 처리.** 알림은 부가 |
| 메일 내용 | 같은 곳 | 유형·세부 유형·발신자·연락처·내용 요약 + **어드민 상세 링크** |
| 수신자 기준 | `docs/06-admin/03…:61` | 설정값 / `admin_users` |

> ⚠️ `docs/06-admin/03…:61`은 메일 서비스를 **"예: Resend"**로 적어 뒀다.
> KPO-23 승인 설계가 이를 뒤집었다. 문서를 같이 고쳐야 한다
> ([03](03-원인과-결정.md) §4).

> ⚠️ 같은 문서가 요구한 **어드민 상세 링크**가 현재 `renderBody`에 없다.
> 이식할 `email-message.ts`에는 있다([02](02-현황분석.md) §6).
