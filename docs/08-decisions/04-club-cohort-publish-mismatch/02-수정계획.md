# 수정 계획

## 1. 두 방향

### 안 A — 앱에서 걷어낸다 (**권장**)

기수 타입·폼·토글에서 `isPublished`를 없앤다. 스키마 쪽 판단
([01](01-원인분석.md) §1의 RLS 주석)이 옳다고 보고 앱을 거기에 맞춘다.

| | |
|---|---|
| 장점 | DB 변경 없음(운영 DB를 안 건드린다). 기수를 숨기는 축이 `status` 하나로 정리된다. 실패하던 세 경로가 즉시 사라진다 |
| 단점 | `SupabaseRepo<T extends ContentBase>` 제약을 한 겹 풀어야 한다 |
| 부수효과 | 목록에서 공개 토글 UI가 빠진다 — **원래 동작한 적이 없는 버튼**이라 잃는 기능이 없다 |

### 안 B — DB에 컬럼을 추가한다

`alter table ... add column is_published boolean not null default true`.

| | |
|---|---|
| 장점 | 앱 코드를 안 고친다. 다른 테이블과 모양이 같아진다 |
| 단점 | **컬럼만 추가하면 토글이 거짓말이 된다.** 기수 RLS는 `using (true)`라 비공개로 바꿔도 공개 화면에 그대로 나온다(`..._p3_education_ver3.sql:299`). 진짜로 숨기려면 RLS 정책까지 published 그룹으로 옮겨야 하고, 그러면 `status='ended'`와 숨김 축이 **둘**이 된다 |
| 언제 | "기수를 임시로 감추고 싶다"는 실제 요구가 생겼을 때. 지금은 그 요구가 없다 |

**결론: A.** 없는 기능을 되살리는 게 아니라, **동작한 적 없는 UI를 걷어내는** 일이다.

## 2. 단계 (안 A 기준)

### 0) 실제 DB 확인 — 먼저 한다

[00-START-HERE.md](00-START-HERE.md)의 쿼리로 컬럼 유무를 본다.
**컬럼이 실재하면 이 계획을 버리고** 마이그레이션 파일에 컬럼을 되살리는
쪽으로 방향을 튼다(스키마 드리프트 복구).

### 1) 타입 — 공개 개념이 없는 베이스를 만든다

`src/lib/admin/content-types.ts`

```ts
/** 정렬만 갖는 콘텐츠. 공개/비공개 축이 없는 것들(기수)에 쓴다. */
export type OrderedBase = { id: string; sortOrder: number };
export type ContentBase = OrderedBase & { isPublished: boolean };

export type EducationClubCohort = OrderedBase & {   // ContentBase 아님
  label: string;
  status: ClubCohortStatus;
  // ... 나머지 그대로 ...
};
```

`status`가 숨김 축이라는 사실을 타입 옆 주석으로 남긴다 — 다음 사람이
`isPublished`를 다시 넣지 않게.

### 2) 리포지토리 제약 완화 — **안전함을 확인했다**

고칠 제약은 **네 곳뿐**이다.

| 파일:줄 | 선언 |
|---------|------|
| `content-data.ts:46` | `interface ContentRepo<T extends ContentBase>` |
| `content-data.ts:98` | `class MockRepo<T extends ContentBase>` |
| `supabase-content.ts:186` | `function fromRow<T extends ContentBase>` |
| `supabase-content.ts:205` | `class SupabaseRepo<T extends ContentBase>` |

이 넷이 base에서 **실제로 쓰는 값은 `id`와 `sortOrder`뿐이다.**
`list()`는 `sortOrder`로 정렬하고(`content-data.ts:105`, `supabase-content.ts:213`),
`create()`는 `id`·`sortOrder`를 채운다(`:112`, `:229`). `fromRow`/`toRow`는
`FIELDS` 테이블만 보고 돈다. **`isPublished`를 구조적으로 요구하는 코드는 없다.**

→ `ContentBase`를 `OrderedBase`로 낮춰도 나머지 11개 타입은 여전히
`ContentBase`(= `OrderedBase & { isPublished }`)라서 아무것도 잃지 않는다.



`src/lib/admin/supabase-content.ts` / `content-data.ts`

`SupabaseRepo<T extends ContentBase>` → `<T extends OrderedBase>`.
`MockRepo`도 같이 본다. **`COMMON`은 건드리지 않는다** — 나머지 11개 테이블이
쓰고 있고, 여기서 손대면 영향 범위가 전체로 번진다([01/06 §P1-4]
(../01-regular-class-schedule-and-html/06-교차검증-결과.md)와 같은 이유).

```ts
// FIELDS: 기수만 COMMON을 안 쓴다
const ORDER_ONLY: FieldMap = [["sortOrder", "sort_order"]];

education_club_cohorts: [
  ...ORDER_ONLY,        // ← is_published를 싣지 않는다. 컬럼이 없다
  ["label", "label"],
  // ... 그대로 ...
],
```

`PublishToggle` 컴포넌트 자체는 **지우지 않는다** — 다른 6개 교육 폼이 쓴다.

### 4) 목데이터

`mock-content.ts`의 `mockEducationClubCohorts`는 빈 배열이라 손댈 것이 없다.
다만 타입이 좁아지므로 `tsc`로 확인한다.

### 5) 마이그레이션 — 필요 없다

DB를 안 건드린다. 대신 `..._p3_education_ver3.sql:299`의 RLS 주석이 이미
이유를 적어 두고 있으므로 **거기에 링크만 남긴다**(코드 주석으로).

## 3. 검증

- [ ] `npx tsc --noEmit` 통과
- [ ] `npm run lint` — 변경 파일에서 신규 오류 0건
      (기존 7건은 별건. [01/06 §0](../01-regular-class-schedule-and-html/06-교차검증-결과.md))
**먼저 현재 행 수를 세어 둔다.** 이걸 안 하면 아래를 오독한다.

```sql
select count(*) from public.education_club_cohorts;
```

- [ ] **실제 Supabase 모드에서** 기수 추가 → 저장 성공
- [ ] 기수 수정 → 저장 성공, 값이 그대로 복원
- [ ] 목록에 공개 토글이 없다 (있는데 안 눌리는 상태가 아니라, 아예 없다)
- [ ] `/education` 바이브데이즈 모달이 **정상 렌더된다** (아래 주의 참고)
- [ ] 나머지 교육 폼 6종(정규 클래스/티어/지난 프로그램/후기/FAQ/성과)의
      **공개 토글이 여전히 동작한다** (`SupabaseRepo` 제네릭을 건드렸으므로 필수)

> **오독 주의 — "모달에 기수가 그대로 나온다"로 판정하면 안 된다.**
> 위 count가 **0이었다면** 공개 화면은 정적 4행 폴백을 보고 있던 것이다
> (`public-content.ts:276`). 그 상태에서 테스트 기수를 하나 추가하는 순간
> 폴백이 빠지고 **그 한 건만** 나온다. 이건 수정이 동작한다는 증거이지 회귀가
> 아니다. 판정 기준은 "4개가 그대로 보이는가"가 아니라
> **"DB에 넣은 것이 화면에 반영되는가"**다. ([01 §6](01-원인분석.md))
>
> count가 **0이 아니었다면**(시드 스크립트를 돌린 상태) 기존 기수에 테스트 기수가
> 더해져 보인다. 끝나고 테스트 행을 지운다.

> 마지막 체크 항목이 이 작업의 진짜 위험이다. 제네릭 완화가 다른 11개 테이블의
> `isPublished` 왕복을 건드리지 않았는지 확인해야 한다.

## 4. 순서

[01](../01-regular-class-schedule-and-html/00-START-HERE.md)과 **같은 파일을 만진다**
(`content-types.ts`, `supabase-content.ts`). 01이 정규 클래스 projection을 넣는
동안 여기서 `FIELDS`를 고치면 충돌한다.

→ **01을 끝낸 뒤에 착수한다.** 급하면 01의 5단계에 얹어도 되지만, 그러면 커밋이
"정규 클래스 폼"과 "기수 버그"로 섞인다.
