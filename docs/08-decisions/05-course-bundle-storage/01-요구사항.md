# 요구사항

## 1. 문제

교육 상세 자료가 **`index.html` 한 장으로 끝나지 않는다.** 이미지, 별도 CSS,
서브 HTML이 같이 온다. 현재 업로드 위젯은 `.html` 파일 **하나**만 받고
(`html-upload.tsx:42`), 저장 위치는 텍스트 컬럼(`detail_html`)이다.

이 구조에서 상대경로 참조는 **원리적으로 불가능하다.** `<img src="images/a.png">`
가 가리킬 `images/a.png`가 어디에도 존재하지 않는다. 정제기가 태그를 지우는
문제가 아니라, 가리킬 대상이 없는 것이다.

## 2. 어드민이 할 수 있어야 하는 것

| # | 요구 | 비고 |
|---|------|------|
| A1 | 정규 클래스 편집 화면에서 **zip 1개**를 골라 올린다 | 폴더 선택이 아니라 zip. 디자이너에게 zip으로 받는 게 현실 |
| A2 | 올리는 동안 진행 상황이 보인다 | 파일 수십 개를 개별 업로드한다 → "12 / 48" |
| A3 | 이미 올린 번들의 **파일명과 개수**가 보인다 | 다시 열었을 때 뭐가 올라가 있는지 알아야 한다 |
| A4 | 번들을 **제거**할 수 있다 | Storage 폴더도 같이 지워진다 |
| A5 | **이름만 고쳐 저장해도 번들이 남는다** | 결정기록 01 §3 5-1과 같은 함정. `BundleIntent`로 막는다 |
| A6 | 잘못된 zip은 **왜 안 되는지** 알려준다 | "index.html이 없어요" / "허용되지 않는 확장자: .exe" |

## 3. 방문자가 보는 것

정규 클래스 상세 페이지(`/education/programs/[slug]`)에 **링크 블록** 하나.

```
┌────────────────────────────────────────┐
│  과정 상세 자료                          │
│  이미지와 커리큘럼이 담긴 상세 페이지를    │
│  새 창에서 볼 수 있습니다.                │
│                                        │
│  [ 상세 자료 보기  ↗ ]                   │
└────────────────────────────────────────┘
```

- `target="_blank"` + `rel="noopener noreferrer"`
- **새 창에서 열린다는 것을 시각·스크린리더 양쪽에 알린다** (아이콘 + `aria-label`)
- 탭 타겟 44px 이상 (CLAUDE.md 접근성)
- 번들이 없으면 **블록 자체를 그리지 않는다**

### 3-1. 본문은 셋 중 하나다 (**2026-08-04 변경**)

처음에는 번들을 본문 **아래에 붙는 부가 자료**로 두고 기존 분기
(`detailHtml ?? curriculum`)를 건드리지 않을 계획이었다. 뒤집었다 —
**어드민이 "상세 본문" 방식을 택일로 고른다.** 두 위젯이 나란히 있으면 어느
쪽이 실제로 화면에 나오는지 어드민이 알 수 없기 때문이다.

그래서 상세 페이지 본문도 3분기가 된다.

| 상태 | 본문 자리에 그리는 것 |
|---|---|
| `detailHtml` 있음 | `CourseHtml` |
| `bundleUrl` 있음 | `ProgramBundleLink` — 새 탭 링크 블록 |
| 둘 다 없음 | `CurriculumTimeline` |

번들을 고르면 **본문이 곧 바깥 링크**가 된다. iframe을 버린 대가로 번들 내용은
검색에 색인되지 않으므로, 히어로·일정·이미지·CTA가 페이지를 지탱한다.

어드민 폼의 라디오가 유일한 진실이다. 둘이 동시에 채워지는 상태를 폼이 만들지
않지만, 만에 하나 그렇더라도 **HTML이 이긴다**(분기 순서).

## 4. `detail_html`은 어떻게 되는가 (D6)

**없애지 않는다.** 이유 두 가지.

1. 이미 저장된 데이터가 있을 수 있다. 렌더 경로를 지우면 그 과정 상세가 빈다
2. 렌더 직전 재정제(release gate G2)는 **그 데이터가 남아 있는 한 계속 필요하다**

대신 **어느 쪽을 쓰는지 폼에서 명시적으로 고르게** 한다(§3-1의 라디오).
"HTML 파일 1개" / "zip 번들 (여러 파일)" 중 하나이므로, 여러 파일이 필요하면
자연히 번들로 간다. 방식을 바꿔 저장하면 쓰지 않는 쪽은 지워진다 —
그래야 화면에 무엇이 나오는지가 폼과 일치한다.

> 결정기록 01에 들인 정제 파이프라인 상당 부분이 이 작업 이후 덜 쓰이게 된다.
> 그건 이 결정의 근거가 **아니다**(매몰비용). 근거는 §1 하나다.

## 5. 범위 밖

| 안 하는 것 | 이유 |
|---|---|
| 목록 카드에서 번들로 바로 보내기 | 카드 목적지는 slug 상세다(결정기록 02 D2). 흐름을 두 갈래로 만들지 않는다 |
| 번들 미리보기 | 결정기록 01 D9와 같은 이유 — 새 탭으로 열어 보면 그게 곧 실물이다 |
| 클럽·조직 교육 등 다른 콘텐츠 타입 | 정규 클래스 하나로 검증한 뒤에 판단한다 |
| 옛 번들 자동 정리(가비지 컬렉션) | §6 참조 — 알고 남기는 부채 |
| 별도 서브도메인(`course.kpopsoft.com`) | 필요해지면 그때. 지금은 supabase.co URL을 감수 → [03](03-보안판단.md) §2-2 |
| 서버 액션 `requireAdmin` | 결정기록 01 D7과 동일 — 별도 결정기록 |

## 6. 알고 남기는 부채

**업로드해 놓고 저장하지 않고 나가면 Storage에 고아 폴더가 남는다.**

`ImageUpload`가 이미 같은 부채를 갖고 있다 — 이미지를 바꿔도 옛 파일을
지우지 않는다(`image-upload.tsx:59` 부근에 삭제 호출이 없다). 이번에도 같은
선택을 하되, 차이가 하나 있다:

- **저장을 누른 교체·제거는 옛 폴더를 실제로 지운다** (A4). 번들은 파일
  수십 개라 방치하면 이미지 한 장과 비용이 다르다
- 저장하지 않고 이탈한 경우만 고아로 남는다

정리 스크립트는 별도 작업으로 남긴다. `detail_bundle_path`에 없는 폴더를
지우는 단순한 sweep이면 된다.
