## ⚠️ 먼저 알아야 할 것 — 로컬과 배포가 DB를 공유합니다

Supabase 프로젝트가 하나라, **DB를 고치면 그 즉시 www.kpopsoft.com에 반영됩니다.**
반면 이미지·코드는 배포되어야 반영됩니다. 이 시차 때문에 2026-07-31 배포 사이트
이미지가 전부 깨진 적이 있습니다(작업로그 참조).

- 콘텐츠성 DB 변경(포트폴리오·문의 유형·통계 수치·강사진)은 **곧 배포**입니다.
- 배포 순서: `브랜치 배포 → 이미지 확인 → DB 반영`
- 포트폴리오 반영은 `scripts/apply-work-content.cjs` 사용 (이미지 미배포 시 자동 중단)

### 목 모드로 저장 검증하기 — 운영에 행을 만들지 않고

어드민의 **저장 버튼을 실제로 눌러 봐야 할 때** 쓴다. 화면이 열리는 것과 저장되는
것은 다른 확인이라, 폼을 고쳤으면 저장까지 밟아야 한다.

`getContentData()`는 `NEXT_PUBLIC_SUPABASE_URL`과 `SUPABASE_SERVICE_ROLE_KEY`가
**둘 다** 있을 때만 Supabase를 본다(`src/lib/admin/content-data.ts`). **서비스 키
하나만** 비우면 인메모리 목 리포로 떨어진다. URL·anon 키는 남겨 둔다 —
`src/proxy.ts`가 그 둘을 non-null로 쓴다.

```
# .env.development.local  ← 임시 파일. 끝나면 지운다
SUPABASE_SERVICE_ROLE_KEY=
ADMIN_DEV_BYPASS=true
```

`.env.local`이 아니라 `.env.development.local`이다. Next가 이쪽을 **먼저** 읽고
먼저 잡힌 키를 뒤 파일이 덮지 않는다(`@next/env`). `.env.local`을 직접 고치면
되돌리는 걸 잊는다.

- **목 모드인지 확인** — 목록 행의 id가 `work_1` 꼴이면 목, uuid면 실제 DB다.
- **이미지 업로드는 이 우회를 안 탄다.** `ImageUpload`는 브라우저에서 Storage로
  바로 올리고, Storage도 로컬·운영이 한 프로젝트다. 업로드까지 밟아야 하면
  브라우저에서 그 요청을 가로챈다.
- 목 리포에 없는 것은 검증도 안 된다 — 정규 클래스의 동반 테이블(업로드 원본)은
  no-op이라 ["이름만 고쳐 저장해도 자료가 남는가"](../06-admin/07-과정-상세본문-HTML과-번들.md) §3-3은
  목 모드로 못 닫는다.

실례 — [../08-decisions/08-content-form-route-merge/06-구현결과.md](../08-decisions/08-content-form-route-merge/06-구현결과.md) §3-3.

## 현재 상태

- Next.js 16 App Router 기반. 작업 브랜치는 `redesign/ver2`, 배포 브랜치는 `main`.
- **ver3 개편 진행 중** — 홈 7섹션 / 교육 8섹션. 현행 기준은 `01-ia`,
  `02-home`, `03-education`이며 공통 규칙은 `04-design-system`과 `06-admin`에 통합했습니다.
- 공개 페이지 콘텐츠는 Supabase에서 읽고(`src/lib/public-content.ts`),
  `src/lib/site.ts`는 DB가 비었을 때의 **폴백 시드**입니다 — 시드만 고치면 화면은
  바뀌지 않습니다.
- 교육 페이지 콘텐츠는 **Supabase 스키마가 있습니다**(`20260802120000_p3_education_ver3.sql`).
  `src/lib/education-content.ts`는 조회 실패 시의 **폴백 시드**입니다.
  2026-08-03에 정규 클래스에 강의 일정·HTML 상세 본문이 추가됐습니다
  ([10-작업로그-2026-08-03.md](10-작업로그-2026-08-03.md)).
- **과정 상세 번들(zip)도 적용 완료입니다** (2026-08-04~05,
  [11-작업로그-2026-08-04.md](11-작업로그-2026-08-04.md)).
  `20260804090000_course_bundle_storage.sql`·`20260804120000_html_raw_size_limit.sql`이
  운영 DB에 들어갔고, 실제 데이터도 확인됩니다 — 2026-08-06 실측으로 `vibe-coding`·
  `ai-tools` 두 과정에 번들 폴더(`index.html`·`prompts.html`·`icons/` 6개)가 있고,
  `detail_html`은 4과정 모두 비어 있습니다(인라인 경로 폐지 완료).
  `automation`·`web-app`은 아직 자료가 없습니다.
  운영 기준은 [../06-admin/07-과정-상세본문-HTML과-번들.md](../06-admin/07-과정-상세본문-HTML과-번들.md).
  > 앞으로도 이 테이블에 컬럼을 더할 때는 순서가 `DDL 적용 → 확인 쿼리 → 배포`입니다.
  > 어드민 select 컬럼이 `FIELDS`에서 자동 파생돼, 컬럼 없는 DB에 코드가 먼저 가면
  > **어드민 목록이 500이 되고 저장이 실패**합니다. 공개 상세는 조용히 정적 폴백으로
  > 떨어져 옛 데이터가 그대로 보입니다 — 이쪽이 더 알아채기 어렵습니다.
- **`/education/programs` 목록·상세 공개 페이지가 나왔습니다**(2026-08-03).
  **상세 페이지는 2026-08-05에 다시 짰습니다** — breadcrumb, 비대칭 2단(본문 +
  sticky 요약 카드), 항상 보이는 커리큘럼, 다른 과정 3장, 모바일 하단 고정 CTA.
  기준은 [../03-education/13-공개-과정-상세페이지.md](../03-education/13-공개-과정-상세페이지.md).
  > ⚠️ **업로드 HTML을 페이지 안에 그리던 경로는 폐지됐습니다.** 정제가 `<script>`를
  > 지워 슬라이드 덱이 **29,435px짜리 빈 페이지**로 나오고 있었습니다. 그리고
  > **Supabase Storage가 HTML을 `text/plain`으로 내려서** 08-04에 올린 zip 번들도
  > 새 탭에서 소스 코드로 보이고 있었습니다. 지금은 `/course-assets/<uuid>/…`
  > 라우트가 Content-Type을 다시 붙이고 `CSP: sandbox`로 origin을 격리합니다.
  > 경위는 [13-작업로그-2026-08-05.md](13-작업로그-2026-08-05.md).
- **정적 데이터 → DB 반영은 시딩 스크립트로 합니다** — `scripts/seed-education-ver3.cjs`,
  `scripts/seed-home-pillars.cjs`. 둘 다 `--apply` 없이는 계획만 출력합니다.
  스크립트는 데이터를 복사해 두지 않고 `education-content.ts`·`pillar-examples.ts`를
  런타임에 읽습니다 — 두 벌로 갈라지면 어느 쪽이 진짜인지 알 수 없게 됩니다.
- 어드민 저장 시 공개 페이지 경로도 함께 `revalidatePath` 합니다 — 고친 것이 바로 보입니다.
- Final CTA 문의 폼은 Server Action(`src/lib/inquiry-actions.ts`)으로 접수하고,
  저장 직후 Cloudflare Email Service로 관리자 알림을 보냅니다(stub 아님).
  → [../06-admin/09-문의-알림-메일.md](../06-admin/09-문의-알림-메일.md)

- `npm run lint`는 **기존 에러 2건 때문에 실패합니다** — `src/components/layout/header.tsx`,
  `src/components/sections/education/vibedays-modal.tsx`. ver3 작업 이전부터 있던
  것으로 빌드에는 영향이 없습니다. (예전에 이 문서가 "lint 통과"로 적어 둔 것은
  사실과 달랐습니다 — 2026-08-05에 바로잡았습니다.)
