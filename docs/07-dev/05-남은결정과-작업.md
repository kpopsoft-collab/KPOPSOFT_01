## 남은 결정 · 작업

### 배포 전 반드시

> 아래는 2026-07-31 시점 **DB 실측** 기준이다.

- [x] ~~교육 세부 유형 마이그레이션~~ — 완료. 3분류 3개 활성, 옛 9개는
      삭제하지 않고 `is_active=false`.
- [ ] **`AI 솔루션 문의` 세부 유형에 `AI Prototype`이 아직 활성** — ver3에서
      AI 솔루션 목록의 `AI Prototype`을 빼기로 했는데 DB에는 그대로 켜져 있다.
      (`AI 에이전트 / 콘텐츠 자동화 / 사내 AI Tool`도 활성 — ver3 문서는 3개로
      줄이기로 했으나 유지 결정인지 미확인.)
- [ ] **강사진 `Prototype` 표기 제거** — ver3에서 폐지했으나 DB(`experts`) 3번째
      행에 `role: "Prototype & Vibe Coding"`, `tags: ["Prototype Development", ...]`이
      남아 있다. → `Vibe Coding`으로 정리.

> **유형 라벨은 ver2 유지가 결정 사항이다.** DB는 `프로젝트 문의 / AI 솔루션 문의 /
> 교육 문의`, `site.ts` 폴백 시드는 `소프트웨어 문의 / …`로 서로 다르다. 의도된
> 차이이므로 시드를 보고 DB가 틀렸다고 판단하지 말 것.

### 교육 페이지 — 콘텐츠 확인 필요 (2026-08-02)

- [ ] **교육 성과 `120+`** — 요청서 §6은 "교육 및 워크숍 진행"이라 하는데
      데이터는 `클럽 참가자`이고 코드에 `// 더미`가 붙어 있다. 실제 항목명과
      값 확인 필요. 교육 수료생은 이번 작업에서 `200+`로 수정됐고, 나머지는
      `4 / 96%`를 유지한다.
- [ ] **강사별 담당 프로그램** — `instructorPrograms`가 비어 있다.
- [ ] **교육 사례 5개 카테고리** — 기업교육 사례 / 정규 교육 사례 / 클럽 활동 /
      세미나 / 수강생 결과물. 자료가 모이면 두 줄 마키를 켠다.
- [ ] **후기 별점** — 실제 평점을 받을지, 별점 없이 갈지.
- [ ] **프로그램 카드 이미지 3장이 서로 비슷하다** — 전부 같은 강의실에서 찍혀
      세 카드가 한눈에 구분되지 않는다. 정규 클래스 4과정 카드에서 이미 나왔던
      문제와 같은 원인(보유 사진이 한 공간에 몰려 있음).

### 컨펌 대기

- [ ] 정규 클래스 4과정 **주차별 커리큘럼** — IA에 기간·난이도만 있어 초안을 작성했다.
      상세 페이지가 나왔으니(2026-08-03) 이제 화면에서 확인하며 확정할 수 있다.
      **2026-08-05부터 자료(zip/`.html`)를 올린 과정도 `curriculum`을 쓴다** —
      커리큘럼은 항상 보이므로 4과정 모두 확정이 필요하다.
- [ ] **상세 자료 핵심 회귀 테스트** (2026-08-05 위젯을 고쳤으므로 **다시** 봐야 한다)
      - [ ] 자료가 있는 과정을 열어 **이름만 고쳐 저장해도 자료가 남는지** (§3-3)
      - [ ] `.html` 한 장 업로드 → `education/<uuid>/index.html`로 올라가는지 (**신규 경로**)
      - [ ] `.zip` 업로드가 이전과 같은지 · `.txt` 등은 거부되는지
      UI 조작이라 스크립트로 대신할 수 없다.
      상세는 [../06-admin/07-과정-상세본문-HTML과-번들.md](../06-admin/07-과정-상세본문-HTML과-번들.md) §3-3.
- [ ] **`ai-tools` 상세 자료 재업로드** — 사진 5장이 404다. 이미지가 딸린 덱을
      `.html` 한 장으로 올려 `assets/`가 Storage에 없다. `assets/`까지 담은 zip으로
      다시 올리면 된다. **화면 버그가 아니다.**
- [ ] 정규 클래스 카드 **이미지** — 보유 사진이 모두 같은 강의실이라 4개 카드가 비슷해 보인다.
- [ ] 후기 1건 (위 §6 참조)

### 보류

- **Admin 연동** — 이번 범위 밖. 프론트 구조만 잡아 두었고, 갤러리(`image_urls`) 입력 UI도 없다.
- **오픈프로젝트 연동** — IA 주석의 "포트폴리오 발행 시 자동 업데이트". 연동 가능 여부 확인 전.

  읽는다. 기준은 [../03-education/13-공개-과정-상세페이지.md](../03-education/13-공개-과정-상세페이지.md).

  폐지돼 인라인 `<style>`을 허용할 이유가 같이 사라졌다. 남은 예외는 상세 자료
  라우트(`/course-assets/…`)뿐이고, 그쪽은 이미 자체 `CSP: sandbox`를 갖고 있다.
  → [12-작업로그-2026-08-05.md](12-작업로그-2026-08-05.md) §4

### 제거했지만 파일은 남긴 것

교육 6개 섹션(`visit-purpose` / `edu-outputs` / `how-we-learn` / `org-training` /
`edu-process` / `cta-split`)과 홈 `about-summary`는 **페이지에서 import만 끊었다.**
되돌리기 쉽고 diff가 작다. `education-content.ts` 하단의 `@deprecated` 블록이
이들을 위한 데이터다 — 지우면 타입 체크가 깨진다. 되살릴 계획이 없어지면 컴포넌트와
함께 정리한다.
