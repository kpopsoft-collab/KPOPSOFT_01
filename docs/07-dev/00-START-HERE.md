## ⚠️ 먼저 알아야 할 것 — 로컬과 배포가 DB를 공유한다

Supabase 프로젝트가 하나라 **DB를 고치면 그 즉시 www.kpopsoft.com에 반영된다.**
반면 이미지·코드는 배포되어야 반영된다. 이 시차 때문에 2026-07-31 배포 사이트
이미지가 전부 깨졌다.

```text
배포 순서:  브랜치 배포 → 이미지 확인 → DB 반영
```

포트폴리오 반영은 `scripts/apply-work-content.cjs`를 쓴다(이미지 미배포 시 자동 중단).
사고 경위는 [03-작업로그-2026-07-31.md](03-작업로그-2026-07-31.md) §4.

## 콘텐츠가 어디에 있나

| 대상 | 실제 출처 | 폴백 |
|------|----------|------|
| 홈 콘텐츠 (포트폴리오·통계·강사진·후기) | Supabase — `src/lib/public-content.ts` | `src/lib/site.ts` 시드 |
| 문의 유형·세부 유형 | Supabase `inquiry_types` / `inquiry_subtypes` | `src/lib/site.ts` (**DB와 값이 다름**) |
| 교육 콘텐츠 | 정적 `src/lib/education-content.ts` + 일부 DB | — |

**시드만 고치면 화면은 바뀌지 않는다.** 이유는
[../01-ia/04-홈-contact-DB-마이그레이션.md](../01-ia/04-홈-contact-DB-마이그레이션.md).

```bash
npm run lint     # 통과
npm run build    # 통과 (next build --webpack)
```

실패한다. 그래서 `npm run build`가 Webpack 빌드를 쓰도록 맞춰져 있다.

## 작업 로그를 쓰는 이유

이 폴더의 작업 로그는 "무엇을 했나"가 아니라 **"왜 그렇게 판단했나"**를 남긴다.
요청서끼리 충돌했을 때 어느 쪽을 택했는지, 만들었다가 되돌린 것이 무엇인지,
지어내지 않고 비워 둔 콘텐츠가 무엇인지가 여기 있다. 새 작업 전에
[04-작업로그-2026-08-02.md](04-작업로그-2026-08-02.md)와
[05-남은결정과-작업.md](05-남은결정과-작업.md)를 읽으면 같은 논의를 반복하지 않는다.
