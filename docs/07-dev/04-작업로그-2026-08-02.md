## 2026-08-02 — 교육 페이지 수정 요청서 반영

기준: `KPOPSOFT_education_page_revision_request.md`. 브랜치 `redesign/ver2`.

### 착수 전 확정한 것 (사용자 결정)

| 쟁점 | 결정 |
|---|---|
| 목적 3축 vs 프로그램 3분류 | **명칭 통일하지 않는다.** 목적은 탐색 장치, 3분류는 상품 체계 |
| 헤더 | 전역 4메뉴 유지 + 교육 전용 서브바 신설 (역할 분리) |
| 상세 페이지 2개 | 이번 범위 제외 |

### 목적 선택 ↔ 프로그램을 어떻게 이었나

요청서는 "앵커 이동만 하지 말고 연결된 항목이 활성화되도록" 요구한다. 두 섹션이
형제라 props로는 안 이어지고, URL 쿼리로 두면 목적을 고를 때마다 뒤로가기 기록이
쌓여 브라우저 뒤로가기가 "이전 화면"이 아니라 "이전 필터"가 된다. 그래서 페이지
안에서만 사는 컨텍스트(`explore-context.tsx`)로 뒀다.

`AI 입문`과 `실무 활용`이 같은 정규 클래스로 가는 문제는 **정렬**로 풀었다.
`RegularClass.tracks`를 새로 두고 선택한 트랙의 과정을 앞으로 보낸다 —
거르지는 않는다. 4과정뿐이라 한 화면에 다 들어오고, 감추면 "고른 것 말고는
없다"는 인상만 남는다. `level`(자유 문자열)과 별개 필드인 이유는 level에
"비개발자 환영" 같은 난이도가 아닌 값이 들어오기 때문이다 — 코드가 분기에
쓸 축을 표기와 섞으면 문구를 다듬을 때 동작이 따라 깨진다.

### 프로그램 — Sticky Scroll을 만들었다가 3열 카드로 되돌렸다

요청서 §7이 지정한 Sticky Scroll(왼쪽 스크롤 / 오른쪽 패널 교체)을 구현했는데
사용자가 "한눈에 안 들어오고, 스크롤에 따라 오른쪽이 바뀌는 게 좋지 않다"고
판단해 **3열 카드 병렬**로 교체했다.

붙여 보고 드러난 문제 둘.
- "목적에 맞는 프로그램을 선택하세요"라는 제목이 요구하는 건 몰입이 아니라
  **비교**다. 비교하려면 셋이 동시에 보여야 하는데 sticky는 하나씩만 보여준다.
- 오른쪽 패널이 스크롤에 따라 저절로 바뀌어서, 방금 읽던 정보가 조금만
  움직여도 사라졌다. 사용자가 요청하지 않은 변화라 통제감이 없다.

교체하면서 자동으로 바뀌는 것을 전부 없앴다. 카드 한 장에 사진·설명·대상·
방식·결과물·CTA가 다 들어가 그 자체로 완결된다. 데스크톱 3열 → 태블릿 2열 →
모바일 1열로 접히므로 **모바일 전용 마크업이 없어졌다**(sticky 구조에서는
데스크톱과 모바일 마크업을 따로 썼다).

목적 선택 연동은 유지된다 — 해당 카드에 테두리·`찾으시는 교육` 배지·Primary
CTA를 얹고, 정규 과정 칩은 트랙 순서로 재정렬한다.

### 지어내지 않은 것

- **별점 제거.** 후기 본문은 수강생이 커뮤니티에 남긴 실제 글이지만, 다섯 건에
  붙어 있던 5점은 작성자가 매긴 값이 아니라 우리가 채운 값이었다. 근거 없는
  만점 평균은 신뢰를 주기는커녕 후기 전체를 의심하게 만든다(요청서 §11).
  `rating` 필드는 남겼다 — 실제 평점을 수집하면 다시 읽으면 된다.
- **강사 담당 프로그램.** 요청서 §10 카드 정보지만 누가 어느 과정을 맡는지
  확인된 자료가 없다. `instructorPrograms`를 빈 맵으로 두고, 비면 그 줄을
  그리지 않게 했다.
- **교육 사례 6개 카테고리.** 실제 자료는 지난 프로그램 3건뿐이다. 두 줄 마키는
  카드가 쌓였을 때 의미가 있고, 3건으로 돌리면 같은 카드가 반복해 지나가며
  사례가 적다는 사실만 강조된다. 섹션 자리와 카테고리 축만 잡아 뒀다.
- **CTA 라벨.** 요청서의 `기업교육 자세히 보기` / `정규 과정 보기`는 상세
  페이지를 전제한 문구다. 페이지가 없는 상태에서 그대로 쓰면 클릭하기 전까지
  알 수 없는 거짓말이 되므로, 지금 실제로 할 수 있는 행동(문의)으로 보냈다.

### 검증

`npm run build` 통과. `npm run lint`는 8건 실패하는데 **전부 이번 작업 이전부터
있던 것**이다(header / vibedays-modal / why-kpopsoft / apply-work-content.cjs).
이번에 추가한 파일은 lint 깨끗하다.

Playwright로 확인: 목적 클릭 시 정렬·스크롤 동작, 강사 3·FAQ 8·별점 0,
1440/390 렌더. 전체 페이지 스크린샷이 비어 보이는 건 `globals.css`의
스크롤 기반 reveal(`animation-timeline: view()`) 때문이지 버그가 아니다.

## 2026-08-02 — WHY KPOPSOFT 개편

기준: `KPOPSOFT_why_section_revision_request.md`(원래 파일명 `신규수정사항`,
확장자를 붙여 `docs/`에 정리했다).

### 섹션이 포트폴리오 앞으로 갔다

포트폴리오 **뒤**에 있던 것을 핵심 비즈니스와 포트폴리오 **사이**로 옮겼다(§1).
증명(사례)을 먼저 보여준 뒤에 이유를 설명하던 거꾸로 된 흐름이었다. 지금은
`무엇을 제공하는가 → 왜 우리인가 → 실제로 어떤 결과를 만들었는가` 순이다.

### 레이더 5축을 갈아엎은 이유

이전 축 `Strategy · Design · Technology · AI · Education`은 핵심 비즈니스
섹션이 이미 말하는 **서비스 분야의 나열**이었다. 바로 위 섹션과 같은 내용을
도형으로 한 번 더 보여주는 셈이라 이 섹션이 따로 있을 이유가 약했다.
새 축(`통합 실행력 / 기술 구현력 / 맞춤 설계 / 현업 적용성 / 지속 운영`)은
분야가 아니라 **고객이 우리를 고르는 기준**이다.

### 요청서 §5 ↔ §7 충돌은 이렇게 처리했다

- §5 — "점수·수치 표시 금지, 정량 비교처럼 보이지 않게"
- §7 — "카드 활성화 시 레이더 **형태**가 해당 역량에 맞게 변경"

형태가 바뀌면 축마다 값이 다르다는 뜻이라 둘은 그대로는 양립하지 않는다.
사용자가 "신경쓰지 말고 예쁘게"로 판단을 위임해서 이렇게 절충했다.

- **기본 상태는 정오각형.** 가만히 두면 어느 축도 더 길지 않다. 눈금·숫자는
  어디에도 없다.
- **카드를 고르면 관련 두 축이 함께 뻗는다.** 축 하나만 늘리면 오각형이
  한쪽으로 뾰족해져 "이것만 잘한다"로 읽히지만, 두 축이 짝으로 움직이면
  역량이 함께 작동한다는 인상이 된다. §6 매핑표가 애초에 카드마다 축을 둘씩
  지정한 것도 같은 맥락으로 읽었다.
- `현업 적용성`은 카드 02·03이 공유한다. 겹친 게 아니라 "직접 만들어 봤다"와
  "쓰이게 만든다"가 만나는 지점이라 그렇다.

### 안 한 것

**스크롤 기반 카드 자동 활성화**(§7 "01 → 02 → 03 순차 활성화")는 넣지 않았다.
§7 자신이 "구성할 수 있습니다"라고 선택지로 뒀고, 모바일에서는 레이더가 카드
위에 있어 카드가 화면 중앙에 올 때쯤 레이더가 이미 화면 밖이라 바뀌는 것을
볼 수 없다. 데스크톱만 되는 인터랙션을 위해 스크롤을 붙잡는 건 §7의 "스크롤을
과도하게 고정하지 말 것"과도 어긋난다.

### 덤

`why-kpopsoft.tsx`에 있던 lint 오류(렌더 중 ref 쓰기)를 함께 고쳤다 —
`selectedRef` 동기화를 effect로 옮겼다. 남은 lint 실패는 7건.
