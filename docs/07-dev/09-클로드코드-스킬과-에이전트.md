**2026-08-02 기준 스냅샷이다.** 스킬은 저장소가 아니라 사용자 계정·플러그인 설정에도
얹히기 때문에, 팀원마다 보이는 목록이 다를 수 있다. 실제로 지금 무엇이 붙어 있는지는
세션에서 `/help` 또는 "지금 쓸 수 있는 스킬 알려줘"로 확인한다. 이 문서는 **카탈로그**이고,
"왜 이렇게 구성했나"는 이 폴더의 작업 로그에 남긴다.

---

## 1. 한 줄 요약

이 저장소에는 **커밋된 스킬(`.claude/skills/`)이 없다.** 실제로 이 프로젝트를 굴리는 것은
저장소에 커밋된 **커맨드 1개 · 서브에이전트 4개 · MCP 3개**, 그리고 저장소 밖 사용자 머신에
있는 **개인 스킬 `deploy`** 다.

```text
저장소 안 (팀 공유)   .claude/commands/dev.md · .claude/agents/*.md · .mcp.json · .codex/*
저장소 밖 (내 머신)   ~/.claude/skills/deploy/SKILL.md
```

## 2. 스코프별 현황

스킬은 아래 네 위치 중 하나에 놓인다. 이름이 겹치면 **enterprise > personal > project > 기본
제공** 순으로 이긴다. 플러그인 스킬은 `플러그인명:스킬명` 네임스페이스라 충돌하지 않는다.

| 스코프 | 경로 | 적용 범위 | 이 프로젝트 상태 |
|--------|------|----------|-----------------|
| Personal | `~/.claude/skills/<name>/SKILL.md` | 내 모든 프로젝트 | **`deploy` 1개** — 저장소엔 없음 |
| Project | `.claude/skills/<name>/SKILL.md` | 이 프로젝트만 | **없음** (아직 미사용) |
| Project (구 방식) | `.claude/commands/<name>.md` | 이 프로젝트만 | **`/dev` 1개** |
| Plugin | `<plugin>/skills/<name>/SKILL.md` | 플러그인 켠 곳 | **없음** — `claude-hud`가 설치돼 있으나 다른 프로젝트 스코프 |
| 기본 제공 | Claude Code 내장 | 전역 | 버전따라 다름. `/help`로 확인 |

> `.claude/commands/*.md`는 스킬 이전 방식이지만 지금도 동일하게 동작한다. 같은 이름의
> 커맨드와 스킬이 동시에 있으면 스킬이 이긴다.

## 3. 스킬 목록

| 스킬 | 스코프 | 발동 | 파일 | 무엇을 하나 | 트리거 |
|------|--------|------|------|------------|--------|
| `deploy` | Personal | 자동 + `/deploy` | `~/.claude/skills/deploy/SKILL.md` | 변경을 **기능 단위로 쪼개 커밋**하고 푸시. 커밋 전 lint/build 검증, Conventional Commits 접두사 + 한글 메시지, 서브 브랜치면 PR·자동 머지까지 | "커밋하고 푸시", "commit and push", "변경사항 올려줘" 등 |

`deploy`가 이 저장소의 커밋 규칙(`fix(seo): ...`, `feat(admin): ...` 형태 + 한글 요약)을
그대로 지켜 준다. **`main` 브랜치에서는 푸시 전에 반드시 사용자 확인을 받는다.**

> ⚠️ `deploy`는 개인 스킬이라 **저장소를 클론한 팀원에게는 없다.** 팀 전체가 같은 규칙으로
> 커밋하게 하려면 `.claude/skills/deploy/SKILL.md`로 옮겨 커밋해야 한다.

## 4. 프로젝트 전용 커맨드 — `/dev`

`.claude/commands/dev.md`. 기능 개발·수정의 **정식 진입점**이다. 하는 일:

1. `CLAUDE.md` → `docs/00-START-HERE.md` → 주제 폴더의 `00-START-HERE.md` 순으로 컨텍스트 확보
2. 요청에 맞는 서브에이전트를 골라 위임 (독립 작업이면 병렬)
3. API가 불확실하면 기억 대신 `context7` MCP
4. UI 변경이면 `playwright` MCP로 375 / 768 / 1440px 세 폭 실제 렌더링 확인
5. 무엇을 바꿨고 어떤 에이전트·MCP를 썼는지 요약 보고

범위가 모호하면 에이전트를 돌리지 않고 먼저 되묻는다.

## 8. 자주 쓰는 조합

```text
화면 작업   /dev → nextjs-frontend → design-reviewer → qa-e2e → deploy
DB·인증     /dev → supabase-backend (+ supabase MCP) → qa-e2e → deploy
문서만 수정  (에이전트 없이 직접) → deploy   ※ 문서만 바뀌면 검증 단계는 건너뛴다
```

## 9. 스킬이 동작하는 방식 (요약)

- **점진적 로드** — 세션 시작 시 컨텍스트에 올라가는 건 각 스킬의 `description`(과
  `when_to_use`)뿐이다. 본문은 실제로 호출될 때만 읽힌다. 그래서 `description`에
  **트리거 문구를 구체적으로** 써야 자동 발동이 걸린다. `deploy`가 "커밋하고 푸시",
  "commit and push"까지 나열해 둔 이유다.
- **자동 발동 vs 수동 호출** — 기본은 둘 다 된다. `disable-model-invocation: true`면
  `/이름`으로만, `user-invocable: false`면 모델만 참조한다.
- **SKILL.md는 짧게** — 개요·라우팅만 담고 긴 내용은 같은 폴더의 `references/`,
  `scripts/`로 뺀다. 문서 200줄 규칙과 같은 이유다.
- 주요 frontmatter 필드: `name`, `description`, `when_to_use`, `allowed-tools`,
  `disallowed-tools`, `model`, `disable-model-invocation`, `user-invocable`, `paths`.
  전체 목록은 [공식 문서](https://code.claude.com/docs/en/skills.md).

## 10. 새로 추가할 때

1. 프로젝트 전용 스킬이면 `.claude/skills/<이름>/SKILL.md`를 만들고 **커밋한다**
   (개인 스킬 `~/.claude/skills/`는 팀에 공유되지 않는다).
2. `description`에 사용자가 실제로 쓸 법한 트리거 문구를 한글·영어로 같이 적는다.
3. 서브에이전트를 늘리면 `.claude/agents/`와 `.codex/agents/`를 **함께** 고치고,
   `/dev` 커맨드의 위임 목록에도 추가한다.
4. 이 문서의 표에 행을 추가한다. 200줄을 넘기면 "스킬"과 "에이전트·MCP"로 쪼개고
   [00-START-HERE.md](00-START-HERE.md)의 목록과 앞뒤 링크를 같이 고친다.
