## 1. 시작 — "페이지 구성이 이상하고 HTML이 안에 들어가 있다"

`ai-tools` 상세를 브라우저에서 그대로 잰 값이다.

```js
{ docHeight: 29435, shellHeight: 27046.5, shellWidth: 768,
  slideCount: 25, hiddenSlides: 24,
  scriptTags: 0, totalImgs: 5, brokenImgs: 5 }
```

업로드물이 1920×1080 **슬라이드 덱**인데, `.slide`가
`visibility:hidden; opacity:0`이고 `.slide.visible`을 **JS가** 붙이는 구조였다.
정제기가 `<script>`를 전부 지워서(`scriptTags: 0`) 아무도 `.visible`을 안 붙였다.
**높이는 남으므로** 27,000px짜리 빈 기둥이 됐다.

## 2. 첫 번째 판단 — 인라인 렌더링에는 고칠 지점이 없다

| 정제기가 지우는 것 | 문서 한 장에는 무엇이었나 | 되살릴 수 있나 |
|---|---|---|
| `<script>` | 슬라이드를 드러내는 코드 | ❌ 살리면 정제가 무의미 |
| `media`·`supports` 외 at-rule | `@keyframes`·`@font-face` | ❌ 같은 이유 |
| `position` 선언 | 슬라이드 레이아웃 | ❌ 같은 이유 |

셋 다 **"정제된 조각을 우리 페이지에 심는다"는 전제 자체**에서 나온다.
정제기는 설계대로 동작하고 있었다 — 틀린 것은 전제였다.

> 어드민 기준 문서([../06-admin/07](../06-admin/07-과정-상세본문-HTML과-번들.md) §1)는
> 처음부터 *"이미지·CSS가 딸린 자료는 zip을 쓴다"* 고 적어 뒀다. 문서가 옳았고,
> **틀린 입력을 막지 못한 화면 쪽이 문제였다.**

## 3. 두 번째 판단 — 어제 만든 번들도 깨져 있었다

`.html`을 Storage로 옮겨 새 탭으로 열기로 하고 백필까지 끝낸 뒤, **URL을 실제로
열어 봤다.** 소스 코드가 떴다.

```
stored mimetype: text/html      served Content-Type: text/plain
document.contentType: "text/plain"   slides: 0
```

**Supabase Storage는 HTML을 의도적으로 `text/plain`으로 내려준다.** 남용·피싱
신고 대응을 위한 플랫폼 정책이고 버킷 설정으로 못 바꾼다
([supabase#7424](https://github.com/supabase/supabase/issues/7424)).

**그래서 08-04에 올린 `vibe-coding` 번들도 같은 이유로 계속 깨져 있었다.**
결정기록 05가 "해소됐다"고 적은 리스크("Storage가 공개 `.html`을 그려 주는가")는
실제로는 **파일이 올라갔다**는 것까지만 확인한 것이었다.

> **교훈 — "파일이 올라갔다"를 "화면이 나온다"의 증거로 쓰지 않는다.**
> 링크를 만들었으면 그 링크를 연다.

## 4. 세 번째 판단 — 결정기록 05 D4(프록시 금지)를 뒤집었다

D4의 전제는 **Storage가 격리된 origin으로 동작한다**였다. §3에서 무너졌다.
그리고 대안이 없었다 — 서브도메인·다른 호스트는 결정기록 05 D1이 이미 버렸고,
어디로 옮기든 `text/plain` 문제는 그 앞단에서 똑같이 풀어야 한다.

그래서 `/course-assets/<uuid>/<path>` 라우트를 만들어 Storage에서 가져와
**Content-Type만 다시 붙여** 내보낸다.

D4가 지키려던 것(업로드된 JS가 앱 origin의 세션에 닿지 못하게)은
**`Content-Security-Policy: sandbox`** 가 지킨다 — `allow-same-origin`을 주지
않으면 문서가 불투명 origin이 된다. 실측:

```
window.origin            "null"
localStorage             예외로 차단
document.cookie          예외로 차단
document.contentType     "text/html"     슬라이드 25장 렌더
```

착수 때 이 안을 버린 이유가 *"헤더 한 줄에 origin 격리를 통째로 의존한다"* 였다.
그 우려는 유효해서 **헤더 하나에만 걸지 않았다** — `<uuid>/` 모양 강제,
DB에 등록된 경로만 허용, 확장자 허용목록, `nosniff`, `noindex`까지 5층이다.
미등록 UUID·`.exe`·경로 순회 전부 404를 확인했다.

## 5. 화면을 다시 짠 근거

조사는 [결정기록 06 02](../08-decisions/06-course-detail-page-redesign/02-조사-상세페이지-구조.md)에 있다.
채택한 것과 **채택하지 않은 것**이 같이 중요하다.

- **커리큘럼을 항상 그린다** — 조사에서 가장 반복된 것이 "커리큘럼을 충분히
  보여야 결정이 난다"였다. 우리는 정반대로 업로드가 있으면 지우고 있었다.
- **sticky 요약 카드** — 기간·난이도·일정이 히어로에만 있어 스크롤하면 사라졌다.
- **breadcrumb + 다른 과정** — 막다른 길이었다.
- **가격·평점·강사 프로필은 안 만들었다** — DB에 없다. **없는 데이터를 지어내지
  않는다.** 후기는 `EduReview.program`이 자유 문자열이라 이 과정 것이라 판단할
  기준이 없어 계속 만들지 않는다(08-03과 같은 판단).

작업 중 히어로와 본문이 `description`을 **둘 다** 그리는 것을 발견해 히어로에서 뺐다.

## 6. 운영 데이터 변경

`scripts/backfill-detail-html-to-bundle.cjs --apply` 실행. `ai-tools` 1행이
Storage로 옮겨졌다(원본 50,488B). `detail_html`은 비웠고 **동반 테이블의 원본은
그대로 남아 있다** — `--rollback`으로 되돌릴 수 있다.

> 이 백필은 **화면 코드가 배포되기 전에 실행해도 안전했다.** 옛 코드의 분기
> 순서가 `detailHtml → bundleUrl → curriculum`이라, `detail_html`이 비면 구
> 코드도 번들 링크로 떨어진다. 라이브는 "빈 29,000px" → "동작하는 링크"로
> 좋아지기만 한다. 순서를 확인하지 않았다면 **본문이 사라진 화면이 나갔을 것**이다.

## 8. 남긴 것과 남은 것

**남긴 것** — `detail_html` 컬럼·`course-html.tsx`·`html-upload.tsx`·`sanitize-html.ts`.
백필을 되돌릴 여지를 남기려고 **일부러 안 지웠다.** 화면은 더 이상 읽지 않는다.

**남은 것**

1. **어드민 회귀 4건** — UI 조작이라 스크립트로 대신할 수 없다. 특히
   *번들 있는 과정을 이름만 고쳐 저장해도 자료가 남는가.*
2. **`ai-tools` 자료 재업로드** — 사진 5장이 여전히 404다. `.html` 한 장으로
   올려서 `assets/`가 Storage에 없다. **화면 버그가 아니라 콘텐츠 입력 문제다.**
3. **CSP 검토(G6)** — 인라인 렌더링이 사라져 인라인 `<style>`을 허용할 이유도
   같이 없어졌다. **지금이 닫기 가장 쉬운 시점이다.**

> **후속 (2026-08-06)** — 3은 같은 날 Report-Only로 적용됐고 확인 체크리스트
> 8개도 통과했다([14-CSP-정책과-적용.md](14-CSP-정책과-적용.md)). 2도 `icons/`를
> 담은 zip 재업로드로 해소됐다(404 5건 → 전부 `200`). **1만 남았다** —
> 그중에서도 *이름만 고쳐 저장해도 자료가 남는가* 한 줄이다.
