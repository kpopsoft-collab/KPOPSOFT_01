## 10. 핵심 사용자 흐름

```text
KPOPSOFT가 무엇을 만드는지 이해
↓
회사의 방향과 경험 확인
↓
실제 프로젝트 사례 확인
↓
제작 가능한 영역 확인
↓
프로젝트 의뢰
```

---

## 11. 구현 완료 조건

- 홈의 전체 섹션이 7개 안팎으로 압축되어 있다.
- Hero CTA는 `프로젝트 의뢰하기` 하나를 중심으로 사용한다.
- Hero 바로 아래에 짧은 About + Numbers가 배치된다.
- 실제 Work 사례가 상단에서 이미지 중심으로 노출된다.
- 사례 카드 전체를 클릭할 수 있다.
- 사례 보기 CTA 버튼을 반복하지 않는다.
- Software와 AI Solutions가 하나의 What We Do 섹션에 통합된다.
- Education 상세 콘텐츠는 제거되고 배너만 남는다.
- Desktop, Tablet, Mobile에서 정상 작동한다.
- 기존 Admin 데이터를 재사용한다.
- 프로젝트 노출 순서와 레이아웃 유형을 Admin에서 관리할 수 있다.
- 실제 이미지가 없을 때 브랜드 Placeholder가 표시된다.
- 기존 기능과 Education 페이지가 깨지지 않는다.

## 12. Claude Code 실행 요청

현재 KPOPSOFT 프로젝트를 먼저 분석한 뒤 위 기획안에 따라 홈 랜딩페이지를 개편해 주세요.

구현 전 다음 항목을 먼저 정리해 주세요.

1. 현재 기술 스택
2. 홈 페이지와 섹션 컴포넌트 구조
3. 기존 Header 및 Footer
4. 기존 Work 데이터 구조
5. 기존 Admin 구조
6. 재사용 가능한 컴포넌트
7. 제거 또는 이동할 Education 콘텐츠
8. 새로 생성할 파일
9. 수정할 파일
10. 데이터 모델 변경 여부
11. 기존 기능에 영향을 줄 수 있는 위험 요소

중요 요구사항:

1. 기존 디자인 시스템과 공통 컴포넌트를 최대한 재사용합니다.
2. 홈은 제작 사례와 프로젝트 의뢰 중심으로 개편합니다.
3. Hero CTA는 `프로젝트 의뢰하기`로 통일합니다.
4. 사례 보기 CTA를 추가하지 말고 실제 Work 카드를 직접 노출합니다.
5. 모든 Work 카드를 동일한 레이아웃으로 만들지 않습니다.
6. About + Numbers는 Hero 다음에 짧게 배치합니다.
7. Software와 AI Solutions를 What We Do 섹션으로 통합합니다.
8. Education은 별도 페이지로 연결되는 배너만 유지합니다.
9. 기존 프로젝트 데이터를 중복 등록하지 않습니다.
10. Admin에서 홈 노출, 대표 사례, 정렬 순서, 레이아웃 유형을 관리할 수 있도록 합니다.
11. 모바일 우선 반응형, 접근성, 이미지 최적화, 빈 데이터 상태를 포함합니다.
12. 기존 홈페이지와 `/education` 페이지 기능을 깨뜨리지 않습니다.
