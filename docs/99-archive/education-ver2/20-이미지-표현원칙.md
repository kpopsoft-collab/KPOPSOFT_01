## 23. 카드와 리스트의 이미지 표현 원칙

Education 페이지의 프로그램 카드, 교육 결과물, 교육 사례 리스트는 텍스트만으로 구성하지 않습니다.

이미지는 단순 장식이 아니라 방문자가 프로그램의 성격과 결과를 빠르게 이해하기 위한 핵심 정보입니다.

### 정보 우선순위

```text
이미지
→ 프로그램 또는 사례명
→ 무엇을 배우거나 만들었는지
→ 대상과 교육 형태
→ 결과
→ 상세 보기 CTA
```

태그, 난이도, 교육 시간 등의 부가 정보가 이미지와 제목보다 먼저 보이지 않도록 합니다.

### 이미지 캡션

이미지가 무엇인지 설명하는 짧은 캡션을 지원합니다.

예:

```text
AI Prototype Lab 과정에서 제작한 서비스 예약 프로토타입
```

```text
운영팀이 직접 설계한 반복 보고서 자동화 Workflow
```

캡션은 프로그램 제목을 단순 반복하지 않습니다.

## 24. 이미지 보안 및 공개 설정

기업 교육 사례에는 공개할 수 없는 이미지가 있을 수 있으므로 이미지별 공개 설정을 지원합니다.

권장 필드:

```ts
isPublic: boolean
isBlurred: boolean
isFeatured: boolean
displayOrder: number
altText: string
caption?: string
```

이미지 공개가 어렵지만 사례 자체는 공개 가능한 경우:

- 화면 일부 Blur
- 기업 로고와 개인정보 제거
- 재구성한 Mockup 사용
- 익명 산업군 표기
- KPOPSOFT 기본 그래픽으로 대체

실제 고객 이미지나 내부 자료를 허가 없이 공개하지 않습니다.

## 25. 이미지 없는 상태

이미지가 없어도 레이아웃이 깨지지 않아야 합니다.

이미지 우선순위:

```text
등록된 대표 이미지
→ 등록된 결과물 이미지
→ 등록된 교육 현장 이미지
→ 프로그램 또는 카테고리 기본 그래픽
→ KPOPSOFT 공통 Placeholder
```

Placeholder는 다음 요소를 조합합니다.

- 원
- 별
- 물결
- 프로그램명 첫 글자
- 감성 라벨
- 단순한 코드와 커서 그래픽

최종 화면에 단순 회색 박스를 표시하지 않습니다.

---

## 26. 이미지 성능 요구사항

- 기존 이미지 최적화 컴포넌트 재사용
- responsive `sizes` 지정
- 화면 밖 이미지는 lazy loading
- Hero 또는 첫 대표 이미지만 우선 로딩
- `aspect-ratio` 지정
- Layout Shift 방지
- 지나치게 큰 원본 업로드 시 최적화
- WebP 또는 AVIF 지원 여부 검토
- 썸네일과 원본 이미지 구분
- 모든 이미지에 alt 필수
