# 검증 체크리스트

리팩터링이므로 **"바뀐 게 없어야 한다"**를 확인하는 것이 핵심이다.

## 1. 라우트

- [ ] `/admin/content/education/regular-classes/new` 200
- [ ] `/admin/content/education/regular-classes/<실제 id>` 200
- [ ] `/admin/content/education/regular-classes/없는-id` → **404**
- [ ] 목록 페이지 `정규 클래스 추가` 버튼 → 추가 화면
- [ ] 목록 페이지 연필(EditLink) → 수정 화면
- [ ] 브레드크럼 `정규 클래스` → 목록으로 복귀 (양쪽 화면 모두)

## 2. 화면

- [ ] 추가 화면 제목: `정규 클래스 추가`
- [ ] 수정 화면 제목: `정규 클래스 수정`
- [ ] **추가 화면에 삭제 버튼이 없다**
- [ ] 두 화면의 여백·정렬·최대폭이 리팩터링 전과 같다
      (변경 전 스크린샷과 비교 — playwright MCP)
- [ ] 폼 필드 순서와 개수가 그대로다

## 3. 동작

- [ ] 추가 → 필수값(과정명·슬러그) 입력 → 저장 → 목록에 새 행
- [ ] 필수값 비우면 저장 버튼 비활성
- [ ] 수정 → 값 변경 → 저장 → 목록에 반영
- [ ] 수정 화면을 열었다가 아무것도 안 고치고 저장 → 값 유실 없음
- [ ] `취소` → 목록으로
- [ ] 저장 후 리다이렉트 목적지가 목록이다
- [ ] 저장 후 `/education`에 반영된다 (`revalidatePath` 그대로 동작)

## 4. 결정기록 01 필드 회귀 (01을 먼저 했다면)

- [ ] 일정 유형 라디오가 두 화면 모두에서 동작
- [ ] 원데이/다회차 날짜 분기가 두 화면 모두에서 동작
- [ ] HTML 업로드가 두 화면 모두에서 동작
- [ ] 추가에서 넣은 값이 수정 화면에서 그대로 복원된다

## 5. 서버/클라이언트 경계

- [ ] `ContentFormShell`에 `"use client"`가 **없다**
- [ ] 추가 화면에서 DB 조회가 일어나지 않는다
      (Supabase 로그 또는 `console.log`로 확인 — R4)
- [ ] 수정 화면은 조회를 **한 번만** 한다

## 6. 회귀

- [ ] `npx tsc --noEmit` / `npm run build` / `npm run lint` 통과
- [ ] 아직 셸을 적용하지 않은 다른 폼 10벌이 그대로 동작한다
      (최소 2벌 — 예: `content/work/new`, `education/faqs/<id>` — 열어서 확인)
- [ ] `(shell)` 레이아웃과 사이드바가 그대로
- [ ] 콘솔 에러 없음

## 7. diff 점검

- [ ] `git diff`에 **스타일 클래스 변경이 없다** (문자열이 그대로 옮겨졌다)
- [ ] 삭제된 줄이 전부 셸로 옮겨진 마크업이고, 기능 코드가 함께 사라지지 않았다
- [ ] `new/page.tsx`가 여전히 존재한다 (안 A로 잘못 가지 않았다)
