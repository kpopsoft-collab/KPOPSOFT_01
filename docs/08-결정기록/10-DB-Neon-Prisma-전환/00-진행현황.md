## 3. 남은 작업 (순서대로)

1. **커밋 → 배포**(사용자 확인 후). 배포 직후 반드시:
   - **`vercel cache purge --type data`** (또는 대시보드 CDN → Caches → Runtime and Data Cache 퍼지). Vercel Data Cache는 **배포 간에 유지**되고 공개 리더는 `revalidate: false`라서, 퍼지하지 않으면 운영이 옛 Supabase 데이터(Supabase 이미지 URL — 새 CSP가 막음)를 계속 보여 준다.
   - 운영에서 `/admin` 로그인(`admin` 계정), 이미지·번들 업로드 1회(CSP `connect-src` 실제 통과 확인 — 로컬에서 아직 안 함), 공개 페이지 이미지 확인.
2. **Vercel env 정리**(새 배포 안정 확인 후 — 그 전엔 이전 배포로 롤백할 때 필요) — `NEXT_PUBLIC_SUPABASE_*`, `SUPABASE_SERVICE_ROLE_KEY`, `ADMIN_DEV_BYPASS` 제거.
3. **남은 결정** — `scripts/*.cjs` 4개(supabase-js 사용, 이제 실행 불가) 삭제 여부, `.mcp.json`의 supabase 서버 제거, 이전 끝난 Supabase 프로젝트 정지/삭제 시점. `course-bundle.test.ts`의 MIME 드리프트 테스트는 `supabase/migrations/`(이력 보존)를 계속 읽는다 — 그대로 둬도 통과.
4. 사이드 메모: 로그인 실패 후 아이디 칸이 비워진다(React 19 폼 액션의 자동 리셋). 불편하면 `defaultValue`로 되돌려 주기.

## 4. 주의사항 (잊으면 사고 나는 것)

- **RLS가 없어졌다.** 어드민 서버 액션 57개는 자체 권한 검사가 없다(그동안 RLS가 막았다). 그래서 Prisma 리포의 **모든 메서드가 `assertAdmin()`을 먼저 부른다** — 새 리포 메서드를 추가할 때도 반드시 넣을 것. 공개 조회는 `public-content.ts`에서 `isPublished` 필터를 직접 건다.
- 운영 `ADMIN_DEV_BYPASS`가 `"false"`가 아니었다(= 운영 /admin이 로그인 없이 열려 있었을 가능성). 새 코드는 production에서 bypass를 무시하므로 **배포 전에 관리자 계정을 반드시 시드**해야 운영 어드민에 들어갈 수 있다.
- `prisma migrate dev`는 백그라운드 실행 시 출력이 늦게 온다 — 중복 실행하면 마이그레이션이 두 개 생긴다.
- Vercel 함수 요청 본문 한도 4.5MB 때문에 업로드는 서버 경유가 아니라 클라이언트 직업로드(토큰 방식)다.
- Neon/Blob/함수 리전은 모두 iad1(프로젝트에 함수 리전 설정 없음 = 기본 iad1).
