## 1. 라우트

| 경로 | 파일 | 무엇 |
|------|------|------|
| `/education/programs` | `src/app/education/programs/page.tsx` | 정규 클래스 4과정 목록 + 트랙 필터 |
| `/education/programs/[slug]` | `.../[slug]/page.tsx` | 과정 상세 |

둘 다 `force-dynamic`이다. 어드민이 고치면 **새로고침만으로 보여야** 하므로
`generateStaticParams`를 쓰지 않는다. 목록은 예전에 빈 페이지라 걸어 뒀던
`robots: { index: false }`를 **지웠다** — 두면 어드민이 공개한 과정이 검색에
영원히 안 나온다.

들어오는 길은 `/education` 프로그램 카드의 `정규 교육과정 알아보기` CTA다.
`/education`의 `edu-programs`는 정규 클래스를 3분류 중 하나로 **소개**만 하고,
이 페이지가 4과정을 나란히 놓고 **비교·선택**하게 한다. 두 화면이 같은 일을
하면 하나가 곧 방치된다.

## 3. 데이터 경로

```text
목록  getPublicRegularClasses()      → REGULAR_CLASS_PUBLIC_COLUMNS
상세  getPublicRegularClassBySlug()  → 위 상수 + detail_html, detail_bundle_path
```

`src/lib/public-content.ts`. 상세 전용 컬럼을 **공통 상수에 넣지 않는다** —
목록이 쓰지도 않는 컬럼 때문에 `/education`까지 같이 폴백으로 떨어질 이유가 없다.

번들의 공개 URL은 DB에 없다. `detail_bundle_path`(폴더)만 저장하고 **서버에서**
`…/index.html` URL을 조립한다. 클라이언트에서 만들면 프로젝트 ref가 화면 코드에
흩어진다.

### 없는 행과 실패한 조회를 **구분한다**

| 상황 | 결과 |
|------|------|
| 조회 성공 + 행 없음 (삭제·비공개) | **404** |
| 조회 자체가 실패 (장애) | **정적 폴백**(`education-content.ts`) |

구분하지 않으면, 목록은 폴백으로 4개 카드를 그리는데 상세만 404가 나서
**목록 카드가 전부 깨진 링크**가 된다. 비공개 필터링은 RLS가 이미 하므로
페이지에서 `is_published`를 다시 검사하지 않는다.

목록 리더도 `read()` 공용 경로를 쓰지 않고 별도다 — 공용 경로는 `0행 = 폴백`이라,
**모든 과정을 일부러 비공개로 돌린 정상 상태**에서 정적 4행이 되살아난다.

## 4. 상세 본문은 셋 중 하나

```text
detailHtml  있으면  → CourseHtml (정제 후 렌더)
없고 bundleUrl 있으면 → ProgramBundleLink (새 탭)
둘 다 없으면        → CurriculumTimeline (curriculum 배열)
```

어드민이 택일로 고르므로 겹치지 않는다. 만에 하나 둘 다 채워져 있으면 HTML이 이긴다.
링크 블록은 본문 **아래**가 아니라 본문 **자리**에 들어간다.
방식·상한·보안 판단은 [../06-admin/07](../06-admin/07-과정-상세본문-HTML과-번들.md).

### release gate — G1~G5 닫힘, **G6만 남았다**

| # | 내용 | 상태 |
|---|------|------|
| G1 | 본문은 slug 단건 조회로만 읽는다(목록은 `detail_html` 제외) | 닫힘 |
| G2 | **렌더 직전 재정제** — DB에 직접 심은 XSS가 실제로 막히는 것을 확인 | 닫힘 |
| G3 | `dangerouslySetInnerHTML`에는 정제 통과분만 | 닫힘 |
| G4 | `.course-html-shell` 컨테인먼트 셸을 그대로 렌더 | 닫힘 |
| G5 | 일정 표기는 `formatClassSchedule()` 하나로 | 닫힘 |
| G6 | **CSP 검토** | **미이행** — 인라인 `<style>`을 허용해야 해 정책과 충돌 여지가 있다 |

셸의 `contain: paint`는 업로드 CSS가 본문 밖으로 못 나가게 하는 **실제 경계**다
(속성 이름 블록리스트는 원리적으로 못 이긴다). 대신 넘치는 표를 잘라 없애던
문제가 있어 가로 스크롤을 따로 붙였다 — 셸 CSS를 손볼 때 이 두 가지를 같이 본다.

## 5. 일부러 만들지 않은 것

**상세 페이지의 강사진·후기·FAQ 블록.** 요구사항이 "(선택)"으로 뒀고, 특히 후기는
`EduReview.program`이 자유 문자열이라 이 과정 것이라고 판단할 기준이 없다.
잘못 매칭해 **다른 과정 후기를 붙이느니** 블록을 빼는 편이 낫다.
붙이려면 후기에 과정 FK나 slug를 먼저 만들어야 한다.

**신청 폼**도 범위 밖이다. 하단 CTA는 기존 문의 섹션으로 보낸다.

## 6. 실제 DB로 확인한 것 (2026-08-03)

- 4개 slug 상세 전부 200, 없는 slug 404, 목록 200
- `<title>`이 `seo_title`을 따르고 canonical·og:url이 정식 도메인
- 비공개로 바꾸면 상세 404 + 목록에서 빠지고, **나머지 과정은 그대로**(정적 4행으로 튀지 않음)
- 정제 안 된 XSS를 DB `detail_html`에 직접 심어도 렌더 직전 정제가
  `<script>`·`on*`·`<iframe>`·`javascript:`·`@import`·`position:fixed`를 전부 막는다
