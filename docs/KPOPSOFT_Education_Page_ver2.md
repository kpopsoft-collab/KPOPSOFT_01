# KPOPSOFT Education 페이지 개발 기획서

현재 KPOPSOFT 웹사이트에 독립된 `/education` 페이지를 추가해 주세요.

기존 홈페이지에 포함된 교육 프로그램, 강사진, 기업 맞춤형 교육, 교육 후기, 교육 상담 등의 콘텐츠를 별도 Education 페이지로 분리합니다.

이번 페이지는 단순한 강의 소개 페이지가 아니라 다음 두 가지 목적을 모두 달성해야 합니다.

1. 개인 실무자가 자신에게 맞는 프로그램을 찾고 참여할 수 있어야 합니다.
2. 기업 교육 담당자가 교육 역량과 사례를 확인하고 상담을 요청할 수 있어야 합니다.

구현 전에 현재 프로젝트의 기술 스택, 라우팅, 디자인 시스템, 공통 컴포넌트, 데이터베이스, Admin 구조를 먼저 분석해 주세요.

기존 코드를 최대한 재사용하고, 새로운 디자인 시스템이나 별도 관리 체계를 중복으로 만들지 마세요.

---

# 1. 핵심 방향

## 페이지 역할

KPOPSOFT Education은 다음 내용을 전달해야 합니다.

- AI와 소프트웨어를 실무 중심으로 교육하는 곳
- 설명만 듣는 것이 아니라 직접 결과물을 만드는 교육
- 개인과 기업 모두 참여할 수 있는 교육
- 비개발자도 참여할 수 있는 교육
- 기업의 실제 업무에 맞춰 커리큘럼을 설계할 수 있는 교육
- 현업 전문가가 직접 진행하는 교육
- 교육 이후에도 직접 활용할 수 있는 결과를 남기는 교육

## 핵심 메시지

```text
배우는 데서 끝나지 않고,
직접 만들고 적용합니다.
```

## 핵심 설명

```text
AI 활용부터 Vibe Coding, 업무 자동화와 프로토타입 제작까지.
실제 업무와 아이디어를 중심으로 직접 만들며 배우는
KPOPSOFT의 실무형 교육 프로그램입니다.
```

## 교육 원칙

```text
Learn by Making
직접 만들며 배웁니다.

Real Work
실제 업무와 문제를 교육 과제로 활용합니다.

Working Results
교육 과정에서 작동하는 결과물을 완성합니다.

Keep Building
교육 이후에도 직접 활용하고 개선할 수 있도록 합니다.
```

# 2. 주요 사용자

## 2.1 개인·실무자

다음 정보를 빠르게 찾을 수 있어야 합니다.

- 어떤 교육 프로그램이 있는가
- 개발 경험이 없어도 참여할 수 있는가
- 프로그램별 추천 대상은 누구인가
- 난이도는 어느 정도인가
- 무엇을 배우는가
- 무엇을 만들게 되는가
- 온라인 또는 오프라인으로 진행되는가
- 준비물이 필요한가
- 현재 모집 중인지
- 신청 방법과 일정은 무엇인지

## 2.2 기업 교육 담당자

다음 정보를 빠르게 찾을 수 있어야 합니다.

- 기업 맞춤형 교육이 가능한가
- 조직의 직무와 수준에 따라 커리큘럼을 조정할 수 있는가
- 교육 인원과 시간은 어떻게 정하는가
- 실제 기업의 업무를 교육 과제로 활용할 수 있는가
- 어떤 강사진이 교육하는가
- 실제 교육 사례와 결과가 있는가
- 교육 이후 어떤 자료와 결과물이 제공되는가
- 상담 및 제안 요청은 어떻게 하는가

# 3. 브랜드 구조

## 3.1 메인 브랜드

```text

```

Education 페이지의 신뢰와 전문성은 KPOPSOFT가 담당합니다.

다음 영역에서는 KPOPSOFT를 우선적으로 노출합니다.

- Hero
- 기업 맞춤형 교육
- 교육 사례
- 강사진
- FAQ
- 상담 및 신청
- Footer

## 3.2 보조 아이덴티티

```text
VIBEDAYS CLUB
```

VIBEDAYS CLUB은 KPOPSOFT의 실습형 교육과 커뮤니티 문화를 표현하는 보조 아이덴티티입니다.

페이지 첫 화면에서 KPOPSOFT와 VIBEDAYS를 같은 비중으로 노출하지 마세요.

방문자가 KPOPSOFT Education의 프로그램과 방향을 먼저 이해한 뒤 페이지 중간에서 VIBEDAYS CLUB을 소개합니다.

추천 소개 문구:

```text
VIBEDAYS CLUB

서로 다른 경험과 수준을 가진 사람들이
배우고, 만들고, 자신의 결과를 나누는
KPOPSOFT의 실습형 러닝 커뮤니티입니다.
```

VIBEDAYS는 별도 회사나 별도 교육기관처럼 보이지 않아야 합니다.

## 이미지 원칙

추상적인 AI 이미지보다 실제 교육 결과물을 사용합니다.

- AI 활용 입문: AI 도구 실습 화면
- AI 업무 활용: 문서, 조사, 콘텐츠 결과 화면
- Vibe Coding: 수강생이 만든 웹 화면
- AI Prototype Lab: 작동 가능한 프로토타입
- AI 업무 자동화: 자동화 Workflow 또는 대시보드
- 기업 맞춤형 교육: 실제 워크숍 사진

이미지 영역 요구사항:

- 카드 상단 전체 너비
- 기본 비율 `4:3`
- `object-fit: cover`
- 모든 카드 동일 비율 유지
- 이미지 위에 감성 라벨과 모집 상태 오버레이 가능
- 과도한 Gradient overlay 금지
- 이미지가 없으면 KPOPSOFT 브랜드 Placeholder 사용
- 모든 이미지에 alt 필수

Desktop Hover:

- 이미지 1.02~1.04 확대
- 제목 또는 화살표 미세 이동
- 큰 그림자나 과도한 3D 효과 금지

# 23. 카드와 리스트의 이미지 표현 원칙

Education 페이지의 프로그램 카드, 교육 결과물, 교육 사례 리스트는 텍스트만으로 구성하지 않습니다.

이미지는 단순 장식이 아니라 방문자가 프로그램의 성격과 결과를 빠르게 이해하기 위한 핵심 정보입니다.

## 정보 우선순위

```text
이미지
→ 프로그램 또는 사례명
→ 무엇을 배우거나 만들었는지
→ 대상과 교육 형태
→ 결과
→ 상세 보기 CTA
```

태그, 난이도, 교육 시간 등의 부가 정보가 이미지와 제목보다 먼저 보이지 않도록 합니다.

## 이미지 캡션

이미지가 무엇인지 설명하는 짧은 캡션을 지원합니다.

예:

```text
AI Prototype Lab 과정에서 제작한 서비스 예약 프로토타입
```

```text
운영팀이 직접 설계한 반복 보고서 자동화 Workflow
```

캡션은 프로그램 제목을 단순 반복하지 않습니다.

# 24. 이미지 보안 및 공개 설정

기업 교육 사례에는 공개할 수 없는 이미지가 있을 수 있으므로 이미지별 공개 설정을 지원합니다.

권장 필드:

```ts
isPublic: boolean
isBlurred: boolean
isFeatured: boolean
displayOrder: number
altText: string
caption?: string
```

이미지 공개가 어렵지만 사례 자체는 공개 가능한 경우:

- 화면 일부 Blur
- 기업 로고와 개인정보 제거
- 재구성한 Mockup 사용
- 익명 산업군 표기
- KPOPSOFT 기본 그래픽으로 대체

실제 고객 이미지나 내부 자료를 허가 없이 공개하지 않습니다.

# 25. 이미지 없는 상태

이미지가 없어도 레이아웃이 깨지지 않아야 합니다.

이미지 우선순위:

```text
등록된 대표 이미지
→ 등록된 결과물 이미지
→ 등록된 교육 현장 이미지
→ 프로그램 또는 카테고리 기본 그래픽
→ KPOPSOFT 공통 Placeholder
```

Placeholder는 다음 요소를 조합합니다.

- 원
- 별
- 물결
- 프로그램명 첫 글자
- 감성 라벨
- 단순한 코드와 커서 그래픽

최종 화면에 단순 회색 박스를 표시하지 않습니다.

# 28. 데이터 재사용 원칙

프로그램, 강사진, 후기, 사례 등의 데이터를 페이지마다 중복 등록하지 않습니다.

각 콘텐츠는 단일 데이터로 관리하고 노출 옵션으로 제어합니다.

예:

```ts
isPublished
isFeatured
showOnEducation
displayOrder
```

프로그램과 강사진은 관계형 또는 참조 방식으로 연결합니다.

```text
Program ↔ Instructor
```

후기는 관련 프로그램 또는 교육 사례와 연결할 수 있어야 합니다.

기존 데이터베이스 구조와 ORM을 먼저 분석하고 불필요한 별도 시스템을 만들지 않습니다.
