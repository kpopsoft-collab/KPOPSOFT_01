# 05. 이미지·에셋 — 시작점

사이트에 들어간 이미지를 **어떤 프롬프트로 만들었는지** 남긴 기록이다.
같은 톤으로 이미지를 추가하려면 여기 로그를 먼저 읽는다.

원본: `docs/image-generation-prompts.md`

## 새 이미지를 추가할 때

1. [01-원칙-규격-에셋목록.md](01-원칙-규격-에셋목록.md)의 규격·파일명 규칙 확인
2. 같은 역할의 기존 프롬프트를 2·3번 로그에서 찾아 **변주**한다 (톤이 갈라지지 않게)
3. `public/`에 저장하고 [01](01-원칙-규격-에셋목록.md)의 에셋 목록에 추가
4. [04-갤러리연결과-브랜드패턴.md](04-갤러리연결과-브랜드패턴.md)의 체크리스트로 확인

> ⚠️ **공식 브랜드 패턴은 생성 대상이 아니다.** 생성 이미지로 대체하지 않는다.
> [04-갤러리연결과-브랜드패턴.md](04-갤러리연결과-브랜드패턴.md) §7 참조.

## ⚠️ 배포 순서

이미지는 **배포되어야** 반영되지만 DB는 즉시 반영된다. 이 시차 때문에
2026-07-31 배포 사이트 이미지가 전부 깨진 적이 있다.

```text
브랜치 배포 → 이미지 확인 → DB 반영
```

포트폴리오 반영은 `scripts/apply-work-content.cjs`를 쓴다(이미지 미배포 시 자동 중단).
사고 경위는 [../07-dev/03-작업로그-2026-07-31.md](../07-dev/03-작업로그-2026-07-31.md) §4.
