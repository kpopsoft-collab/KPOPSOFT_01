## 1. 기준 문서 우선순위

충돌하면 아래 순서를 따른다.

1. 해당 화면의 최신 수정 요청서 — `docs/02-home`, `docs/03-education` 앞 번호
2. [디자인 시스템](00-START-HERE.md) — 색·타입·그리드·도형·컴포넌트·반응형
3. 이 문서 — 구현 방법과 검증 절차
4. 현재 코드 — 문서와 다르면 이유를 확인한 뒤 문서 기준으로 수정

작업 전 실제 렌더 경로를 먼저 확인한다. 폴더에 파일이 있어도 `page.tsx`가 import하지
않으면 현재 화면이 아니다.

| 화면 | 렌더 시작점 |
|---|---|
| 홈 | `src/app/page.tsx` |
| 교육 | `src/app/education/page.tsx` |
| 과정 목록·상세 | `src/app/education/programs/` |
| 프로젝트 | `src/app/work/page.tsx` |
| 어드민 | `src/app/admin/(shell)/layout.tsx` |

## 2. 구현 소스 지도

| 목적 | 먼저 사용할 것 |
|---|---|
| 색·폰트·radius·전역 간격 | `src/app/globals.css`의 Tailwind v4 토큰·utility |
| 페이지 컨테이너·섹션 간격 | `components/layout/section.tsx`의 `Section` |
| 주요 CTA | `components/ui/cta-button.tsx`의 `CtaButton` |
| 일반 버튼 | `components/ui/button.tsx`의 `Button` |
| 카드·태그·배지 | `components/ui/card.tsx`, `tag.tsx`, `badge.tsx` |
| 폼 선택 UI | `components/ui/select.tsx` |
| 모달·모바일 메뉴 | `components/ui/modal.tsx`, `sheet.tsx` |
| 외부 링크 | `components/ui/new-tab-link.tsx` |
| 이미지 확대 | `components/ui/image-lightbox.tsx` |
| class 병합 | `src/lib/utils.ts`의 `cn()` |

같은 역할의 JSX와 긴 class 목록이 두 번째로 생기면 새로 복사하지 말고 기존 primitive의
variant 또는 공용 컴포넌트로 흡수할 수 있는지 먼저 확인한다.

## 3. 스타일 작성 규칙

- 컴포넌트에는 hex 색상을 쓰지 않고 `bg-ivory`, `text-ink`, `bg-brand-blue` 같은 토큰을 쓴다.
- 기본 컨테이너는 `container-editorial`, 섹션 세로 간격은 `section-py` 또는 `Section`을 쓴다.
- 제목은 `text-display`, `text-display-long`, `text-section`; 큰 본문은 `text-body-lg`를 우선한다.
- 버튼·태그는 기존 variant를 사용한다. 새 radius·shadow·임의 픽셀값은 문서 근거가 있을 때만 추가한다.
- 모바일 우선으로 작성하고 `sm` → `md` → `lg` 순서로 확장한다.
- 장식 도형은 `components/shapes`, 아이콘은 `lucide-react`를 사용하며 장식에는 `aria-hidden`을 준다.
- 전역 CSS는 토큰·공용 utility·전역 동작에만 사용한다. 화면 한 곳의 스타일은 Tailwind class로 둔다.

## 4. Next.js 16 UI 규칙

이 프로젝트의 설치 버전 문서는 `node_modules/next/dist/docs/`가 기준이다.

- 내부 이동은 `next/link`, 이미지는 `next/image`를 사용한다.
- 원격 이미지는 `next.config.ts`의 제한된 `remotePatterns` 안에서만 허용한다.
- 이미지에는 고정 비율을 확보하는 `width`·`height` 또는 `fill`과 의미 있는 `alt`를 제공한다.
- Server Component를 기본으로 두고 상태·이벤트·브라우저 API가 필요한 최소 경계만 `"use client"`로 만든다.
- effect는 외부 시스템 동기화와 구독에만 사용한다. 렌더에서 계산할 수 있는 값을 effect state로 복제하지 않는다.
- 전역 CSS import는 루트 layout에 모으고, 실제 프로덕션 CSS 순서는 `bun run build`로 확인한다.

## 5. 접근성과 상호작용

- 모바일 터치 대상은 최소 `44×44px`이다. 아이콘만 있는 버튼에는 한국어 `aria-label` 또는 `sr-only` 이름을 둔다.
- 링크는 이동, 버튼은 동작에 사용한다. 색만으로 선택·오류·상태를 구분하지 않는다.
- hover만 만들지 말고 `focus-visible`, active, disabled, loading, error 상태를 함께 확인한다.
- 모달·Sheet는 공용 primitive를 사용해 Escape 닫기, focus trap, 스크롤 잠금을 유지한다.
- 폼 오류는 필드 가까이에 두고 `aria-invalid`, `aria-describedby`로 연결한다.
- 애니메이션은 `prefers-reduced-motion`에서 제거하거나 즉시 완료한다.
- sticky header가 앵커를 가리지 않도록 `Section`의 scroll margin을 유지한다.

## 6. AI 작업 절차

1. `AGENTS.md`와 관련 Next.js 16 문서를 읽는다.
2. 화면별 문서와 실제 `page.tsx` import를 대조해 살아 있는 컴포넌트만 찾는다.
3. 기존 토큰·primitive로 해결 가능한지 검색한다.
4. 변경할 파일과 성공 조건을 짧게 정하고 최소 범위로 구현한다.
5. 390·768·1024·1440px에서 아래 항목을 확인한다.
6. lint·타입·프로덕션 빌드를 통과시킨다.

## 7. 화면 점검표

- 가로 스크롤, 잘린 제목, 겹친 장식, 화면 밖 CTA가 없는가
- sticky header 뒤로 앵커 제목이 숨지 않는가
- 내비게이션·모달·아코디언을 키보드만으로 열고 닫을 수 있는가
- 이미지가 로드되기 전후 레이아웃이 움직이지 않는가
- 긴 한글·영문·빈 데이터·오류 상태에서도 높이와 줄바꿈이 유지되는가
- 모바일에서 카드가 단순 축소되지 않고 읽는 순서대로 1열 재구성되는가
- 브라우저 콘솔 hydration·Base UI·React 경고가 없는가

## 8. 완료 명령

```bash
bun run lint
bunx tsc --noEmit
bun run build
```

UI를 변경했다면 위 명령만으로 끝내지 않는다. 가능하면 실행 화면을 390px과 1440px에서
직접 확인하고, 브라우저를 사용할 수 없다면 그 한계를 작업 결과에 명시한다.
