# 콘텐츠 폼 공용 셸 (ContentFormShell)

> **위치** `docs/06-admin/06-콘텐츠-폼-공용셸.md` · **원본** `../08-decisions/03-regular-class-form-merge/` + `../08-decisions/08-content-form-route-merge/` (완료 후 승격)
> **읽는 순서** ← 이전 [구축 실행 계획 (병렬 Wave)](05-구축-실행계획.md) · [00-START-HERE](00-START-HERE.md)
>
> **함께 보기** 탭 타겟 규칙은 [../04-design-system/12-모바일과-접근성.md](../04-design-system/12-모바일과-접근성.md)

어드민 콘텐츠 **추가/수정 화면 25개**가 공유하는 페이지 껍데기다.
`/admin/content/**` 아래 폼 페이지를 새로 만들거나 고칠 때 **이 문서가 기준**이다.

## 1. 무엇인가

`src/components/admin/content/content-form-shell.tsx`

목록으로 돌아가는 링크 + `h1` 제목을 렌더하고, 폼은 `children`으로 받는다.

```tsx
<ContentFormShell
  backHref="/admin/content/education/regular-classes"
  backLabel="정규 클래스"
  title={isNew ? "정규 클래스 추가" : "정규 클래스 수정"}
>
  <RegularClassForm
    initial={item}
    onSave={isNew ? createRegularClass : updateRegularClass.bind(null, id)}
  />
</ContentFormShell>
```

한 파일이 추가·수정을 겸하므로 `title`과 `onSave`가 `isNew`로 갈린다 — §3.

| prop | 타입 | 필수 | 용도 |
|------|------|:---:|------|
| `backHref` | `string` | O | 목록 경로 |
| `backLabel` | `string` | O | 링크 문구. 제목과 다를 수 있다 (Work / 프로젝트) |
| `title` | `string` | O | `h1`. 행 값을 써야 하면 템플릿 문자열로 넘긴다 |
| `description` | `string` | | 제목 아래 보조 설명. 현재 `inquiry-options/new` 한 곳 |
| `className` | `string` | | 래퍼 폭·간격 덮어쓰기. **현재 `inquiry-options` 2곳뿐** |
| `children` | `ReactNode` | O | 폼과 그 뒤 블록 전부 |

**서버 컴포넌트다.** `"use client"`를 붙이면 정적인 헤더와 아이콘까지 클라이언트
번들로 들어간다. 폼은 이미 각자 클라이언트 컴포넌트이므로 셸까지 옮길 이유가 없다.

`description`이 `ReactNode`가 아니라 `string`인 것은 의도다 — `<p>` 안에 블록
요소가 들어가는 잘못된 중첩을 타입으로 막는다.

`className`은 셸의 레이아웃 기본값(`mx-auto flex max-w-2xl flex-col gap-6`)을
전부 덮을 수 있는 **넓은 escape hatch**다. `cn`(=`twMerge`)이라 `max-w-xl`,
`gap-8`이 기본값을 이긴다. 꼭 필요한 화면에만 쓴다.

## 2. 적용 범위 — 화면 25개 / 파일 14개

`[id]` **13개** — 그중 12개가 추가·수정을 겸하고(§3), `pillars/[id]`만 수정 전용이다
(카드가 고정 3장이라 추가 화면이 없다). 여기에 `inquiry-options/new` 1개를 더해 14개.

```
content/  work · experts · stats · pillar-examples
          inquiry-options([id] + new — 유일하게 두 파일, §3) · pillars([id]만)
content/education/  regular-classes · club-cohorts · club-tiers · faqs ·
                    past-programs · reviews · stats
```

**제외**
- `content/education/org-training/page.tsx` — 싱글턴 화면이라 목록 복귀 링크가 없다
- 목록 페이지 13개 — `max-w-5xl`이고 헤더 구조가 다르다
- `admin/inquiries/[id]` — 콘텐츠 폼이 아니라 문의 상세·상태 화면이다

## 3. 라우트 병합 — `inquiry-options` 빼고 다 합쳤다

**`new/` 세그먼트가 없다.** `/new`가 `[id]`에 `id === "new"`로 들어와 한 파일이
추가·수정을 겸한다. 2026-08-04에 정규 클래스 하나로 시작해 **2026-08-06에 나머지
9쌍 + `past-programs`까지 넓혔다.**

```tsx
const isNew = id === "new";
const item = (isNew ? undefined : await …collection.get(id)) ?? undefined;
if (!isNew && !item) notFound();
```

치르는 값 둘:

- **`new`는 그 컬렉션에서 쓸 수 없는 id가 된다.** `[id]`에 들어오는 값은 슬러그가
  아니라 행 id(mock은 `work_1`·`edu_class_…` 꼴, Supabase는 uuid PK)라 실제 충돌은
  없다. 하지만 **코드만 봐서는 그 사실을 알 수 없다** — id 생성 방식을 바꿀 때
  이 제약을 같이 본다. 이 문단이 그 제약의 본문이고, 각 페이지에는 여기를 가리키는
  한 줄 주석만 있다.
- 라우트가 하는 일이 파일 경로에서 안 읽힌다. `/new`가 어디서 처리되는지
  `[id]/page.tsx`를 열어야 안다.

> **세 번째 값은 없다.** 2026-08-04까지는 "`/new`가 정적 프리렌더에서 빠진다"를
> 비용으로 셌지만, 2026-08-06 실측 결과 **어드민 페이지는 원래 전부 동적이었다**
> (셸 레이아웃이 `requireAdmin()`을 거친다). 잃는 정적성이 없다.
> 경위: [../08-decisions/08-content-form-route-merge/02-현황분석.md](../08-decisions/08-content-form-route-merge/02-현황분석.md) §4

**`inquiry-options`만 두 파일로 남았다.** 이쪽은 두 화면이 실제로 다르다 — 제목이
행 값(`type.label`)인지 고정인지, `description`·`className`이 있는지, 본문이
`TypeForm` 하나인지 `SubtypeManager`까지 두 섹션인지가 전부 갈린다. 합치면 셸 prop
네 개가 모두 삼항이 된다.

→ **새 콘텐츠 폼은 `[id]/page.tsx` 한 파일로 만든다.** 두 화면의 구조 자체가
갈릴 때만 `new/`를 따로 둔다.

## 4. 새 콘텐츠 폼을 만들 때 지킬 것

한 파일 안에서 `isNew`가 가르는 것들이다.

| | 추가 (`isNew`) | 수정 |
|---|---|---|
| 데이터 조회 | **하지 않는다** | `getContentData()….get(id)` |
| 없는 id | — | `notFound()` — **셸 렌더 이전에** |
| 폼 props | `initial`이 `undefined` | `initial` + `onSave` |
| `onSave` | `create…` | `update….bind(null, id)` |
| 삭제 버튼 | **없다** | 목록 페이지의 `DeleteButton`이 담당 |
| 부모 행이 필요한 블록 | **`!isNew`로 감싼다** | 그린다 |

- 추가 화면이 조회를 하면 매번 존재하지 않는 행을 찾는다. **`isNew`일 때
  `getContentData()`를 아예 부르지 않는지를 코드로 본다** — 빌드 출력의 ○/ƒ로는
  확인되지 않는다. 어드민은 라우트 병합과 무관하게 전부 ƒ다(§3의 인용 블록).
- 마지막 줄의 실례가 `past-programs`의 `GalleryManager`다. `programId`를 FK로 쓰므로
  부모 행이 없는 추가 화면에 뜨면 안 된다. **조회(`listByProgram`)도 같은 분기
  안에 둔다** — 밖에 두면 추가 화면에서 `listByProgram("new")`가 나간다.
- 셸에 삭제 슬롯을 만들지 않은 것은 의도다. 슬롯이 없으면 추가 화면에 삭제가
  새는 사고가 구조적으로 불가능하다.
- `?? undefined`를 빠뜨리지 않는다. 리포지터리는 미스를 `null`로 주는데 폼의
  `initial`은 `T | undefined`다. `!item` 검사가 `isNew`와 묶여 있어 타입이 좁혀지지
  않으므로 여기서 맞춘다.

## 5. 함께 쓰는 공용 컴포넌트

| 파일 | export | 용도 |
|------|--------|------|
| `content/fields.tsx` | `TextField` `DateField` `NumberField` `TextAreaField` `CheckboxField` `CheckboxListField` `StringListField` `SelectField` | 폼 필드 프리미티브 |
| `content/row-actions.tsx` | `EditLink` `DeleteButton` `PublishToggle` | 목록 행 컨트롤 |
| `content/image-upload.tsx` | `ImageUpload` | Storage 업로드 |
| `content/accent-picker.tsx` | `AccentPicker` | 브랜드 accent 선택 |
| `content/education/form-actions.tsx` | `FormActions` | 저장·취소 줄 |

> **알려진 중복** — `FormActions`는 `education/` 아래에 있어 교육 폼 8곳만 쓴다.
> 비교육 폼 6곳(`work-form` `stat-form` `expert-form` `pillar-form` `type-form`
> `pillar-example-form`)이 같은 저장·취소 마크업을 각자 하드코딩한다.
> `content/form-actions.tsx`로 승격할 여지가 있다. **아직 하지 않았다.**

## 6. 접근성

뒤로가기 링크에 `min-h-11 w-fit`이 붙어 있다. 탭 타겟 최소 44px 규칙
([../04-design-system/12-모바일과-접근성.md](../04-design-system/12-모바일과-접근성.md))
때문이고, 글자 높이만으로는 모바일에서 누르기 어렵다.
**지우지 마라.** 셸 한 곳이라 25개 화면이 여기에 달려 있다.
