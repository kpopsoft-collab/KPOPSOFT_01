## 1. 프로덕션 정책 (제안)

```
default-src 'self';
base-uri 'self';
object-src 'none';
frame-ancestors 'none';
form-action 'self';
script-src 'self' 'nonce-{NONCE}' 'strict-dynamic';
style-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net;
font-src 'self' https://cdn.jsdelivr.net;
img-src 'self' https://oxkxkqfwliobkyyexjtk.supabase.co;
connect-src 'self' https://oxkxkqfwliobkyyexjtk.supabase.co;
upgrade-insecure-requests;
```

### 지시문별 근거

| 지시문 | 값 | 왜 |
|---|---|---|
| `script-src` | `'nonce-…' 'strict-dynamic'` | 인라인은 RSC 페이로드뿐이고 Next가 nonce를 자동으로 붙인다([01](01-조사결과.md) §1). `'strict-dynamic'`은 그 스크립트가 불러오는 청크까지 신뢰를 잇는다 |
| `style-src` | `'unsafe-inline'` **유지** | `style={{}}` 11곳 + `next/image fill`([01](01-조사결과.md) §2). **nonce로 못 푼다** — §4 |
| `style-src`/`font-src` | `cdn.jsdelivr.net` | Pretendard를 외부 CDN에서 받는다([01](01-조사결과.md) §3) |
| `img-src` | Supabase만 | `data:`·`blob:` 불필요 — `placeholder="blur"`도 어드민 blob 미리보기도 없다 |
| `connect-src` | Supabase만 | 브라우저에서 Storage 직접 업로드 |
| `frame-ancestors 'none'` | | 이 사이트를 iframe에 넣을 이유가 없다. 클릭재킹 차단 |
| `object-src 'none'` | | 플러그인 미사용 |
| `form-action 'self'` | | 문의 폼이 외부로 전송되지 않게 |

### 개발 모드 추가분

```
script-src … 'unsafe-eval';          ← dev 디버깅 API (01 §5)
connect-src … ws: wss:;               ← HMR 웹소켓
```

`process.env.NODE_ENV === "development"`로 분기한다. **prod에는 `'unsafe-eval'`도
`script-src 'unsafe-inline'`도 넣지 않는다.**

## 2. 어디에 거나 — `proxy.ts`

`next.config.ts`의 `headers()`는 **쓰지 않는다.** nonce는 요청마다 달라야 하는데
그 설정은 정적이다([01](01-조사결과.md) §4).

```
src/proxy.ts
  matcher: ["/admin/:path*"]   →   전체 경로 (단, 아래 제외)
```

### 반드시 제외할 경로

| 경로 | 왜 |
|---|---|
| **`/course-assets/:path*`** | 자체 `sandbox` CSP를 갖는다. 전역 `script-src`가 겹치면 업로드 자료 안의 스크립트가 nonce가 없어 **차단되고 자료가 안 뜬다**([01](01-조사결과.md) §6) |
| `/_next/static/:path*` | 정적 자산에 헤더를 붙일 이유가 없다. proxy를 태우면 캐시 효율만 떨어진다 |

### 기존 로직을 깨지 않기

`proxy.ts`는 지금 Supabase 세션을 갱신하고, 주석에
*"`createServerClient`와 `getUser()` 사이에 로직을 넣지 말라"* 는 제약이 있다.

**세션 갱신은 `/admin/*`에서만 계속 돌게 두고, nonce/CSP는 그 앞뒤로 분리한다.**
전체 경로에서 매 요청 Supabase 세션을 갱신하면 공개 페이지에 불필요한 왕복이 붙는다.

## 3. 위반 보고 수집

Report-Only 단계에만 필요하다. Next가 수신 엔드포인트를 주지 않으므로 직접 만든다.

```
src/app/api/csp-report/route.ts   (신설)
  POST — application/csp-report / application/reports+json 을 받아 로그로 남긴다
```

- **저장하지 않는다.** 서버 로그로 충분하고, DB에 넣으면 그 자체가 관리 대상이 된다
- 봇이 아무 JSON이나 POST할 수 있으므로 **본문 크기 상한**을 둔다
- 헤더에 `report-uri /api/csp-report`를 붙인다(`report-to`는 그룹 설정이 더 필요하다)

## 4. `style-src 'unsafe-inline'`을 남기는 판단

**이게 이번 작업에서 가장 중요한 결정이다.**

빼려면 두 가지를 해야 한다.

1. `style={{}}` 11곳을 CSS 클래스/유틸리티로 이전 — 그런데 **대부분 런타임 값**이다
   (스크롤 offset, 캐러셀 translateX, 실측 px). 정적 클래스로 못 옮긴다
2. `next/image`의 `fill`을 포기 — **프레임워크가 박는 스타일이라 우리가 못 없앤다**

그래서 **지금은 남긴다.** 대신 이렇게 판단한다.

> **CSP의 XSS 방어력은 대부분 `script-src`에서 나온다.** 공격자가 `style` 속성만
> 넣을 수 있고 스크립트를 못 넣으면 할 수 있는 일이 극히 제한된다. `script-src`를
> nonce로 완전히 닫는 것만으로 **G6의 실질 목표는 달성된다.**

`style-src`를 닫는 것은 별도 작업으로 남긴다. 하려면 `fill` 사용처부터 세고
`aspect-ratio` 기반으로 바꿀 수 있는지 보는 것이 시작점이다.

> ⚠️ **문서 정정** — 백로그 06과 `docs/07-dev/13`은 "인라인 렌더링이 사라져 인라인
> `<style>`을 허용할 이유도 사라졌다"고 적었다. 절반만 맞다. `course-html.tsx`
> 때문에 필요하던 이유는 사라졌지만, **원래부터 있던 인라인 스타일 11곳은 그대로다.**
> 이 작업이 끝나면 두 문서를 고친다.

## 5. 적용 순서

각 단계가 끝나야 다음으로 간다. **한 번에 강제하지 않는다** — CSP는 위반해도
콘솔에만 나오고 화면이 조용히 깨지기 때문이다.

| # | 단계 | 산출물 | 확인 |
|---|---|---|---|
| 1 | 보고 엔드포인트 | `api/csp-report/route.ts` | 수동 POST에 200 |
| 2 | **Report-Only**로 proxy에 부착 | `proxy.ts` | 화면이 **아무것도 안 바뀜**, 헤더 존재 |
| 3 | 위반 수집 | 로그 | 4개 상세 페이지 · `/education` · 홈 · 어드민 폼 · **`/course-assets` 자료 열기** |
| 4 | 위반 반영 | 정책 수정 | 예상 밖 위반이 0이 될 때까지 반복 |
| 5 | **강제 전환** | 헤더 이름 변경 | §6 체크리스트 |

**2·5단계는 운영 사이트의 응답 헤더를 바꾼다 — 사용자 확인 후에 한다.**
