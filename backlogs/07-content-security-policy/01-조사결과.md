## 1. 인라인 `<script>` — nonce로 전부 덮인다

`/education/programs` 프로덕션 응답 기준.

| | 개수 |
|---|---|
| `<script>` 전체 | 25 |
| `src=` 외부 청크 | 16 |
| **인라인** | **9** |

인라인 9개는 **전부** `(self.__next_f=self.__next_f||[]).push(...)` — App Router의
**RSC(Flight) 하이드레이션 페이로드**다. 페이지마다 내용이 달라 정적 해시로는
못 잡는다.

- `next/script` 사용: **0건**
- `dangerouslySetInnerHTML`로 script 주입: **0건**

> **CSP에 미치는 영향** — Next가 CSP 헤더의 nonce를 파싱해 자기 스크립트에
> 자동으로 붙여 준다. `script-src`에 `'unsafe-inline'`이 **필요 없다.**

## 2. 인라인 `style` — 여기가 유일한 걸림돌

### 2-1. `style={{...}}` JSX prop — **11곳 / 7파일** (재확인 완료)

| 파일 | 개수 | 무엇 |
|---|---|---|
| `sections/process.tsx` | 3 | `transitionDuration`·`transitionDelay` |
| `sections/education/edu-hero.tsx` | 3 | `transform: scale(...)`·`transitionDelay` |
| `ui/image-lightbox.tsx` | 1 | `transform: translateX(...)` |
| `sections/why-kpopsoft.tsx` | 1 | `transitionDelay` |
| `sections/selected-work.tsx` | 1 | `transform: translateX(...)` |
| `sections/education/reviews.tsx` | 1 | CSS 변수 주입 `--marquee-shift` |
| `sections/education/edu-process.tsx` | 1 | 동적 스타일 |

대부분 **런타임에 값이 정해지는** 것들이다(스크롤 위치, 캐러셀 offset, 실측 px).
정적 클래스로 옮기기 어려운 성격이다.

### 2-2. `next/image`의 `fill` prop — 프레임워크가 주입한다

`fill`을 쓰면 Next가 `<img>`에 `style="position:absolute;height:100%;width:100%;…"`를
직접 박는다. 사용처: `admin/.../gallery-manager.tsx`, `admin/.../gallery-field.tsx`,
`sections/experts.tsx` 등. **우리 코드를 고쳐도 없앨 수 없다** — `fill`을 포기해야 사라진다.

### 2-3. `dangerouslySetInnerHTML`로 `<style>` 주입

**0건.** 남아 있는 `dangerouslySetInnerHTML`은 `course-html.tsx:32` 하나뿐이고,
그 컴포넌트는 **아무도 import하지 않는다**(백로그 06 D8로 파일만 남겨 둔 죽은 코드).

> **CSP에 미치는 영향** — **nonce는 `style` 속성에 적용되지 않는다.** CSP 스펙상
> nonce는 `<style>` **요소**에만 붙는다. Next 공식 문서도 인라인 스타일은
> *"외부 스타일시트로 옮기라"* 고만 안내한다. 따라서 `style-src 'unsafe-inline'`은
> 지금 뺄 수 없다.

## 3. 외부 출처 — 두 곳뿐

| 지시문 | 출처 | 근거 |
|---|---|---|
| `img-src` | `oxkxkqfwliobkyyexjtk.supabase.co` | `next.config.ts` `images.remotePatterns` |
| `connect-src` | 같은 도메인 | 브라우저에서 Supabase를 직접 부르는 곳 — `image-upload.tsx`, `bundle-upload.tsx`(Storage 직접 업로드) |
| `style-src` | `cdn.jsdelivr.net` | `layout.tsx:66` Pretendard CSS `<link rel="stylesheet">` |
| `font-src` | `cdn.jsdelivr.net` | 위 CSS가 참조하는 woff2 (같은 CDN으로 추정) |

확인한 것:

- **`next/font` 미사용** — 폰트를 외부 CDN에서 직접 받는다
- **iframe·embed·analytics 없음** (`<iframe>` 문자열은 정제기 테스트 픽스처뿐)
- **`placeholder="blur"` 없음** → `img-src`에 `data:` **불필요**
- SVG는 전부 `/assets/…` 동일 출처 → `'self'`로 충분
- 브라우저발 `fetch()` 없음. `course-assets/route.ts:93`의 `fetch`는 **서버**라 무관

## 4. Next.js 16에서 CSP를 거는 방법 (context7로 공식 문서 확인)

- **`next.config.ts`의 `headers()`로는 nonce를 못 쓴다.** nonce는 요청마다 새로
  만들어야 하는데 그 설정은 정적이다. `headers()`만으로 CSP를 걸려면
  `'unsafe-inline'`을 켜야 해서 의미가 크게 준다.
- **nonce는 proxy(구 middleware)에서 건다.** 요청마다 nonce를 만들어
  응답의 `Content-Security-Policy`와 요청의 `x-nonce` 헤더 양쪽에 넣는다.
  Next가 그 헤더를 파싱해 **프레임워크 스크립트에 자동으로 붙인다** — 태그마다
  수동으로 넣을 필요가 없다.
- **이 프로젝트의 `src/proxy.ts`는 이미 있다.** 다만 `matcher: ["/admin/:path*"]`라
  관리자 경로에만 돈다. Supabase 세션 갱신을 하고 있고,
  `createServerClient`와 `getUser()` 사이에 로직을 넣지 말라는 제약이 주석에 있다.
- **Report-Only**는 헤더 이름만 `Content-Security-Policy-Report-Only`로 바꾸면 된다.
  다만 **위반 보고를 받을 엔드포인트는 우리가 만들어야 한다** — Next가 제공하지 않고,
  이 프로젝트에도 없다.

## 5. 개발 모드

공식 문서가 명시한다 — dev는 디버깅 API 때문에 **`'unsafe-eval'`이 필요하다.**
번들러(Turbopack/webpack)와 무관하다. **dev/prod 정책 분기가 필요하다.**

## 6. `/course-assets`와의 충돌 — **가장 큰 실무 위험**

그 라우트는 HTML 응답에 자체 `Content-Security-Policy: sandbox …`를 세팅한다.
전역 CSP를 경로 제한 없이 걸면 같은 응답에 CSP가 **두 개** 붙고, 브라우저는
둘을 **교집합**으로 적용한다.

결과: 업로드 자료 안의 인라인 스크립트는 우리 nonce가 없으므로 전역
`script-src 'nonce-…'`에 걸려 **차단된다.** 자료가 안 뜬다.

> **CSP에 미치는 영향** — 전역 CSP에서 `/course-assets/:path*`를 **반드시 제외**한다.

## 7. 어드민 — 추가로 열 것이 없다

- `image-upload.tsx` — `blob:`/`data:` 미사용. 파일을 Storage에 바로 올리고
  미리보기는 **업로드 후 받은 공개 URL**을 쓴다
- `bundle-upload.tsx` — zip을 메모리에서 풀어(`fflate`) 바로 업로드.
  `createObjectURL` 코드베이스 전체 **0건**

> **CSP에 미치는 영향** — `img-src`에 `blob:`·`data:`를 열 필요가 **없다.**
