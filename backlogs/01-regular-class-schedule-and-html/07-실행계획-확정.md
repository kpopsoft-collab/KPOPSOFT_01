# 실행계획 (확정본)

`01~05`의 계획을 코드 대조와 codex 교차검증 결과로 고쳐 쓴 것이다.
어긋나면 **이 문서가 우선**한다. 근거는 [06-교차검증-결과.md](06-교차검증-결과.md).

> ⚠️ **로컬과 운영이 Supabase 프로젝트 하나를 공유한다**(`scripts/*.cjs` 머리말).
> 마이그레이션 적용은 곧 **운영 DB 변경**이다. 되돌리기 DDL을 손에 쥐고 시작한다.

## 3. 단계

각 단계 끝에서 `npx tsc --noEmit`이 통과해야 한다.

**1) 마이그레이션 SQL 작성** — §2. D8에 따라 **파일만 만들고 적용은 미룬다.**
적용 전까지 3~7단계의 실제 DB 검증이 불가능하다는 점을 감수한다(§5).

**2) 의존성·설정** — `sanitize-html` + `@types/sanitize-html`, 그리고 CSS 스코프에
쓸 `postcss`와 `parse5`를 **직접 의존성으로** 올린다(둘 다 지금은 전이 의존일
뿐이라 언제 사라져도 이상하지 않다). `sanitize-html@2.17.6`은 Node `>=22.12.0`
요구 → `package.json`에 `engines.node` 고정.
`next.config.ts`에 `experimental.serverActions.bodySizeLimit: "2mb"` 추가.
`package-lock.json`에 **작업 전부터 있던 미커밋 변경**을 덮어쓰지 않도록 주의.

**3) 정제 + CSS 스코프 유틸** — 설계는 [08](08-HTML정제-설계.md)(HTML)과
[09](09-CSS스코프-설계.md)(CSS). **09를 빼먹으면 CSS 쪽이 통째로 없는 구현이 된다.**
D5가 `<style>` 유지를 택했으므로 이 단계가 **이 작업에서 가장 무겁고 위험하다.**
`src/lib/admin/sanitize-html.ts`에 `server-only`를 **붙이지 않는다** — 백로그 02가
렌더 직전에도 호출해야 하고, 순수 함수라 클라이언트 노출 자체는 위험이 아니다
(위험한 건 클라이언트 정제에 *의존*하는 것이다).

테스트: `src/lib/admin/sanitize-html.test.ts` + `node --test`
(Node 24 타입 스트리핑. 경로 별칭이 안 먹으므로 **상대 경로**로 import).
케이스는 05 §3-1 페이로드 전부 + [08 §4](08-HTML정제-설계.md)(HTML) +
[09 §4-1](09-CSS스코프-설계.md)(CSS).

**4) 폼 프리미티브 (먼저 한다)** — `fields.tsx`에 `RadioField`
(`useId`, `fieldset`+`legend`, 탭 타겟 44px).
`html-upload.tsx` — Storage 미사용. 확장자를 주 검증(MIME은 빈 문자열일 수 있다),
**512KB** 상한, `TextDecoder("utf-8",{fatal:true})`로 UTF-8 강제,
선택 후 input value 초기화(같은 파일 재선택), 파일명·글자 수·제거 버튼. 미리보기 없음(D9).
둘 다 **추가만** 하므로 이 단계 단독으로 `tsc`가 통과한다.

**5) 타입·매핑·액션·폼 — 한 단계, 한 커밋 (쪼개면 반드시 깨진다)**

`EducationRegularClass`에 필수 필드를 넣는 순간 `regular-class-form.tsx:23`의
`Input = Omit<EducationRegularClass,…>`이 넓어지고, `:59`의 payload가 새 필드를
안 넘겨 **`TS2345`가 난다.** 타입만 먼저 커밋하면 그 커밋은 빌드가 깨진 채 남는다.
그래서 아래를 **한 덩어리로** 간다.

- `content-types.ts` — `EducationScheduleType`, 라벨맵, `scheduleType`/
  `startDate`/`endDate`/`detailHtml`
- `supabase-content.ts` — **전역 리팩터링 금지**(06 §P1-4). 정규 클래스에만
  `DATE_FIELDS` 대칭 변환(`fromRow`: null→`""` / `toRow`: `""`→`null`;
  `undefined`로 두면 `toRow`가 스킵해 **날짜를 지울 수 없다**)과
  `list()` projection(`detail_html` 제외, **`id` 명시** — `FIELDS`에 `id`가 없다)
- **`getForEdit(id)`** — 동반 테이블을 같이 읽는 관리자용 조회. `[id]/page.tsx`가
  이걸 쓴다. §5-1 참고
- `actions.ts` + 폼 payload를 같은 커밋에서 맞춘다

목데이터는 빈 배열이라 작업 없음(06 §1-1).

### 5-1. 원본을 안 읽으면 **일반 수정이 기존 HTML을 지운다**

`get()`은 기본 테이블만 읽는다(`supabase-content.ts:218`). 원본은 동반 테이블에
있으므로, 폼이 `detailHtmlRaw`를 빈 문자열로 들고 열린다. 이 상태로 **이름만 고쳐
저장하면 "제거"로 해석돼 HTML이 통째로 날아간다.** 정제본을 raw 대신 쓰면 원본과
파일명이 유실된다. 둘 다 조용한 데이터 손실이다.

→ 폼이 보내는 값은 문자열이 아니라 **의도**여야 한다.

```ts
type HtmlIntent =
  | { kind: "keep" }                              // 안 건드림 — 기본값
  | { kind: "replace"; raw: string; fileName: string }
  | { kind: "remove" };
```

- `keep` — 동반 테이블·`detail_html` **둘 다 손대지 않는다**
- `replace` — 크기·타입 검사 → 정제 → `detail_html` 갱신 + 동반 테이블 upsert
- `remove` — `detail_html = ''` + 동반 행 delete

### 5-2. 액션

```ts
// 클라이언트를 믿지 않는 지점은 여기 하나다. 크기·타입 검사를 정제 전에 한다.
function normalize(input: Input) {
  const oneday = input.scheduleType === "oneday";
  return { ...input, endDate: oneday ? "" : input.endDate };
}
function resolveHtml(intent: HtmlIntent) {
  if (intent.kind !== "replace") return intent;
  if (typeof intent.raw !== "string") throw new Error(...);
  if (Buffer.byteLength(intent.raw, "utf8") > 512 * 1024) throw new Error(...);
  return { ...intent, detailHtml: sanitizeCourseHtml(intent.raw) };
}
```

`detailHtml`은 **폼이 보낸 값을 절대 쓰지 않고** raw에서 서버가 만든다.
`create`/`update` 둘 다 통과시키고, 부분 patch인 `setRegularClassPublished`는
태우지 않는다.

**6) 공개 층 (타입·함수까지만)** — `education-content.ts` 타입 +
정적 4행에 `scheduleType: "multi"`. `public-content.ts`의 정규 클래스 리더는
**정상 0행이면 `[]`**, 오류일 때만 폴백(06 §P1-5). 목록 매핑에 `detailHtml`을
**넣지 않는다**(본문은 02의 slug 단건 조회에서). `formatClassSchedule()`은
`new Date()`를 쓰지 않고 문자열을 직접 자른다. **실제 렌더는 백로그 02.**

**7) 문서** — `docs/07-dev/02-개발상태.md`, 작업로그, `01`~`05`의 오류 3건(06 §1).
02에 **release gate**를 남긴다: slug 단건 조회 / **렌더 직전 재정제** / 실제 렌더 /
`.course-html-shell` 컨테인먼트 / 필요 시 CSP.
클럽 기수 `is_published` 버그(06 §4)는 **새 백로그로 등록**한다.

## 4. 커밋 분할

단계와 1:1이다. **4·5를 쪼개면 빌드가 깨진 커밋이 남는다**(§3 5단계).

| # | 범위 | 메시지 예 |
|---|------|-----------|
| 1 | 마이그레이션 SQL | `feat(db): 정규 클래스 일정 컬럼과 HTML 원본 테이블` |
| 2 | 의존성·Next 설정 | `build: 상세 HTML 정제 의존성과 서버 액션 본문 한도` |
| 3 | 정제·CSS 스코프 유틸 + 테스트 | `feat(admin): 상세 HTML 정제와 CSS 스코프` |
| 4 | `RadioField` + `HtmlUpload` | `feat(admin): 라디오 필드와 HTML 업로드 위젯` |
| 5 | 타입·repo·액션·폼 (원자적) | `feat(admin): 정규 클래스 폼에 강의 일정·상세 HTML 입력` |
| 6 | 공개 데이터 계약·포맷 함수·문서 | `feat(education): 정규 클래스 일정 데이터 계약과 표기 포맷` |

### DB 적용 후로 미루는 항목 (D8)

코드만 먼저 내므로 아래는 **마이그레이션 적용 시점에 다시 연다.** 이때까지
01은 "완료"가 아니라 **"DB 적용 대기"** 상태다.

- 컬럼·제약·동반 테이블이 생겼고 기존 4행이 `multi`+날짜 null로 살아 있다
- CHECK가 "원데이+종료일", "종료일<시작일", "종료일만"을 실제로 막는다
- `detail_html_raw`가 anon PostgREST로 **안 읽힌다**(동반 테이블 RLS)
- 전 과정을 비공개로 하면 `/education`에 정규 클래스가 **안 나온다**
  (정적 4행이 되살아나면 06 §P1-5 미처리)
- 클럽 기수·나머지 교육 폼 6종이 그대로 저장된다(projection 회귀)
- 어드민에서 고친 값이 공개 화면에 반영된다 (05 §0의 폴백 함정)
