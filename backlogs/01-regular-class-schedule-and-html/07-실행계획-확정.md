# 실행계획 (확정본)

`01~05`의 계획을 코드 대조와 codex 교차검증 결과로 고쳐 쓴 것이다.
어긋나면 **이 문서가 우선**한다. 근거는 [06-교차검증-결과.md](06-교차검증-결과.md).

> ⚠️ **로컬과 운영이 Supabase 프로젝트 하나를 공유한다**(`scripts/*.cjs` 머리말).
> 마이그레이션 적용은 곧 **운영 DB 변경**이다. 되돌리기 DDL을 손에 쥐고 시작한다.

## 1. 착수 전 결정 (D5~D9가 신규)

| # | 질문 | 기본안 |
|---|------|--------|
| D1 | HTML을 DB 컬럼 vs Storage | **DB 컬럼** (03 §3 A안 유지) |
| D2 | 정제 위치 | **저장 시 + 렌더 직전 2중**. 저장만으로는 안 닫힌다(06 §P1-3) |
| D3 | 원데이에 시간(HH:MM) | 날짜만 |
| D4 | 기존 4과정 초기값 | `multi`, 날짜 비움 |
| **D5** | `<style>`·`class` 처리 | **`<style>` 유지 + CSS 셀렉터 스코프 구현.** `class`도 허용 → [08](08-HTML정제-설계.md) |
| **D6** | 업로드 원본(raw) 저장 위치 | **admin-only 별도 테이블**로 분리. 같은 테이블이면 익명 공개된다(06 §P1-2) |
| **D7** | 서버 액션 `requireAdmin` 추가 | **별도 백로그.** 기존 인증 미배선 문제라 여기 넣으면 범위가 번진다 |
| **D8** | 마이그레이션 적용 시점 | **코드 먼저, DB 적용은 나중에.** SQL은 이번에 완성해 둔다 |
| **D9** | 업로드 미리보기 | **v1 생략.** `sandbox=""` iframe은 실제 결과와 다른 화면을 보여준다(06 §3) |

> **D5는 권장안(둘 다 제거)이 아닌 쪽으로 확정됐다.** 대가는 [08](08-HTML정제-설계.md)에
> 적었다 — CSS 파서 도입, `</style>` 탈출·`@import`·`position:fixed` 오버레이까지
> 막아야 하고 이 작업 리스크의 대부분이 여기 몰린다. 되돌리려면 08 §2의 `KEEP_STYLE`을 끈다.

D5·D6·D9는 요구사항 §3.2-5(미리보기)와 03 §1(raw 컬럼)을 **바꾸는** 결정이다.

## 2. 마이그레이션

`supabase/migrations/20260803HHMMSS_regular_class_schedule_and_html.sql`

```sql
-- 정규 클래스: 일정 유형(원데이/다회차) + HTML 상세 본문
-- 근거: backlogs/01-regular-class-schedule-and-html/07-실행계획-확정.md

do $$ begin
  create domain public.education_schedule_type as text
    check (value in ('oneday', 'multi'));
exception when duplicate_object then null; end $$;

alter table public.education_regular_classes
  add column if not exists schedule_type public.education_schedule_type
    not null default 'multi',
  add column if not exists start_date date,
  add column if not exists end_date   date,
  -- 정제 완료본만 들어온다. 렌더되는 값은 이것뿐이다.
  add column if not exists detail_html text not null default '';

-- 날짜는 "없어도 되지만, 있으면 앞뒤가 맞아야 한다".
-- "종료일만 있는" 상태도 막는다 — 시작을 모르는 종료일은 화면이 쓸 수 없다.
do $$ begin
  alter table public.education_regular_classes
    add constraint education_regular_classes_schedule_ck check (
      (schedule_type = 'oneday' and end_date is null)
      or (schedule_type = 'multi' and (
            end_date is null
            or (start_date is not null and end_date >= start_date)
      ))
    );
exception when duplicate_object then null; end $$;

-- ── 업로드 원본: 관리자 전용 동반 테이블 ──────────────────────────────
-- 원본은 정제 전 스크립트를 그대로 담는다. 같은 테이블에 두면 RLS가 행 단위라
-- 게시된 행의 이 컬럼까지 anon에게 열린다 = 공개 API에 XSS 페이로드가 놓인다.
create table if not exists public.education_regular_class_html_sources (
  class_id   uuid primary key
             references public.education_regular_classes (id) on delete cascade,
  raw        text not null default '',
  file_name  text not null default '',
  updated_at timestamptz not null default now(),
  constraint education_regular_class_html_raw_size_ck
    check (octet_length(raw) <= 524288)          -- 512KB. 서버 검사와 같은 값
);

alter table public.education_regular_class_html_sources enable row level security;

drop policy if exists education_html_sources_admin_all
  on public.education_regular_class_html_sources;
create policy education_html_sources_admin_all
  on public.education_regular_class_html_sources for all
  using (public.is_admin()) with check (public.is_admin());

drop trigger if exists set_updated_at on public.education_regular_class_html_sources;
create trigger set_updated_at before update
  on public.education_regular_class_html_sources
  for each row execute function public.set_updated_at();

-- ── 되돌리기 (down) ───────────────────────────────────────────────────
--   drop table if exists public.education_regular_class_html_sources;
--   alter table public.education_regular_classes
--     drop constraint if exists education_regular_classes_schedule_ck,
--     drop column if exists schedule_type, drop column if exists start_date,
--     drop column if exists end_date,      drop column if exists detail_html;
--   drop domain if exists public.education_schedule_type;
```

03 §2 대비 — raw/파일명/업로드시각을 **동반 테이블로 옮겼고**, CHECK가 "종료일만"도
막고, `start_date` 인덱스를 **뺐다**(4행뿐이고 그 축의 조회가 아직 없다).

## 3. 단계

각 단계 끝에서 `npx tsc --noEmit`이 통과해야 한다.

**1) 마이그레이션 SQL 작성** — §2. D8에 따라 **파일만 만들고 적용은 미룬다.**
적용 전까지 3~7단계의 실제 DB 검증이 불가능하다는 점을 감수한다(§5).

**2) 의존성·설정** — `sanitize-html` + `@types/sanitize-html`, 그리고 CSS 스코프에
쓸 `postcss`와 `parse5`를 **직접 의존성으로** 올린다(둘 다 지금은 전이 의존일
뿐이라 언제 사라져도 이상하지 않다). `sanitize-html@2.17.6`은 Node `>=22.12.0`
요구 → `package.json`에 `engines.node` 고정.
`next.config.ts`에 `experimental.serverActions.bodySizeLimit: "2mb"` 추가.
`package-lock.json`에 **작업 전부터 있던 미커밋 변경**을 덮어쓰지 않도록 주의.

**3) 정제 + CSS 스코프 유틸** — 설계는 [08-HTML정제-설계.md](08-HTML정제-설계.md).
D5가 `<style>` 유지를 택했으므로 이 단계가 **이 작업에서 가장 무겁고 위험하다.**
`src/lib/admin/sanitize-html.ts`에 `server-only`를 **붙이지 않는다** — 백로그 02가
렌더 직전에도 호출해야 하고, 순수 함수라 클라이언트 노출 자체는 위험이 아니다
(위험한 건 클라이언트 정제에 *의존*하는 것이다).

테스트: `src/lib/admin/sanitize-html.test.ts` + `node --test`
(Node 24 타입 스트리핑. 경로 별칭이 안 먹으므로 **상대 경로**로 import).
케이스는 05 §3-1 페이로드 전부 + 08 §4 CSS 케이스 + "본문이 살아남는지".

**4) 타입·매핑·날짜 왕복** — `content-types.ts`에 `EducationScheduleType`,
라벨맵, `scheduleType`/`startDate`/`endDate`/`detailHtml` 필드.
`supabase-content.ts`는 **전역 리팩터링 금지**(06 §P1-4). 정규 클래스에만:
- `DATE_FIELDS` 대칭 변환 — `fromRow`: null → `""` / `toRow`: `""` → `null`.
  `undefined`로 두면 `toRow`가 스킵해서 **날짜를 지울 수 없다.**
- `list()` projection에서 `detail_html` 제외(`get()`은 포함).
  projection에는 `id`를 **명시**해야 한다(`FIELDS`에 `id`가 없다).
- 목데이터는 빈 배열이라 **작업 없음**(06 §1-1).

**5) 폼 프리미티브** — `fields.tsx`에 `RadioField`
(`useId`, `fieldset`+`legend`, 탭 타겟 44px).
`html-upload.tsx` — Storage 미사용. 확장자를 주 검증(MIME은 빈 문자열일 수 있다),
**512KB** 상한, `TextDecoder("utf-8",{fatal:true})`로 UTF-8 강제,
선택 후 input value 초기화(같은 파일 재선택), 파일명·글자 수·제거 버튼. 미리보기 없음(D9).

**6) 액션 + 폼 연결 (한 커밋)** — 타입을 넓히면 폼 payload가 비어 빌드가
깨지므로 **원자적으로** 한다(04 2단계의 "여기서 빌드가 깨진다"를 없앤다).
`actions.ts`:

```ts
// 클라이언트를 믿지 않는 지점은 여기 하나다. 크기·타입 검사를 정제 전에 다시 한다.
function normalize(input: Input) {
  const oneday = input.scheduleType === "oneday";
  if (typeof input.detailHtmlRaw !== "string") throw new Error(...);
  if (Buffer.byteLength(input.detailHtmlRaw, "utf8") > 512 * 1024) throw new Error(...);
  return { ...input, endDate: oneday ? "" : input.endDate,
           detailHtml: sanitizeCourseHtml(input.detailHtmlRaw) };
}
```

`detailHtml`은 **폼이 보낸 값을 절대 쓰지 않고** raw에서 서버가 만든다.
raw/파일명은 동반 테이블에 upsert(제거 시 delete). `create`/`update` 둘 다
통과시키고, 부분 patch인 `setRegularClassPublished`는 태우지 않는다.

**7) 공개 층 (타입·함수까지만)** — `education-content.ts` 타입 +
정적 4행에 `scheduleType: "multi"`. `public-content.ts`의 정규 클래스 리더는
**정상 0행이면 `[]`**, 오류일 때만 폴백(06 §P1-5). 목록 매핑에 `detailHtml`을
**넣지 않는다**(본문은 02의 slug 단건 조회에서). `formatClassSchedule()`은
`new Date()`를 쓰지 않고 문자열을 직접 자른다. **실제 렌더는 백로그 02.**

**8) 문서** — `docs/07-dev/02-개발상태.md`, 작업로그, `01`~`05`의 오류 3건(06 §1).
02에 **release gate**를 남긴다: slug 단건 조회 / **렌더 직전 재정제** / 실제 렌더 /
필요 시 CSP. 클럽 기수 `is_published` 버그(06 §4)는 **새 백로그로 등록**한다.

## 5. 완료 조건

05-검증체크리스트를 쓰되 아래를 **바꾼다**.

- `npm run lint` "통과" → **"변경 파일에서 신규 오류 0건"**(기존 7건은 별건, 06 §0)
- 공개 화면 표기 항목(§4) → **백로그 02로 이동.** 01은 `formatClassSchedule()`
  단위 테스트(연·윤년 경계, 시작=종료, 종료일만, 잘못된 ISO)로 대신한다
- **추가**: 정제·스코프 단위 테스트가 08 §4 케이스를 전부 통과한다
- **추가**: 512KB 초과 raw를 액션에 직접 넘기면 서버가 거부한다

### DB 적용 후로 미루는 항목 (D8)

코드만 먼저 내므로 아래는 **마이그레이션 적용 시점에 다시 연다.** 이때까지
01은 "완료"가 아니라 **"DB 적용 대기"** 상태다.

- 컬럼·제약·동반 테이블이 생겼고 기존 4행이 `multi`+날짜 null로 살아 있다
- CHECK가 "원데이+종료일", "종료일<시작일", "종료일만"을 실제로 막는다
- `detail_html_raw`가 anon PostgREST로 **안 읽힌다**(동반 테이블 RLS)
- 전 과정을 비공개로 하면 `/education`에 정규 클래스가 **안 나온다**
  (정적 4행이 되살아나면 06 §P1-5 미처리)
- 클럽 기수·나머지 교육 폼 6종이 그대로 저장된다(projection 회귀)
- 어드민에서 고친 값이 공개 화면에 반영된다 (05 §0의 폴백 함정)
