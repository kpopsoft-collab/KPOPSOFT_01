# 현황 분석

## 1. 화면 구조

```
/admin/content/education/regular-classes            목록  page.tsx
                                        /new        추가  new/page.tsx      ─┐
                                        /[id]       수정  [id]/page.tsx     ─┤ 껍데기
                                                                             │
                        components/admin/content/education/regular-classes/  │
                                        regular-class-form.tsx  ◀────────────┘ 본체
```

`new/page.tsx`와 `[id]/page.tsx`는 **제목 문구와 `onSave`만 다르다**. 폼 필드는
전부 `RegularClassForm` 하나에 있다.

```tsx
// new/page.tsx:22
<RegularClassForm onSave={createRegularClass} />

// [id]/page.tsx:32
<RegularClassForm initial={item} onSave={updateRegularClass.bind(null, id)} />
```

→ 이 작업의 폼 변경은 `regular-class-form.tsx` **한 파일**에서 끝난다.
껍데기 두 개를 합치는 건 별건이다([03](../03-regular-class-form-merge/00-START-HERE.md)).

## 2. 지금 폼이 다루는 필드

`regular-class-form.tsx:32~48` — 상태 훅 하나에 필드 하나다.

| 그룹 | 필드 |
|------|------|
| 기본 | `name`, `subtitle`, `description` |
| 표기 | `indexLabel`, `duration`, `level` |
| 분류 | `tracks[]` (beginner/practical), `accent` |
| 이미지 | `imageUrl`, `imageAlt`, `imageCaption` |
| 내용 | `curriculum[]` (주차별 문자열 목록) |
| 경로 | `slug`, `detailHref` |
| SEO | `seoTitle`, `seoDescription` |
| 노출 | `isPublished` |

**일정 관련 필드는 하나도 없다.** `duration`("4주")이 유일한 기간 표현이고 이건
자유 텍스트라 정렬·필터에 쓸 수 없다.

저장 흐름:

```
form onSubmit → onSave(input)            // input = Omit<EducationRegularClass,"id"|"sortOrder">
  → actions.ts createRegularClass/updateRegularClass   ("use server")
    → getContentData().education.regularClasses.create/update
      → SupabaseRepo("education_regular_classes")   ← FIELDS 매핑으로 camel↔snake
    → revalidatePath("/admin/...", "/education") → redirect(목록)
```

## 3. 데이터 층 — 필드 하나가 지나가는 자리

새 필드를 넣으려면 **아래 전부**를 손대야 한다. 하나라도 빠지면 조용히
사라진다(런타임 에러 없이 값만 안 실린다 — 특히 §3-2).

| # | 파일 | 무엇을 |
|---|------|--------|
| 1 | `supabase/migrations/*.sql` | 새 마이그레이션으로 컬럼 추가 |
| 2 | `src/lib/admin/content-types.ts:170` `EducationRegularClass` | 타입 필드 추가 |
| 3 | `src/lib/admin/supabase-content.ts:95` `FIELDS.education_regular_classes` | **camel↔snake 쌍 추가 (누락 시 조용히 유실)** |
| 4 | `src/lib/admin/mock-content.ts` `mockEducationRegularClasses` | 목데이터 기본값 |
| 5 | `src/components/admin/.../regular-class-form.tsx` | 입력 UI |
| 6 | `src/lib/education-content.ts:335` `RegularClass` + `regularClasses` | 공개 타입·폴백 데이터 |
| 7 | `src/lib/public-content.ts:305` `getPublicRegularClasses()` | 공개 리더 매핑 |
| 8 | 공개 화면 컴포넌트 | 실제 표기 |

### 3-1. `FIELDS` 매핑이 하는 일

`supabase-content.ts`의 `FIELDS` 테이블이 camelCase 앱 필드 ↔ snake_case 컬럼을
잇는다. 매핑에 없는 필드는 **select에도 insert에도 실리지 않는다.**

```ts
education_regular_classes: [
  ...COMMON,                       // sortOrder, isPublished
  ["slug", "slug"],
  ["indexLabel", "index_label"],
  ...
  ["seoDescription", "seo_description"],
],
```

### 3-2. 공개 화면은 별도 리더를 탄다

어드민(`content-data`)과 공개(`public-content`)가 **서로 다른 경로**로 같은
테이블을 읽는다. 공개 쪽은 `read()` 헬퍼로 읽다가 실패하면
`src/lib/education-content.ts`의 정적 배열로 **조용히 폴백**한다.

```ts
// public-content.ts
export async function getPublicRegularClasses(): Promise<RegularClass[]> {
  return read("education_regular_classes", (rows) => rows.map(...), regularClasses);
  //                                                                  ▲ 폴백
}
```

이 폴백 때문에, **DB 매핑을 잘못 짜도 화면은 멀쩡해 보인다**(정적 데이터가
대신 나온다). 검증할 때 "화면에 나온다"만으로 판단하면 안 된다 —
[05-검증체크리스트.md](05-검증체크리스트.md) 참고.

## 4. 이미지 업로드 컴포넌트 (HTML 업로드의 참고 모델)

`src/components/admin/content/image-upload.tsx`

```
파일 선택 → MIME 화이트리스트 검사 → 5MB 검사
  → supabase.storage.from(bucket).upload(uuid.ext)   ← 브라우저에서 직접
  → getPublicUrl() → onChange(url)
```

- 버킷: `education` (공개 읽기 / 어드민 쓰기 RLS)
- **`education` 버킷의 `allowed_mime_types`는 이미지 4종뿐이다.**
  `image/jpeg, image/png, image/webp, image/svg+xml`
  (`20260802120000_p3_education_ver3.sql:329`)

→ **HTML 파일은 이 버킷에 올릴 수 없다.** MIME 목록을 넓히거나, 버킷을 새로
만들거나, Storage를 안 쓰거나. 셋 중 하나를 골라야 한다 →
[03-데이터모델.md](03-데이터모델.md) §3.

## 5. 쓸 수 있는 폼 프리미티브

`src/components/admin/content/fields.tsx`

| 있는 것 | 서명 |
|---------|------|
| `TextField` | `label, value, onChange, required?, placeholder?` |
| `DateField` | `label, value(ISO "YYYY-MM-DD"), onChange` ← **그대로 쓴다** |
| `NumberField` | `label, value:number, onChange` |
| `TextAreaField` | `label, value, onChange, rows?` |
| `CheckboxField` | `label, checked, onChange` |
| `CheckboxListField` | `label, options, values, onChange` |
| `StringListField` | `label, values, onChange` |
| `SelectField<T>` | `label, value, options, onChange` |

| 없는 것 | 필요성 |
|---------|--------|
| `RadioField` | 일정 유형 선택 (§요구사항 2.1) — 새로 만든다 |
| `HtmlUpload` | HTML 업로드 위젯 — 새로 만든다 |

`FormActions`(저장/취소 줄)는 교육 폼 7종이 공유한다. 손대지 않는다.
