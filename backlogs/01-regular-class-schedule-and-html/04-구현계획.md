## 3단계 — 서버 액션: 정규화 + 정제

파일: `src/app/admin/(shell)/content/education/regular-classes/actions.ts`

폼이 보내는 값을 **DB에 넣기 직전에** 두 가지로 다듬는다. 클라이언트를 믿지
않는 지점이 여기 하나뿐이 되게 한다.

```ts
import { sanitizeCourseHtml } from "@/lib/admin/sanitize-html";

type Input = Omit<EducationRegularClass, "id" | "sortOrder">;

/**
 * 폼 값 → 저장 값.
 *  - 빈 날짜 문자열은 null 로. `date` 컬럼에 ""를 보내면 Postgres가 거부한다.
 *  - 원데이는 종료일을 버린다. DB check와 같은 규칙을 여기서도 지켜야
 *    제약 위반이 저장 실패가 아니라 애초에 안 생긴다.
 *  - HTML은 **서버에서** 정제한다. 클라이언트 정제는 액션 직접 호출로 우회된다.
 */
function normalize(input: Input): Input {
  const oneday = input.scheduleType === "oneday";
  return {
    ...input,
    startDate: input.startDate || "",
    endDate: oneday ? "" : input.endDate || "",
    detailHtmlRaw: input.detailHtmlRaw,
    detailHtml: sanitizeCourseHtml(input.detailHtmlRaw),
  };
}
```

`""` → `null` 변환 위치는 둘 중 하나를 고른다.

- **(권장) `SupabaseRepo`의 쓰기 경로**에서 `date` 계열 필드가 빈 문자열이면
  `null`로 — 단, 범용 코드라 다른 테이블에 영향이 없는지 확인 필요
- 액션에서 별도 payload를 만들어 넘김 — 영향 범위가 좁지만 타입이 한 겹 는다

`createRegularClass` / `updateRegularClass` 모두 `normalize()`를 통과시킨다.
한쪽만 하면 추가와 수정의 결과가 달라진다.

## 4단계 — 정제 유틸

새 파일: `src/lib/admin/sanitize-html.ts` (`import "server-only"`)

```ts
import "server-only";

 *
 * 이 함수를 통과한 문자열만 dangerouslySetInnerHTML 에 들어간다. 어드민만

 * 한 줄이 방문자 브라우저에서 도는 경로가 된다.
 */
export function sanitizeCourseHtml(raw: string): string {
  // 1) 통짜 문서면 <body> 안쪽만 취한다
  // 2) 화이트리스트 정제 (script/on*/iframe/form/link 제거)
  // 3) <style>은 남기되 컨테이너 클래스로 스코프를 씌운다
}
```

라이브러리: `isomorphic-dompurify` 또는 `sanitize-html`.
**설치 전 `context7`로 최신 API를 확인한다** (CLAUDE.md 규약).

허용 태그 초안
```
p br strong em b i u s
h2 h3 h4
ul ol li
table thead tbody tr th td
a[href|target|rel] img[src|alt|width|height]
blockquote code pre hr
div span section article figure figcaption
style
```

`<style>` 스코프: 정제 결과를 `<div class="course-html">…</div>`로 감싸고,
`<style>` 안 셀렉터 앞에 `.course-html `을 붙인다. 붙이지 않으면 올린 파일의
`h2 { }` 한 줄이 사이트 전역에 적용된다.

간단히 갈 거면 **`<style>`을 아예 제거**하고 본문 구조만 받는 것도 방법이다.
그러면 스타일은 프로젝트 디자인 시스템(docs/04-design-system/)을 따르게 되어 오히려
일관성이 좋아진다. → 사용자 확인 필요.

## 6단계 — HTML 업로드 위젯

새 파일: `src/components/admin/content/html-upload.tsx` (`"use client"`)

`ImageUpload`의 생김새·에러 표기 방식을 따르되 **업로드는 하지 않는다**
(Storage 왕복 없음 — [03-데이터모델.md](03-데이터모델.md) §3 안 A).

```tsx
export function HtmlUpload({
  value,        // detailHtmlRaw
  fileName,     // detailHtmlName
  onChange,     // (raw: string, fileName: string) => void
  label = "상세 페이지 HTML",
}: { ... })
```

동작
1. `accept=".html,.htm,text/html"`
2. 확장자·MIME 검사 → 아니면 `"HTML 파일(.html)만 올릴 수 있어요."`
3. `file.size > 1MB` → `"HTML 파일은 1MB 이하여야 해요."`
4. `const raw = await file.text()` → `onChange(raw, file.name)`
5. 값이 있으면 파일명 + 글자 수 + `제거` 버튼 표시
6. `<details><summary>미리보기</summary>`로 접힌 미리보기

> **미리보기 주의**: 클라이언트에는 정제된 값이 없다. `srcdoc`을 쓴 샌드박스
> iframe(`sandbox=""`)에 원본을 넣어 보여주거나, 미리보기를 아예 빼고
> "저장 후 상세 페이지에서 확인" 안내만 남긴다. **정제 안 된 원본을 현재
> 문서에 `dangerouslySetInnerHTML`로 넣지 않는다** — 어드민 화면에서 XSS가
> 터지면 그게 제일 나쁜 경우다(관리자 세션이 거기 있다).

## 7단계 — 폼에 필드 연결

파일: `src/components/admin/content/education/regular-classes/regular-class-form.tsx`

상태 추가 (기존 훅 나열 뒤, `regular-class-form.tsx:48` 근처)
```tsx
const [scheduleType, setScheduleType] = useState<EducationScheduleType>(
  initial?.scheduleType ?? "multi",
);
const [startDate, setStartDate] = useState(initial?.startDate ?? "");
const [endDate,   setEndDate]   = useState(initial?.endDate ?? "");
const [detailHtmlRaw,  setDetailHtmlRaw]  = useState(initial?.detailHtmlRaw ?? "");
const [detailHtmlName, setDetailHtmlName] = useState(initial?.detailHtmlName ?? "");
```

검증 (`canSave` 확장, `:51`)
```tsx
const dateInvalid =
  scheduleType === "multi" && Boolean(startDate && endDate) && endDate < startDate;
//                                                             ▲ ISO 문자열은 사전순 = 시간순

const canSave = Boolean(name.trim() && slug.trim()) && !dateInvalid && !pending;
```

UI 배치 — `기간`/`난이도` 줄(`:88~92`) **바로 아래**에 일정 블록을 넣는다.
기간과 일정은 같은 얘기라 떨어져 있으면 둘 다 채웠는지 알기 어렵다.

```tsx
<fieldset className="flex flex-col gap-4 rounded-2xl border border-ink/10 p-5">
  <legend className="px-2 text-sm font-semibold text-ink/70">강의 일정</legend>

  <RadioField
    label="일정 유형"
    value={scheduleType}
    onChange={setScheduleType}
    options={[
      { value: "oneday", label: "원데이 클래스", hint: "하루에 끝나는 과정" },
      { value: "multi",  label: "다회차 클래스", hint: "여러 날에 걸쳐 진행" },
    ]}
  />

  {scheduleType === "oneday" ? (
    <DateField label="강의일" value={startDate} onChange={setStartDate} />
  ) : (
    <div className="grid gap-6 sm:grid-cols-2">
      <DateField label="시작일" value={startDate} onChange={setStartDate} />
      <DateField label="종료일" value={endDate} onChange={setEndDate} />
    </div>
  )}

  {dateInvalid && (
    <p role="alert" className="text-sm font-medium text-brand-red">
      종료일은 시작일보다 빠를 수 없어요.
    </p>
  )}
  <p className="text-sm text-ink/50">
    날짜는 비워 둬도 됩니다. 비우면 화면에 기간 표기(예: 4주)만 나옵니다.
  </p>
</fieldset>
```

- 종료일 입력은 `oneday`일 때 **DOM에서 제거**한다(감춤만으로는 남은 값이 안 보인다).
- `endDate` 상태는 유지한다 — `multi`로 되돌리면 값이 살아 있어야 한다.
  실제 저장 시 버리는 일은 3단계 `normalize()`가 한다.

HTML 업로드는 `주차별 커리큘럼`(`:114`)과 `슬러그` 줄 사이에 넣는다.
```tsx
<HtmlUpload
  value={detailHtmlRaw}
  fileName={detailHtmlName}
  onChange={(raw, name) => { setDetailHtmlRaw(raw); setDetailHtmlName(name); }}
/>
```

`onSave` payload(`:59~77`)에 6개 필드를 추가한다. `detailHtml`은 서버가 채우므로
빈 문자열을 보내거나 타입에서 `Omit` 한다 — **폼이 보낸 `detailHtml`을 그대로
쓰지 않는다**(그러면 정제를 건너뛰는 경로가 생긴다).

/** 일정 표기 한 줄. 날짜가 없으면 null — 화면은 이때 표기 자체를 뺀다. */

출력 규칙은 [01-요구사항.md](01-요구사항.md) §2.4 표 그대로.

있다. 문자열을 직접 잘라 쓰는 편이 안전하다.
