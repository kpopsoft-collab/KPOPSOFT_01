## 2. 문서가 놓친 실패 모드 (P1)

### P1-1. 서버 액션 본문 한도 1MB — 요구사항과 정면 충돌
`experimental.serverActions.bodySizeLimit` 기본값이 **1MB**
(설치된 `next@16.2.10` 문서로 확인). 요구사항 §3.2는 "1MB 초과 거부"인데,
raw HTML을 액션 인자로 넘기므로 다른 필드까지 얹혀 **1MB짜리 파일은 한도를 넘겨
불투명한 에러**가 난다. `next.config.ts`에는 현재 이 설정이 없다.

### P1-2. `detail_html_raw`가 익명에게 공개된다
→ §1-3. 원본은 정제 전 스크립트를 그대로 담고 있다. 같은 테이블에 두면
"렌더는 안 하지만 누구나 내려받을 수 있는 XSS 페이로드"가 공개 API에 생긴다.

### P1-3. 저장 시 정제만으로는 부족하다
`supabase/migrations/20260802120000_p3_education_ver3.sql:289` — 관리자는 RLS상
테이블을 직접 수정할 수 있다. 서버 액션을 거치지 않고 `detail_html`에 값을
넣는 경로가 남는다. → **렌더 직전(sink)에서 한 번 더 정제**해야 실제로 닫힌다.

### P1-4. 전역 `FIELDS` 기반 명시 select는 기존 어드민을 깨뜨린다
`src/lib/admin/supabase-content.ts:37`의 `COMMON`은 `["isPublished","is_published"]`를
모든 테이블에 넣는다. 그런데 `education_club_cohorts` 테이블에는
**`is_published` 컬럼이 없다**(DDL `..._p3_education_ver3.sql:82~102`,
RLS도 "is_published이 없는 테이블" 그룹에 있다). `FIELDS`에는 `id`도 없다.
`select("*")`라서 지금은 조용히 넘어가지만, 명시 select로 바꾸면 즉시 400이 난다.

→ **전역 리팩터링을 하지 않는다.** 정규 클래스 repo에만 projection을 둔다.

### P1-5. 전 과정을 비공개로 하면 정적 4행이 되살아난다
`src/lib/public-content.ts:276` — `data.length === 0`이면 폴백을 반환한다.
RLS가 정상적으로 0행을 준 것과 조회 실패를 구분하지 않는다.
→ 정규 클래스 리더는 **정상 0행이면 `[]`**, 오류일 때만 폴백이어야 한다.

## 3. 그 밖에 반영할 지적 (P2)

- **클라이언트 검사는 전부 우회 가능.** 액션에서 `typeof raw === "string"`과
  `Buffer.byteLength(raw,"utf8")` 상한을 **정제 전에** 다시 본다.
- **`detail_html`도 목록에서 빼야 한다.** raw만 빼면 절반이다. 공개 `/education`은
  매 요청 읽는다. 목록은 둘 다 제외, 본문은 백로그 02의 slug 단건 조회에서만 읽는다.
- **"종료일만 입력" 상태가 허용된다.** 03의 CHECK와 04의 `dateInvalid` 둘 다
  `start=null, end!=null`을 통과시킨다. → 07 §2의 CHECK로 교체.
- **타입 계약 불일치.** `fromRow()`는 null 컬럼의 키를 아예 만들지 않는데
  타입은 `startDate: string`이다. `fromRow(null)→""` / `toRow("")→null`을 대칭으로 둔다.
- **`detail_html_uploaded_at`이 죽은 컬럼.** 03에 컬럼만 있고 매핑·상태·액션
  어디에도 없다. 요구사항 §3.2-4의 "업로드 시각 표시"가 충족되지 않는다.
- **`sandbox=""` iframe 미리보기의 한계.** 스크립트는 막지만 네트워크 요청은
  막지 않고, 부모 CSS를 상속하지 않아 **실제 결과와 다른 화면**을 보여준다.
- **임의 `class` 허용 위험.** 동적 업로드 클래스는 Tailwind가 빌드하지 않고,
  이미 번들된 `fixed inset-0 z-50` 류는 피싱 오버레이로 악용된다.
  → D5가 `class` 허용으로 확정돼, `.course-html { contain: layout }`으로
  `fixed` 자손을 본문 영역에 가두는 방어를 넣는다([08](08-HTML정제-설계.md) §3-5).
- **`.html`의 MIME은 빈 문자열일 수 있다.** 확장자를 주 검증, MIME은 보조로.
- **`file.text()`는 CP949/EUC-KR 문서를 깨뜨린다.** UTF-8 전용을 명시한다.
- **같은 파일 재선택 시 `change`가 안 뜬다.** input value를 초기화한다.
- **`start_date` 인덱스는 현재 과설계.** 4행뿐이고 그 축의 조회가 아직 없다.
- **타임존 설명 정정.** `new Date("2026-09-12")`는 UTC 파싱이 맞지만, 밀리는 쪽은
  KST가 아니라 **음수 UTC 오프셋** 지역이다. "문자열을 직접 자른다"는 결론은 유지.

## 4. 범위 밖 발견 — 클럽 기수 저장이 이미 깨져 있다

§P1-4의 부산물이다. `FIELDS.education_club_cohorts`가 `...COMMON`으로
`is_published`를 싣는데 그 컬럼이 테이블에 없다. 그리고
`cohort-form.tsx:65`가 저장 때마다 `isPublished`를 보내고,
`club-cohorts/actions.ts:37`도 `update(id, {isPublished})`를 호출한다.

→ **실제 Supabase 모드에서 클럽 기수 추가·수정이 PostgREST 오류로 실패한다.**
읽기는 `fromRow()`가 없는 컬럼을 조용히 건너뛰어 멀쩡해 보인다.

이 작업의 범위가 아니다. **별도 백로그로 등록해야 한다.** 다만 §P1-4의 이유이므로
여기 남긴다.
