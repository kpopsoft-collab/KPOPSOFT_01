# 05. 과정 상세 번들 — Storage 업로드 + 새 탭 열람

> **상태: 코드 완료 (2026-08-04) · DDL 미적용 · 0단계 사전 확인 미완.**
> 앞 문서와 코드가 어긋나면 [07-구현결과.md](07-구현결과.md) §2가 우선한다.

정규 클래스 상세 자료를 **여러 파일 묶음(zip)** 으로 올려 Supabase Storage에
두고, 상세 페이지에서 **새 탭 링크**로 연다.

지금은 `.html` **한 개**만 올릴 수 있다(`html-upload.tsx`). 이미지·서브 페이지가
낀 실제 결과물을 올릴 방법이 없다 — `detail_html`은 텍스트 컬럼 하나라
상대경로 `<img src="images/a.png">`가 가리킬 대상이 존재하지 않는다.

## 착수 전에 반드시 확인할 것 2가지

둘 다 코드 없이 확인할 수 있다 → [05-구현계획.md](05-구현계획.md) **0단계**.

1. **Storage가 공개 `.html`을 인라인으로 그려 주는가**, 아니면 다운로드로
   떨구는가. 후자면 "새 탭으로 연다"(D2)가 성립하지 않는다
2. **어드민에 실제 로그인 세션이 있는가.** 지금은 `ADMIN_DEV_BYPASS`가 켜져 있어
   `is_admin()`이 항상 false다 → **Storage 업로드가 RLS에 막힌다.**
   이 작업의 최대 리스크다 → [02-현황분석.md](02-현황분석.md) §4

## 다른 백로그와의 관계

- **01 (완료)** 이 만든 `detail_html` 경로와 **공존**한다. 대체가 아니다 → D6
- **02 (완료)** 의 상세 페이지(`src/app/education/programs/[slug]/page.tsx`)에
  링크 블록이 붙는다
- **03 (대기, 폼 병합)** 과 같은 라우트 폴더를 만지지만 충돌은 작다.
  폼 본체는 이미 공용 컴포넌트(`RegularClassForm`) 하나라, 03은 페이지 껍데기만
  합친다. 순서 제약 없음
- **G6(CSP)** 는 이 작업으로 **나빠지지 않는다.** 번들은 우리 페이지에
  아무것도 심지 않는 바깥 링크다 → [03](03-보안판단.md) §6
