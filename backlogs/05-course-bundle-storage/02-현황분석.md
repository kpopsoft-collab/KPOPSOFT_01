## 1. 이미 있는 것 — 그대로 베낄 수 있다

### 1-1. Storage 업로드 패턴

`src/components/admin/content/image-upload.tsx`가 **정확히 같은 구조**다.

```ts
const supabase = createSupabaseBrowserClient();          // :57
const path = `${crypto.randomUUID()}.${EXT[file.type]}`; // :58  ← UUID 키
await supabase.storage.from(bucket).upload(path, file, {
  contentType: file.type, upsert: false,                 // :59~61
});
const { data } = supabase.storage.from(bucket).getPublicUrl(path); // :66
```

- **어드민 세션으로 브라우저에서 직접 올린다.** 서버 액션을 안 탄다 →
  `serverActions.bodySizeLimit: "2mb"`(`next.config.ts:17`)에 걸리지 않는다.
  번들에 이미지가 들어가면 이 한도는 즉시 넘는다
- UUID를 키로 쓰는 관행이 이미 있다 → D8이 새 발명이 아니다

### 1-2. 버킷 생성·정책 SQL

(`education` 버킷). read = `anon, authenticated`, write/update/delete =
`authenticated and public.is_admin()`. **이 블록을 그대로 복제**하면 된다.

### 1-3. "의도"로 저장 손실을 막는 패턴

`HtmlIntent`(`content-types.ts:246`)와 `resolveDetailHtml()`
(`actions.ts:44`)이 만든 규칙이 있다.

```ts
type HtmlIntent =
  | { kind: "keep" }                               // 키를 아예 안 넣는다
  | { kind: "replace"; raw: string; fileName: string }
  | { kind: "remove" };
```

`keep`이면 `update()` payload에서 **키를 통째로 뺀다**(`actions.ts:92`).
`toRow`가 `undefined`를 스킵하기 때문에 컬럼이 안 건드려진다.
**`BundleIntent`도 같은 모양이어야 한다** — 안 그러면 이름만 고쳐 저장했을 때
번들이 조용히 날아간다.

## 3. `detail_href`를 재사용하면 안 되는 이유 (D5)

`detail_href`는 이미 **"외부 상세 링크(선택)"** 로 살아 있다.
`program-card.tsx:30`이 `http`로 시작할 때만 카드 목적지를 그쪽으로 돌린다.

여기에 번들 URL을 넣으면 두 가지가 깨진다.

1. **카드 목적지가 바뀐다.** 목록에서 카드를 누르면 slug 상세가 아니라
   번들이 열린다. 요구사항 §5에서 명시적으로 배제한 동작이다
2. **"우리가 호스팅하는 번들"과 "남의 사이트"를 구분할 수 없다.**
   교체·제거 시 지울 폴더를 알 수 없다. URL 접두사로 판별하는 방법은
   프로젝트 ref가 바뀌는 순간 전부 오작동한다

→ **`detail_bundle_path` 신설.** URL이 아니라 **경로**를 저장한다
([04](04-데이터모델-DDL.md) §1).

## 4. 선행 조건 — **지금 어드민에는 실제 Supabase 세션이 없다**

이 작업의 **가장 큰 리스크**다. 착수 전에 반드시 확인한다.

```
auth.ts:18        const DEV_BYPASS = process.env.ADMIN_DEV_BYPASS !== "false";  // 기본 ON
auth.ts:21~22     if (DEV_BYPASS) return { email: "dev@kpopsoft.local" };       // 가짜 세션
```

`is_admin()`은 `auth.uid()`가 `admin_users`에 있는지 본다
(`20260709121130_p1_inquiries_admin.sql:33~35`). **DEV 바이패스 중에는 로그인이
없으므로 `auth.uid()`가 null이고 `is_admin()`은 항상 false다.**

`createSupabaseServerClient()`도 **anon 키**를 쓴다(`server.ts:18`) — service_role이
아니다. 즉 어드민의 DB 쓰기도 지금은 anon 자격으로 나간다.

| 경로 | 지금 어떻게 되는가 |
|---|---|
| Storage 업로드(브라우저) | **거부된다.** insert 정책이 `is_admin()`을 요구한다 |
| DB `insert` | 거부된다(`42501`) |
| DB `update` | **조용히 0행.** RLS는 에러가 아니라 매칭 실패다 — 저장한 줄 안다 |
| 시드/검증 스크립트(`scripts/*.cjs`) | 정상. service_role 키를 직접 쓴다 |

**백로그 01·04의 DB 검증이 전부 스크립트로 이뤄진 이유**가 여기 있다. 어드민
UI에서 사람이 직접 저장해 보는 항목이 계속 "남은 것"으로 남아 있는 것도 같은 이유다.

→ **번들 업로드는 로그인이 실제로 붙어야 동작한다.** 실 계정으로 로그인해
`admin_users`에 행이 있는 상태를 만들거나, 이 작업 전에 인증 배선(백로그 01 D7)을
먼저 끝내야 한다. 착수 전 확인은 [05](05-구현계획.md) 0단계 ②.

## 5. 주의 — 기존 코드가 걸어 둔 지뢰

- `sanitizeCourseHtml()`은 `<iframe>`을 **금지 태그**로 막는다
  (`sanitize-html.ts`의 `allowedTags`에 없음). D2가 새 탭이라 문제가 안 되지만,
  나중에 마음이 바뀌어 iframe으로 돌아가면 여기부터 걸린다
- `next.config.ts:9`의 `remotePatterns`는 `next/image` 전용이다.
  번들 링크는 `<a href>`라 여기와 **무관하다**. 이걸 고쳐야 한다고 착각하지 말 것
- `getForEdit()`(`supabase-content.ts:339`)은 동반 테이블을 따로 읽는다.
  번들은 **평범한 컬럼**이라 여기에 손댈 필요가 없다 — `get()`이 이미 가져온다
