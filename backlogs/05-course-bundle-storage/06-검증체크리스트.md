## 0. 사전 확인 — 이게 아니면 나머지가 무의미하다

- [ ] Storage 공개 객체의 `.html`이 새 탭에서 **렌더된다** (다운로드 아님)
- [ ] 그 안의 **상대경로 이미지**(`images/a.png`)가 뜬다
- [ ] 응답 헤더 기록: `content-type` / `content-disposition` /
      `x-content-type-options` / `cache-control`
- [ ] **어드민에 실제 세션이 있다** — 기존 `ImageUpload`로 과정 이미지를 올려
      성공한다. 실패하면 `ADMIN_DEV_BYPASS` 때문이고, 인증 배선이 선행돼야
      한다([02](02-현황분석.md) §4)

## 1. `course-bundle.ts` 단위 테스트 (`node --test`)

경로 거부 ([03](03-보안판단.md) §3-1)

- [ ] `../../evil.html` → 거부
- [ ] `a/../../evil.html` → 거부
- [ ] `/etc/passwd` → 거부 (절대경로)
- [ ] `C:\x\index.html` → 거부 (드라이브 문자 · 역슬래시)
- [ ] `a//b.png` → 거부 (빈 세그먼트)
- [ ] `a\0b.png` → 거부 (널바이트)
- [ ] `./index.html` → 거부 또는 정규화 — **둘 중 하나로 정해 테스트에 박는다**

무시 항목

- [ ] `__MACOSX/._index.html`, `.DS_Store`, `Thumbs.db` → 조용히 제외
- [ ] 무시 항목만 있는 zip → "index.html이 없다"로 실패 (빈 번들이 만들어지지 않는다)

정규화

- [ ] `mysite/index.html` + `mysite/images/a.png` → 공통 접두사 `mysite/`가
      벗겨져 `index.html`, `images/a.png`가 된다
- [ ] `index.html`과 `sub/index.html`이 둘 다 있으면 **얕은 쪽**이 루트다
- [ ] `index.html`이 없으면 실패하고, 메시지에 그 사실이 나온다

한도·확장자

- [ ] 확장자 목록 밖(`.exe`, `.php`) → **파일명을 포함한** 메시지로 거부
- [ ] 파일 300개 초과 → 거부
- [ ] 압축 해제 총합 20MB 초과 → 거부 (zip bomb 방어)
- [ ] 단일 파일 5MB 초과 → 거부 (education 버킷 `file_size_limit`와 같은 값)
- [ ] `EXT_MIME`의 값 집합이 마이그레이션 `allowed_mime_types`와 **정확히 일치**
      (테스트로 박는다 — 한쪽만 고치면 업로드가 원인 모르게 실패한다)

경고(막지 않음)

- [ ] 한글/비ASCII 파일명 → `warnings`에 담기고 업로드는 진행된다

## 3. 어드민 화면 (사람이 직접)

- [ ] zip을 올리면 진행 표시가 돌고, 끝나면 파일명·개수가 보인다
- [ ] **저장을 눌러야** 반영된다(업로드만 하고 나가면 화면에 안 붙는다)
- [ ] **이름만 고쳐 저장해도 번들이 남는다** — `BundleIntent.keep`이 빠지면
      여기서 조용히 지워진다. **이 항목이 이 작업의 핵심 회귀 테스트다**
- [ ] 번들을 **교체**하면 새 폴더가 생기고 **옛 폴더가 Storage에서 사라진다**
      (하위 폴더 `images/`까지 — [05](05-구현계획.md) §5-1 재귀 삭제)
- [ ] 번들을 **제거**하면 컬럼이 비고 폴더가 사라진다
- [ ] 과정을 **삭제**하면 폴더도 정리된다
- [ ] 공개/비공개 토글은 번들을 건드리지 않는다
- [ ] `index.html` 없는 zip → 이유가 화면에 뜨고 **아무것도 업로드되지 않는다**
- [ ] `.exe`가 든 zip → 파일명이 포함된 메시지로 거부
- [ ] 새로 만드는 화면(`/new`)에서도 번들 업로드가 된다 (클래스 id 없이 — D8)
- [ ] 기존 `detail_html` 업로드가 여전히 동작한다 (D6 — 회귀)
- [ ] "본문 방식" 라디오가 **지금 들어 있는 것**으로 열린다 (번들 있으면 zip, 아니면 HTML)
- [ ] HTML → zip으로 **바꿔 저장하면** `detail_html`과 동반 테이블 행이 비워진다
- [ ] zip → 없음으로 바꿔 저장하면 컬럼이 비고 **폴더도 지워진다**
- [ ] 라디오를 **건드리지 않고** 이름만 고쳐 저장하면 양쪽 다 그대로다

## 4. 공개 화면

- [ ] 번들이 있는 과정 상세에 링크 블록이 뜬다
- [ ] 링크를 누르면 **새 탭**에서 열리고 이미지·CSS가 정상이다
- [ ] 번들이 없으면 블록이 **아예 없다**
- [ ] `target="_blank"` + `rel="noopener noreferrer"`
- [ ] 새 창에서 열린다는 것이 **스크린리더에도** 전달된다(`aria-label` 등)
- [ ] 탭 타겟 44px 이상, 모바일 375px에서 레이아웃이 깨지지 않는다
- [ ] 본문이 **셋 중 하나만** 나온다 — HTML / 번들 링크 / 커리큘럼 (요구사항 §3-1)
- [ ] HTML을 쓰는 기존 과정은 링크 블록이 **안 나온다**(회귀)
- [ ] 과정을 비공개로 바꾸면 상세가 404가 되어 링크도 같이 사라진다
- [ ] `detail_bundle_path`가 목록 카드의 목적지를 **바꾸지 않는다**
      (`detail_href` 외부 링크 분기와 섞이지 않았는지)
