# 데이터 흐름

## 1. 전체 경로

```
어드민 폼 ─▶ actions.ts ─▶ getContentData().education.regularClasses
                                    │  (SupabaseRepo + FIELDS 매핑)
                                    ▼
                        education_regular_classes (Postgres)
                                    │
                                    │  anon client, RLS: is_published = true 만
                                    ▼
                   public-content.ts  getPublicRegularClasses()
                                    │  실패·빈결과 ─▶ education-content.ts 정적 4행
                                    ▼
        ┌───────────────────────────┴───────────────────────────┐
   /education (edu-programs 섹션)              /education/programs (이번 작업)
                                              /education/programs/[slug]
```

**쓰기와 읽기가 다른 클라이언트를 탄다.** 어드민은 세션 서버 클라이언트(RLS가
관리자 쓰기 허용, 비공개 행도 읽음), 공개는 anon 클라이언트(공개 행만).

## 2. 목록 페이지가 읽는 것

```ts
// src/app/education/programs/page.tsx
export const dynamic = "force-dynamic";

const classes = await getPublicRegularClasses();
```

`read()` 헬퍼가 `is_published`/`sort_order` 정렬까지 처리한다. 페이지에서
추가 정렬을 하지 않는다 — 어드민의 순서 조정이 무시되면 순서 컬럼이 무의미해진다.

## 3. 상세 페이지가 읽는 것

`public-content.ts`에 함수를 하나 추가한다.

```ts
/**
 * 정규 클래스 한 건. 없으면 null — 호출부가 notFound() 한다.
 *
 * 목록을 통째로 읽고 find 하는 방식이 아니다. 과정이 늘어나도 상세 페이지가
 * 읽는 양이 늘지 않아야 하고, "없는 slug"와 "DB 장애"를 구분해야 하기 때문이다.
 * 다만 정적 폴백은 목록과 같은 규칙으로 맞춘다 — 장애 중에 목록에는 있는데
 * 상세만 404가 나면 링크가 깨진 것처럼 보인다.
 */
export async function getPublicRegularClass(slug: string): Promise<RegularClass | null> {
  const all = await getPublicRegularClasses();
  return all.find((c) => c.slug === slug) ?? null;
}
```

> **판단**: 정규 클래스는 4~10건 규모다. 목록 재사용이 폴백 일관성까지
> 공짜로 가져오므로 단건 쿼리보다 낫다. 수십 건 규모가 되면 그때 단건
> 쿼리로 바꾼다. 위 주석의 "읽는 양" 논리는 그 시점에 유효해진다.

## 4. 폴백이 만드는 상태 조합

| DB 상태 | 목록 페이지 | 상세 페이지 |
|---|---|---|
| 정상, 공개 4건 | DB 4건 | DB 값 |
| 정상, 공개 0건 | **정적 4건** (빈 상태가 아니다) | 정적 값 |
| 연결 실패 | **정적 4건** | 정적 값 |
| 정상, 공개 1건 | DB 1건 | DB 값 |

**"공개 0건 → 정적 4건"이 핵심이다.** [01-요구사항.md](01-요구사항.md) §2.3의
빈 상태 화면은 현재 폴백 구조에서는 **사실상 나오지 않는다.**

두 선택지
- **(권장) 그대로 둔다.** 랜딩페이지가 비는 것보다 시드가 보이는 게 낫다.
  빈 상태 UI는 만들되 "이론상 경로"로 남긴다
- 정규 클래스만 폴백을 끈다. 그러면 DB 장애 시 `/education`의 정규 클래스
  카드도 함께 빈다 — 영향이 이 페이지 밖으로 나간다

`read()`는 공용 헬퍼라 **여기서 고치면 교육 전 컬렉션에 영향이 간다.**
바꾸려면 `getPublicRegularClasses()` 안에서만 처리한다.

## 5. 백로그 01이 추가하는 필드

## 6. 캐시·재검증

- 두 페이지 모두 `export const dynamic = "force-dynamic"` — `/education`,
  `/work`와 같다. 어드민 수정이 즉시 보여야 한다
- 어드민 액션의 `revalidatePath`에 **새 경로를 추가한다**
  ```ts
  // actions.ts
  revalidatePath("/education");
  revalidatePath("/education/programs");           // 추가
  revalidatePath(`/education/programs/${slug}`);   // 추가 — slug는 input에 있다
  ```
  `force-dynamic`이라 매 요청 렌더지만, 경로를 명시해 두면 나중에 캐시 전략을
  바꿔도 어드민 반영이 안 깨진다.

## 7. 이미지

`imageUrl`은 Supabase Storage(`education` 버킷) 공개 URL이거나 `/education/*.jpg`
로컬 경로다. `next.config.ts`의 `images.remotePatterns`에 Supabase 호스트가
**이미 등록돼 있다** — `next/image`를 그대로 쓸 수 있다.

```ts
remotePatterns: [{ protocol: "https",
  hostname: "oxkxkqfwliobkyyexjtk.supabase.co",
  pathname: "/storage/v1/object/public/**" }]
```

자산을 자주 교체하는 목업 이미지에서 캐시 잔상이 문제가 되면
`unoptimized`를 쓴다(`EducationPastProgram.coverUnoptimized`가 이미 그 사례다).
