## 4. 함정 — 정적 폴백

`getPublicRegularClasses()`는 실패 시 조용히 정적 배열로 떨어진다.

```ts
return read("education_regular_classes", (rows) => rows.map(...), regularClasses);
//                                                                ▲ 폴백
```

`read()`는 에러도, 빈 결과도 폴백으로 처리한다. 그래서 **DB에 아무것도 없어도,
연결이 끊겨도, 화면에는 4개 과정이 멀쩡히 나온다.**

이게 랜딩페이지로서는 옳은 설계지만(장애 때도 사이트가 안 죽는다) 개발 중에는
"연동됐다"는 착각을 만든다.

→ 검증은 반드시 **어드민에서 값을 바꾸고 공개 화면에서 그 값을 확인**하는
방식으로 한다. 자세히는 [05-검증체크리스트.md](05-검증체크리스트.md) §0.

## 5. `detailHref` 컬럼의 애매함

`education_regular_classes.detail_href`가 자유 입력 텍스트다. 어드민 폼
placeholder는 `/education/programs/ai-tools`, 정적 데이터도 같은 값이다.

즉 **`slug`와 `detail_href`가 같은 정보를 두 벌 들고 있다.** 운영자가 둘을
다르게 적으면 어느 쪽이 진짜 상세 페이지인지 코드가 판단할 수 없다.

정리안 (D2)
- 이동 경로는 **항상** `/education/programs/${slug}`로 계산한다
- `detail_href`는 **외부 링크가 있을 때만** 쓴다(`http`로 시작하면 새 탭)
- 어드민 폼의 라벨과 도움말을 그에 맞게 고친다 —
  `상세 페이지 경로` → `외부 상세 링크(선택)`
- 값이 없으면 지금처럼 slug 기반 내부 페이지

이 정리는 **백로그 01 폼 작업과 같이 하면 파일 한 번만 열면 된다.**
