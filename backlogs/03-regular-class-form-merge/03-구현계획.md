## 1. 세 가지 방식

### 안 A — 라우트를 물리적으로 하나로 (`[id]`만 남김)

`new/page.tsx`를 지우고 `[id]/page.tsx`에서 `id === "new"`를 분기.

| | |
|---|---|
| 얻는 것 | 파일 1개 감소 |
| 잃는 것 | `new`가 암묵적 예약어가 된다. 라우트 목적이 파일 경로에서 안 읽힌다. 실제 id와 충돌 가능성이 코드에 안 드러난다 |
| 판정 | **권장하지 않음.** 근거는 [02-현황분석.md](02-현황분석.md) §4 |

### 안 B — 공용 셸 컴포넌트 (**권장**)

라우트 두 개는 그대로. 반복되는 브레드크럼+제목 마크업을 컴포넌트로 뽑는다.

| | |
|---|---|
| 얻는 것 | 중복 제거, URL 유지, 라우트 의도가 경로에 그대로 남음, 나머지 10벌에도 그대로 재사용 가능 |
| 잃는 것 | 파일 수는 그대로 (컴포넌트 1개 증가) |
| 판정 | **이걸로 간다** |

### 안 C — 라우트 그룹 + 공용 클라이언트 컴포넌트

`(form)` 그룹을 만들어 두 라우트가 같은 클라이언트 컴포넌트를 쓰게 하고
mode prop을 넘긴다.

| | |
|---|---|
| 얻는 것 | B와 비슷 |
| 잃는 것 | 그룹 폴더가 하나 늘어 경로 탐색이 한 겹 깊어진다. B로 충분한 일에 구조를 더한다 |
| 판정 | 불필요 |

## 2. 안 B 구현

### 2-1. 공용 셸

새 파일: `src/components/admin/content/content-form-shell.tsx`

```tsx
import Link from "next/link";
import { ArrowLeft } from "lucide-react";

/**
 * 콘텐츠 등록/수정 화면 껍데기 — 브레드크럼 + 제목 + 폼 자리.
 *
 * 어드민 콘텐츠 폼 22개(추가/수정 11쌍)가 같은 마크업을 각자 들고 있었다.
 * 한 벌로 모아 두면 어드민 화면 톤이 화면마다 갈라지지 않는다.
 *
 * 라우트는 합치지 않는다 — `/new`와 `/[id]`는 하는 일이 다르고, 그 차이가
 * 경로에서 읽히는 편이 낫다(backlogs/03-.../02-현황분석.md §4).
 */
export function ContentFormShell({
  backHref,
  backLabel,
  title,
  children,
}: {
  backHref: string;
  backLabel: string;
  title: string;
  children: React.ReactNode;
}) {
  return (
    <div className="mx-auto flex max-w-2xl flex-col gap-6">
      <div>
        <Link
          href={backHref}
          className="inline-flex items-center gap-1.5 text-sm font-semibold text-ink/55 transition-colors hover:text-ink"
        >
          <ArrowLeft className="size-4" aria-hidden />
          {backLabel}
        </Link>
        <h1 className="mt-3 text-2xl font-extrabold tracking-tight text-ink">
          {title}
        </h1>
      </div>
      {children}
    </div>
  );
}
```

**서버 컴포넌트로 둔다.** `"use client"`를 붙이면 자식 폼이 전부 클라이언트
경계 안으로 들어간다.

클래스 문자열은 기존 두 파일에서 **그대로 옮긴다.** 이 작업에서 디자인을
바꾸지 않는다 — 바꾸면 회귀 원인이 병합인지 스타일인지 구분이 안 된다.

### 2-2. 두 페이지 교체

경로 상수를 한 번만 적는다.

```tsx
// new/page.tsx
const LIST = "/admin/content/education/regular-classes";

export default function NewRegularClassPage() {
  return (
    <ContentFormShell backHref={LIST} backLabel="정규 클래스" title="정규 클래스 추가">
      <RegularClassForm onSave={createRegularClass} />
    </ContentFormShell>
  );
}
```

```tsx
// [id]/page.tsx
const LIST = "/admin/content/education/regular-classes";

export default async function EditRegularClassPage({
  params,
}: { params: Promise<{ id: string }> }) {
  const { id } = await params;
  const item = await getContentData().education.regularClasses.get(id);
  if (!item) notFound();

  return (
    <ContentFormShell backHref={LIST} backLabel="정규 클래스" title="정규 클래스 수정">
      <RegularClassForm initial={item} onSave={updateRegularClass.bind(null, id)} />
    </ContentFormShell>
  );
}
```

각 페이지가 8~12줄로 줄고, 남는 내용은 **그 라우트에서만 의미 있는 것**뿐이다.

> `actions.ts`에도 같은 `const LIST`가 있다. 셋으로 늘리기 싫다면
> `actions.ts`에서 `export const REGULAR_CLASSES_LIST`로 내보내 두 페이지가
> 가져다 쓴다. `"use server"` 파일에서 상수를 export 해도 되는지는
> Next.js 버전에 따라 다르므로(서버 액션만 export 하도록 제한될 수 있다)
> **빌드로 확인**하고, 막히면 별도 `constants.ts`에 둔다.

### 2-3. 삭제 버튼 (선택)

수정 화면에만 삭제를 두고 싶다면 `ContentFormShell`에 `action?: ReactNode`
슬롯을 추가하고 `[id]/page.tsx`에서만 넘긴다. **`new`에서 절대 렌더되지
않는 구조**여야 한다(R3).

이번 범위에 넣을지는 선택. 넣지 않아도 목록 페이지에 이미 삭제 버튼이 있다.

## 3. 확산 (D2)

정규 클래스에서 검증이 끝나면 나머지 10벌에 같은 셸을 적용한다.
**한 번에 하지 않는다.** 커밋을 컬렉션별로 나눠 문제가 생겼을 때 어느
화면인지 바로 좁혀지게 한다.

적용 대상
```
content/experts, inquiry-options, pillar-examples, stats, work
content/education/club-cohorts, club-tiers, faqs, past-programs, reviews, stats
```

**정규 클래스만 적용한 채 오래 두지 않는다.** 11벌 중 1벌만 다른 모양이면
다음 사람이 어느 쪽을 따라야 할지 판단해야 한다.
