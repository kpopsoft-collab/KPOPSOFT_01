# 03. 정규 클래스 `new` · `[id]` 페이지 병합

정규 클래스 **추가**와 **수정** 화면을 하나로 합친다.

대상
- `src/app/admin/(shell)/content/education/regular-classes/new/page.tsx`
- `src/app/admin/(shell)/content/education/regular-classes/[id]/page.tsx`

## 읽는 순서

1. [01-요구사항.md](01-요구사항.md) — 무엇을 합치고 무엇을 남기나
2. [02-현황분석.md](02-현황분석.md) — 두 파일이 실제로 얼마나 다른가
3. [03-구현계획.md](03-구현계획.md) — 세 가지 방법과 권장안
4. [04-검증체크리스트.md](04-검증체크리스트.md)

## 먼저 알아야 할 것

**폼 본체는 이미 하나다.** `RegularClassForm` 컴포넌트를 두 페이지가 공유하고
있고, 두 페이지 파일의 실질적 차이는 **제목 문구와 `onSave` 하나**뿐이다
(각 25~35줄, 그중 겹치는 게 20줄).

즉 이 작업은 "폼을 통합한다"가 아니라 **"라우트 껍데기 두 개를 하나로 줄인다"**
이고, 얻는 것은 코드 중복 20줄 제거다.

→ 그래서 [03-구현계획.md](03-구현계획.md)는 **하지 않는 선택지도 함께** 놓는다.
Next.js App Router에서 `/new`와 `/[id]`를 물리적으로 한 파일로 만들면
"`new`라는 id를 가진 행"과 구분하는 분기가 페이지 안으로 들어오는데, 그 분기가
지금 줄이려는 중복보다 읽기 어려울 수 있다.

## 선행 조건

[01-regular-class-schedule-and-html](../01-regular-class-schedule-and-html/00-START-HERE.md)을
**먼저 한다.** 1번이 폼을 크게 고치므로, 병합을 먼저 하면 같은 파일을 두 번
연다. 다만 **1번과 같은 브랜치에서 이어서 하는 것**은 괜찮고 오히려 효율적이다.

## 결정이 필요한 것

| # | 질문 | 기본안 |
|---|------|--------|
| D1 | 어떤 병합 방식? | **안 B** — 라우트는 그대로 두고 공용 셸 컴포넌트를 뽑는다 ([03-구현계획.md](03-구현계획.md)) |
| D2 | 이 패턴을 교육 폼 7종 전체에 적용할지 | 정규 클래스에서 먼저 해 보고 판단. 한 번에 7종을 바꾸면 되돌리기 어렵다 |
| D3 | URL이 바뀌어도 되는지 | 바뀌지 않게 한다. 어드민 북마크·목록 링크가 이미 두 경로를 가리킨다 |
