# 03. 정규 클래스 `new` · `[id]` 페이지 병합

정규 클래스 **추가**와 **수정** 화면을 하나로 합친다.

대상
- `src/app/admin/(shell)/content/education/regular-classes/new/page.tsx`
- `src/app/admin/(shell)/content/education/regular-classes/[id]/page.tsx`

## 읽는 순서

1. [01-요구사항.md](01-요구사항.md) — 무엇을 합치고 무엇을 남기나
2. [02-현황분석.md](02-현황분석.md) — 두 파일이 실제로 얼마나 다른가
3. [03-구현계획.md](03-구현계획.md) — 세 가지 방법과 권장안
4. [04-검증체크리스트.md](04-검증체크리스트.md)

## 먼저 알아야 할 것

**폼 본체는 이미 하나다.** `RegularClassForm` 컴포넌트를 두 페이지가 공유하고
있고, 두 페이지 파일의 실질적 차이는 **제목 문구와 `onSave` 하나**뿐이다
(각 25~35줄, 그중 겹치는 게 20줄).

즉 이 작업은 "폼을 통합한다"가 아니라 **"라우트 껍데기 두 개를 하나로 줄인다"**
이고, 얻는 것은 코드 중복 20줄 제거다.

→ 그래서 [03-구현계획.md](03-구현계획.md)는 **하지 않는 선택지도 함께** 놓는다.
Next.js App Router에서 `/new`와 `/[id]`를 물리적으로 한 파일로 만들면
"`new`라는 id를 가진 행"과 구분하는 분기가 페이지 안으로 들어오는데, 그 분기가
지금 줄이려는 중복보다 읽기 어려울 수 있다.

## ✅ 완료 (2026-08-03, 라우트 병합은 2026-08-04)

`ContentFormShell`로 구현했고 **결과는 [docs/06-admin/06-콘텐츠-폼-공용셸.md](../../docs/06-admin/06-콘텐츠-폼-공용셸.md)로 승격했다.**
앞으로 콘텐츠 폼 화면을 만들 때는 그 문서를 본다. 이 폴더는 판단 근거 기록으로만 남긴다.

## 선행 조건 — 재판정: 01 없이 진행했다

원래 [01-regular-class-schedule-and-html](../01-regular-class-schedule-and-html/00-START-HERE.md)을
선행으로 뒀지만, **소스 파일 편집 교집합이 0**이었다. 01은 폼 컴포넌트·타입·
마이그레이션·`actions.ts`를 고치고, 03은 페이지 껍데기와 신규 셸만 고친다.
01의 `00-START-HERE.md`도 "껍데기를 합치는 일은 03에서 다룬다"고 적고 있다.

충돌을 0으로 유지하려고 **`actions.ts`를 건드리지 않았다.** 03-구현계획 §2-2의
`export const REGULAR_CLASSES_LIST` 아이디어는 그래서 폐기했다(`"use server"`
파일이 비동기 함수 외 export를 거부할 수 있다는 문제도 있다). 경로 문자열은
각 페이지에 그대로 뒀다.

## 결정 — 확정 결과

| # | 질문 | 결정 |
|---|------|------|
| D1 | 어떤 병합 방식? | **안 B + 안 A** — 먼저 공용 셸(안 B)로 25개 화면의 껍데기를 모았고, 그 뒤 **정규 클래스에 한해 안 A(라우트 병합)까지 적용**했다. `new/`를 지우고 `[id]`가 `id === "new"`로 추가·수정을 겸한다. 나머지 11쌍은 두 파일 그대로다 |
| D2 | 어디까지 적용? | **25개 전부.** 일부만 바꾸면 공통 패턴이 두 개가 되어 다음 사람이 어느 쪽이 기준인지 다시 판단해야 한다. 커밋은 컬렉션별로 쪼개 bisect 가능성을 남겼다 |
| D3 | URL이 바뀌어도 되는지 | **바꾸지 않았다.** 목록 페이지가 두 경로를 하드코딩하고 있다 |
| D4 | 삭제 버튼 슬롯(구현계획 §2-3) | **만들지 않았다.** 슬롯이 없으면 추가 화면에 삭제가 새는 사고가 구조적으로 불가능하다 |

## 곁다리로 고친 것

25개 뒤로가기 링크에 높이 지정이 없어 디자인 시스템의 탭 타겟 44px 규칙을
어기고 있었다. 셸로 모아 둔 덕에 **한 줄(`min-h-11 w-fit`)로 25개를 같이
고쳤다.** 리팩터링 커밋과 섞이지 않게 별도 커밋으로 분리했다.
