# backlogs — 진행 중인 작업만

**이 폴더는 지금 비어 있다.** 완료된 기록은 전부
[`docs/08-decisions/`](../docs/08-decisions/00-START-HERE.md)에 있다 — 2026-08-05에
일곱 건을 옮겼고, 2026-08-06에 여덟 번째(`08-content-form-route-merge`), 2026-08-11에
아홉 번째(`09-inquiry-email-notification` — 문의 알림 메일)가 옮겨졌다.

## 규칙

| | 어디 |
|---|---|
| **진행 중**인 기능의 조사·계획 | **여기** |
| **완료된** 기능의 조사·결정 기록 | [`docs/08-decisions/`](../docs/08-decisions/00-START-HERE.md) |
| **지금 어떻게 동작하나** | `docs/01~07` (상시 기준 문서) |

**끝나면 여기서 뺀다.** 완료된 것이 쌓여 있으면 "아직 할 일이 남았다"로 읽히고,
계획 문서에 남은 착수 전 판단이 현행 기준처럼 보인다.

## 새 기능을 시작할 때

폴더를 하나 만들고 `00-START-HERE.md`부터 쓴다. 지금까지 일곱 건이 공통으로 쓴
골격이다 — 필요 없는 단계는 건너뛴다.

```
backlogs/08-<영문-슬러그>/
  00-START-HERE.md      읽는 순서, 결정 요약(D1·D2…), 닿는 파일
  01-요구사항.md
  02-현황분석.md         지금 있는 것과 없는 것 — 실측값으로
  03-…결정.md            이 작업의 기준 문서. 버린 대안과 그 이유
  04-구현계획.md         단계 순서와 그 순서인 이유
  05-검증체크리스트.md
  06-구현결과.md         계획과 다른 점. 끝난 뒤에 쓴다
```

문서 하나는 200줄을 넘지 않는다. 넘으면 주제 경계에서 쪼개고
`00-START-HERE.md` 목록과 앞뒤 링크를 같이 고친다.

## 끝났을 때 — 두 갈래로 나눈다

1. **"지금 어떻게 동작하나"** → `docs/01~07`의 상시 문서로 올린다.
   이미 있는 문서에 녹일 수 있으면 새로 만들지 않는다.
2. **"왜 그렇게 정했나"** → 폴더째 `docs/08-decisions/`로 옮긴다.
   폴더 슬러그를 바꾸지 않으면 문서끼리의 상대 링크가 그대로 살고
   git이 rename으로 인식해 이력도 이어진다.

옮긴 뒤 이 세 가지를 반드시 같이 고친다.

- `docs/08-decisions/00-START-HERE.md` 목록과 **뒤집힌 결정 표**
- 옮긴 문서 안의 `../../docs/` → `../../`
- **코드 주석이 인용하는 경로** — `grep -rn "backlogs/" src/ scripts/`

마지막 항목을 빠뜨리면 주석이 없는 문서를 가리킨다. 이 프로젝트에서 주석은
"왜 그렇게 했나"의 1차 근거라, 링크가 죽으면 다음 사람이 근거를 못 찾는다.

## 번호는 `docs/08-decisions/`와 이어서 매긴다

옮겨 갈 때 슬러그를 안 바꾸므로(위 2번) 번호도 그쪽 목록의 다음 수를 쓴다.
지금 완료된 것이 09까지라 다음에 시작하는 것이 10이다.
