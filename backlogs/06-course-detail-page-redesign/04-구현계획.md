## 순서를 이렇게 잡은 이유

**화면(1~3단계)이 먼저다.** 화면이 `bundleUrl` 하나만 보게 바뀌어 있어야
백필(4단계)이 데이터를 옮겨도 아무것도 깨지지 않는다. 반대로 하면 백필 직후
`detail_html`이 비고 화면은 아직 그것만 보고 있어서 **본문이 통째로 사라지는
구간**이 생긴다.

```
1. 리더  ──▶  2. 컴포넌트  ──▶  3. 페이지 조립  ──▶  4. 백필  ──▶  5. 어드민 위젯
   (데이터)     (부품)          (화면 완성)         (데이터 이동)   (재발 방지)
```

## 1단계 — 공개 리더

`src/lib/public-content.ts`

- `getPublicRegularClassBySlug()`는 지금 그대로 둔다(`detailHtml`도 계속 읽는다 — D8).
- **추가** `getPublicRegularClassSiblings(slug, limit)` — 다른 공개 과정 최대 3개.
  - 목록 리더(`getPublicRegularClasses()`)를 재사용하고 현재 slug만 뺀다.
  - 실패·0건이면 **빈 배열**. 다른 과정 블록이 없다고 페이지가 깨질 이유는 없다.

### 요약 카드가 지켜야 할 것

- 일정이 `null`이면 **"상시 모집 · 문의 시 안내"**([03](03-화면구조-결정.md) §2).
- 카드 배경은 `bg-white` + `border-ink/10`. accent는 히어로가 이미 쓴다 —
  **한 화면에 원색 패널 두 개를 두지 않는다**.
- sticky는 `lg:sticky lg:top-24`. `lg` 미만에서는 sticky를 걸지 않는다.

### 모바일 CTA 바가 지켜야 할 것

- `fixed inset-x-0 bottom-0 z-40 lg:hidden`
- `pb-[env(safe-area-inset-bottom)]` — iOS 홈 인디케이터에 가리지 않게.
- 바 높이만큼 `<main>`에 `pb-*`를 준다 — 마지막 섹션이 가려지면 안 된다.
- 버튼 최소 높이 44px.

## 3단계 — 페이지 조립

`src/app/education/programs/[slug]/page.tsx`

- 본문 3분기 **삭제**. `CourseHtml` import 제거.
- 2단 그리드: `lg:grid lg:grid-cols-12 lg:gap-12` → 본문 `lg:col-span-8`,
  카드 `lg:col-span-4`.
- 블록 순서는 [03](03-화면구조-결정.md) §2 그대로.
- `getPublicRegularClassSiblings()`를 상세 조회와 **병렬로**(`Promise.all`) 부른다.
- `generateMetadata`·`force-dynamic`·`notFound()`는 손대지 않는다.

## 4단계 — 백필 (**데이터 이동, 1회성**)

`scripts/backfill-detail-html-to-bundle.cjs` (신설)

```
대상: detail_html <> '' AND coalesce(detail_bundle_path,'') = ''
각 행마다
  1) education_regular_class_html_sources 에서 원본(raw)을 읽는다
     └ 없으면 건너뛰고 로그에 남긴다 (정제본만으로는 올리지 않는다)
  2) 새 UUID로 education/<uuid>/index.html 업로드 (contentType: text/html)
  3) UPDATE detail_bundle_path = '<uuid>/',
            detail_bundle_name = <원래 파일명 or 'index.html'>,
            detail_html = ''
  4) 업로드 성공 + UPDATE 실패면 폴더를 지운다 (고아 방지)
```

- **삭제 순서 규칙**([docs/06-admin/07](../../docs/06-admin/07-과정-상세본문-HTML과-번들.md) §3-4)을 그대로 따른다:
  업로드 → DB update 성공 → 그 다음 정리.
- `--dry-run`을 기본으로 하고, 실제 반영은 `--apply`를 줘야 한다.
- 원본은 동반 테이블에 **그대로 남는다** — 되돌리려면 `detail_html`에 정제본을
  다시 넣는 대신 이 스크립트를 반대로 돌리면 된다.

> ⚠️ **로컬과 운영이 Supabase 프로젝트 하나를 공유한다.** 이 스크립트를
> `--apply`로 돌리는 것은 곧 운영 반영이다. **사용자 승인 후 실행한다.**

## 5단계 — 어드민 위젯 (재발 방지)

`src/components/admin/content/bundle-upload.tsx`

- 받는 확장자를 `.zip` → **`.zip`과 `.html`/`.htm`** 으로 넓힌다.
- `.html`이면 unzip을 건너뛰고 `entries = [{ name: "index.html", size }]`로
  같은 `planBundle()` 검증·업로드 경로를 탄다.
- 라벨을 "상세 자료 (zip 또는 HTML 한 장)"로 바꾼다.

`regular-class-form.tsx`

- "상세 본문" 라디오에서 **HTML 한 장 항목을 뺀다** — 남는 것은
  `없음` / `상세 자료(zip·HTML)` 둘.
- `htmlIntent`는 계속 보내되 값은 항상 `{ kind: "keep" }`(D8: 컬럼을 아직 안 지운다).
- **회귀**: 라디오를 안 건드리고 이름만 고쳐 저장하면 `bundleIntent`가 `keep`이라
  번들이 남아야 한다([docs/06-admin/07](../../docs/06-admin/07-과정-상세본문-HTML과-번들.md) §3-3).

## 하지 않는 것

- `detail_html` 컬럼 DROP, `CourseHtml`·`html-upload.tsx` 삭제 (D8)
- 정제기(`sanitize-html.ts`) 수정 — 어드민 미리보기에서 계속 쓴다
- 후기·강사진 블록 신설 ([02](02-조사-상세페이지-구조.md) §4)
- 신청 폼
