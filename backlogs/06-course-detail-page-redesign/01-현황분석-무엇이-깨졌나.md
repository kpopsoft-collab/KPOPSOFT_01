## 1. 지금 페이지가 하는 일

`[slug]/page.tsx`는 네 블록을 세로로 쌓는다.

```
ProgramDetailHero      container-editorial 전폭(≤1280px) accent 패널
ProgramDetailImage     max-w-3xl (768px) 중앙
본문 — 셋 중 하나 택일   max-w-3xl
   detailHtml 있으면 → CourseHtml (인라인 렌더)
   없고 bundleUrl    → ProgramBundleLink (새 탭)
   둘 다 없으면      → CurriculumTimeline
ProgramInquiryCta      전폭 패널
```

운영 데이터 4행이 세 갈래에 고르게 흩어져 있다.

| slug | 본문 갈래 | 렌더된 문서 높이 |
|------|----------|-----------------|
| `ai-tools` | `detailHtml` 인라인 | **29,435px** |
| `vibe-coding` | 번들 새 탭 | 2,894px |
| `web-app` | 커리큘럼 | 2,894px |
| `automation` | 커리큘럼 | 2,894px |

## 2. `ai-tools` — 실측값

브라우저에서 그대로 잰 값이다.

```js
{ docHeight: 29435, shellHeight: 27046.5, shellWidth: 768,
  slideCount: 25, hiddenSlides: 24,
  scriptTags: 0, totalImgs: 5, brokenImgs: 5 }
```

읽는 법:

- **슬라이드 25장 중 24장이 `visibility:hidden; opacity:0`.** 업로드물의 CSS가
  `.slide { width:1920px; height:1080px; visibility:hidden; opacity:0 }`이고
  `.slide.visible`을 **JS가** 붙이는 구조인데, 정제가 `<script>`를 전부
  지워서(`scriptTags: 0`) 아무도 `.visible`을 붙이지 않는다.
- 그런데 **높이는 남는다.** 그래서 27,046px짜리 빈 기둥이 된다.
- **이미지 5장 전부 404.** `assets/photo_research.jpg` 같은 상대경로인데
  `.html` 한 장만 올라와 있어 가리킬 파일이 없다. 요청은
  `/education/programs/assets/…`로 나가 우리 앱의 404를 받는다.
- 1920px로 짜인 슬라이드가 **768px 컬럼** 안에 들어가 있다.

## 3. 원인은 인라인 렌더링의 전제 그 자체다

정제기(`src/lib/admin/sanitize-html.ts`)는 설계대로 동작하고 있다. 문제는
**정제된 조각을 우리 페이지에 심는다**는 전제가 실제 업로드물과 맞지 않는 것이다.

| 정제기가 지우는 것 | 근거 | 문서 한 장에는 무엇이었나 |
|---|---|---|
| `<script>` | XSS 차단 | 슬라이드를 드러내는 코드 |
| `media`·`supports` 외 at-rule (`ALLOWED_AT_RULES`) | 전역 이름 충돌 | `@keyframes`·`@font-face` |
| `position` 선언 (`UNSAFE_PROPS`) | 경계 밖 오버레이 차단 | 슬라이드 레이아웃 |

**세 개를 되살리면 정제가 무의미해진다.** 그러니 인라인 경로에서는 못 고친다.

> 어드민 기준 문서도 이 한계를 이미 적어 뒀다 —
> [docs/06-admin/07](../../docs/06-admin/07-과정-상세본문-HTML과-번들.md) §1:
> *"HTML은 `.html` **한 장**만 받으므로 이미지·CSS·서브 페이지가 딸린 자료는
> zip을 쓴다."* 실제 운영에서는 그 한 장에 덱을 통째로 올렸다. 문서가 옳았고,
> **틀린 입력을 막지 못한 화면 쪽이 문제다.**

## 4. 나머지 3개도 "안 깨졌을 뿐" 구성이 얕다

`web-app`을 기준으로 위에서 아래로 본 것.

| 문제 | 무엇이 | 왜 문제인가 |
|------|--------|------------|
| **폭이 튄다** | 히어로 1280px → 이미지·본문 768px | 히어로가 끝나면 화면이 갑자기 좁아진다. 사이 여백만 남는다 |
| **커리큘럼이 조건부다** | 업로드가 있으면 통째로 사라진다 | `ai-tools`는 커리큘럼 데이터가 있는데 화면에 한 줄도 없다 |
| **돌아갈 길이 없다** | breadcrumb·목록 링크 없음 | 검색으로 바로 들어온 사람은 여기가 어디인지 모른다 |
| **다음 행동이 하나뿐** | 맨 아래 "교육 문의하기" | 이 과정이 안 맞으면 그냥 이탈한다. 다른 3과정으로 가는 길이 없다 |
| **CTA가 화면 밖에 있다** | 스크롤 최하단에만 존재 | 2,894px를 다 내려야 신청/문의 버튼을 만난다 |
| **핵심 정보가 히어로에만** | 기간·난이도·일정·트랙 | 스크롤하면 사라진다. 커리큘럼을 보며 "몇 주짜리였지"를 다시 못 본다 |
| **일정이 자주 빈다** | `formatClassSchedule()`이 null이면 항목 자체가 빠짐 | 상시 모집인지 미정인지 화면이 말해 주지 않는다 |

## 5. 그래서 이번 작업의 범위

1. **본문 갈래를 없앤다.** 커리큘럼은 항상 그리고, 업로드물은 "상세 자료"
   블록 하나로 통일해 **새 탭**으로만 연다.
2. **`.html` 한 장도 Storage로 올린다.** 그래야 새 탭 URL이 생기고, 원본이
   격리된 origin에서 그대로 열린다.
3. **화면을 다시 짠다.** [02](02-조사-상세페이지-구조.md)의 조사 결과를 기준으로.
